# verify_lab 패키지 가이드

> CRITICAL: `src/verify_lab/` 작업 전에 이 문서를 반드시 읽어야 합니다.
> 프로젝트 전반의 공통 규칙은 [루트 CLAUDE.md](../../CLAUDE.md),
> 파이썬 코딩 표준은 [.claude/rules/python.md](../../.claude/rules/python.md)를 참고하세요.

## 패키지 목적

`verify_lab`은 순수 비즈니스 로직만 담당합니다. CLI 인터페이스는 `scripts/`에서 제공합니다.

## 계층 구조

```
src/verify_lab/
├── common_constants.py  # 공통 상수 (경로, 컬럼명 등)
├── data/                # 시장별 데이터 로더 — 자산군이 늘 때만 어댑터 추가
├── measure/             # forward return·베이스라인·통계 — 검증이 바뀌어도 안 바뀜
├── report/              # 표·CSV·마크다운 출력 — 검증이 바뀌어도 안 바뀜
├── studies/             # 개별 검증의 이벤트 정의 — 검증마다 새로 작성
├── strategy/            # 측정 결과로 도출한 매매 규칙 — **예외 계층** (아래 참고)
└── utils/               # 횡단 관심사 (로거, 포맷팅, CLI 헬퍼, 메타 관리)
```

### 계층 간 의존 방향 (단방향)

```
studies  →  measure  →  data
   ↓          ↓
      report        utils

strategy  →  studies      (이벤트 구동 — 신호 목록을 받는다)
strategy  →  data         (상태 구동 — 시세 자체를 받는다)
```

- `measure`·`report`는 **어떤 검증이 자기를 쓰는지 몰라야 합니다.** `studies`를 import하지 않습니다
- `studies`가 `measure`의 함수 시그니처를 바꿔야 한다면, 그 검증에만 필요한 것인지 먼저 의심합니다.
  한 검증 때문에 공통 계층이 특수해지면 다음 검증에서 다시 갈라집니다
- `utils`는 도메인 로직에 의존하지 않습니다
- **`strategy`만 두 갈래로 들어옵니다.** `studies`가 낸 신호 목록을 받는 이벤트 구동과,
  시세 자체를 받는 상태 구동 둘 다 허용합니다. 상태 구동이 필요한 이유와 그때도 지켜야 하는 것은
  [.claude/rules/strategy.md](../../.claude/rules/strategy.md)가 SoT입니다

### strategy 계층은 예외입니다

루트 `CLAUDE.md`가 "하지 않는 일"로 규정한 **진입·손절·익절 설계를 유일하게 허용하는 폴더**입니다.
경계는 폴더 단위이며 **`measure/`·`studies/`·`report/`에서는 여전히 금지**입니다.

- 허용 범위와 제약의 SoT: [.claude/rules/strategy.md](../../.claude/rules/strategy.md)
- **모든 매매법의 공통 산출물은 일별 총자산 곡선**입니다. 표준 지표는 곡선 하나만 받는 함수에서
  계산하며, 곡선에는 **미실현 평가손익이 반드시 들어갑니다** — 실현손익만 집계하면
  익절형 매매법의 자산곡선은 구조적으로 항상 우상향합니다
- **상태 구동이라고 해서 미래를 봐도 되는 것이 아닙니다.** 상태는 판정일까지의 체결로만 쌓입니다

### studies의 계약

각 검증이 공통 계층에 넘기는 것은 **"어느 날이 신호인가"** 하나입니다.

```python
def find_events(df: pd.DataFrame) -> pd.Series:
    """신호인 날은 True인 bool Series (인덱스는 df와 동일)."""
```

이 계약을 지키면 `measure`·`report`를 손대지 않고 검증을 추가할 수 있습니다.
계약을 못 지키는 검증(예: 이벤트가 하루가 아니라 구간인 경우)이 나오면,
우회하지 말고 **공통 계층 확장이 필요한지 먼저 판단**합니다.

## 아키텍처 원칙

### 1. 계층 분리

| 계층 | 책임 | 금지 |
| --- | --- | --- |
| CLI (`scripts/`) | 인자 파싱, 로거 초기화, 예외 처리, 결과 표시 | 도메인 로직 구현 |
| 비즈니스 로직 (`src/verify_lab/`) | 계산, 검증, 변환 | **ERROR 로그** (예외를 raise로 전파) |

### 2. 상수 관리 (3계층)

사용 범위를 기준으로 배치합니다. **계층 간 중복 정의는 발견 즉시 통합합니다.**

| 사용 범위 | 배치 위치 |
| --- | --- |
| 2개 이상 계층에서 사용 | `common_constants.py` |
| 한 계층 내 2개 이상 파일에서 사용 | `<계층>/constants.py` |
| 1개 파일에서만 사용 | 해당 파일 상단 |

카운트에서 테스트 코드와 단순 로그 출력은 제외합니다.

상수 명명 접두사:

- `COL_`: DataFrame 컬럼명 (내부 계산용 영문 토큰)
- `KEY_`: dict/JSON 키
- `DISPLAY_`: CSV 출력·화면 표시용 한글 레이블
- `DEFAULT_`: 기본값 파라미터

**내부/출력 분리**: 내부 계산은 `COL_*`(영문), 저장 직전에 `rename(COL → DISPLAY)`로 한글 헤더를 붙입니다.

> **이 규칙은 CSV 산출물에 예외 없이 적용됩니다.** 사용자가 여는 파일이라 영문 토큰이 그대로
> 나가면 무슨 값인지 알 수 없습니다. 실제로 검증 #7 이 이 연결을 빠뜨려 `ticker,price_basis,
> SignalCount,…` 로 나간 적이 있고, 쓰이지 않는 `DISPLAY_*` 상수만 쌓여 있었습니다.
> **`DISPLAY_*` 를 정의만 하고 `rename` 에 연결하지 않으면 규칙을 지킨 것이 아닙니다.**
> `measure`·`report` 가 내는 공통 컬럼은 `report/constants.py` 의 `DISPLAY_*` 를 재사용합니다 —
> 검증마다 다른 말을 쓰면 두 결과를 나란히 읽을 수 없습니다.

### 3. 핵심 패턴

#### 데이터 로딩은 중앙 집중

모든 시세 파일 로딩은 `data/` 계층을 통합니다. 각 검증이 직접 `pd.read_csv`를 부르지 않습니다.
로딩 시 자동으로 수행할 것: 파일 존재 확인 → 필수 컬럼 검증 → 날짜 파싱 → 시간순 정렬 → 중복 제거.

#### 데이터 검증은 즉시 실패

- 결측치·0값·음수·비정상 급등락을 검사합니다
- **보간 금지.** 이상을 발견하면 메우지 않고 즉시 예외를 던집니다
- 검증을 통과한 데이터만 저장합니다

#### 난수는 시드를 고정

무작위 베이스라인처럼 난수를 쓰는 계산은 **시드를 인자로 받고 기본값을 상수로 둡니다.**
결과 문서에 시드를 기록해야 재현됩니다. 시드 없는 난수 사용은 금지입니다.

#### 예외는 숨기지 않는다

- 하위에서 올라온 예외를 삼키거나 다른 타입으로 바꾸지 않습니다
- 계산 불가 상황에서 조용히 `0`·`None`·빈 DataFrame을 반환하지 않습니다

## 구현 원칙

### 상태 비저장 (순수 함수 지향)

- 함수는 상태를 유지하지 않습니다. 모든 입력을 파라미터로 받습니다
- 전역 가변 상태를 두지 않습니다
- 같은 입력에 항상 같은 출력을 냅니다 — 측정 결과의 재현성이 이 프로젝트의 존재 이유입니다

### 데이터 불변성

- 원본 DataFrame을 변경하지 않습니다. 계산 시 `df.copy()`를 씁니다
- 수집된 원시 시세 파일(`storage/market/`)은 분석 코드가 덮어쓰지 않습니다

### 명시적 검증 / 불가능 조건

- 입력 파라미터는 즉시 검증하고, 잘못된 값이면 `ValueError`
- 코드 흐름상 도달 불가능한 조건은 `RuntimeError` — 메시지에 "내부 불변조건 위반" 접두사와
  위반된 변수·값을 포함합니다. 조용히 기본값을 반환하거나 건너뛰지 않습니다

상세는 [.claude/rules/python.md](../../.claude/rules/python.md)를 따릅니다.

## 측정 계층의 절대 원칙

이 프로젝트에서 아래를 어기면 결과 전체가 무효입니다.

1. **look-ahead 금지** — 신호는 판정일까지의 정보로만 산출합니다.
   판정일 종가로 판정하고 집행은 다음 거래일 시가로 가정합니다.
   전체 기간을 한 번에 보고 순위·통계를 매기는 코드는 금지입니다
2. **가격 기준 일관성** — **원본가 파일 하나로 잽니다**(루트 `CLAUDE.md` 측정의 원칙 14).
   등락률과 forward return이 같은 파일에서 나와야 하며, 한 검증 안에서 두 기준을 섞지 않습니다.
   수정주가 파일(`*_adjusted_max.csv`)과 수집기의 `adjusted` 경로는 **배당 총수익을 따로 물을 때를
   위해 남겨둔 자산**이지, 측정의 기본 입력이 아닙니다
3. **보간 금지** — 결측·이상은 메우지 않습니다. 제외하거나 예외를 던지고, 제외한 건수를 보고합니다
4. **표본 수 보존** — 표본을 줄이는 처리(구간 절단, 제외)를 하면 **몇 건이 왜 빠졌는지** 함께 반환합니다.
   조용히 사라진 표본은 생존편향을 만듭니다
5. **판정식 단일화** — 같은 판정을 두 곳에서 구현하지 않습니다. 복제하면 두 곳이 조용히 갈라집니다

## 데이터 저장 규칙

| 위치 | 내용 | git |
| --- | --- | --- |
| `storage/market/` | 수집한 원시 시세 | 동기화 |
| `storage/results/<실행시각>_<검증명>/` | 검증 산출물 (CSV, summary.json) | 제외 (재생성 가능) |

- 경로는 `common_constants.py`의 상수로만 참조합니다. 하드코딩 금지
- 검증 산출물은 덮어쓰지 않고 실행 시각으로 구분합니다 — 같은 검증을 파라미터만 바꿔 여러 번 돌리는 것이 전제입니다
- 저장 직전 반올림 규칙은 [.claude/rules/python.md](../../.claude/rules/python.md)를 따릅니다

### 경로 기준점은 실행 위치가 아니라 파일 위치다

`common_constants.py`의 경로 상수는 **이 파일의 위치를 기준으로** 저장소 루트를 계산합니다.
실행 디렉터리(CWD)를 기준으로 삼지 않습니다.

같은 검증을 파라미터만 바꿔 여러 번 돌리는 것이 이 프로젝트의 전제이고, 실행 위치를 매번
보장할 수 없습니다. CWD 기준으로 두면 어디서 실행했느냐에 따라 결과가 다른 폴더에 흩어지고,
나중에 그 결과들이 같은 검증의 산출물인지 알 수 없게 됩니다.

### 시세 컬럼명은 저장된 데이터가 정한다

`COL_*` 상수는 `Date`·`Open`·`High`·`Low`·`Close`·`Volume` 처럼 **대문자로 시작합니다.**
이것은 취향이 아니라 이미 저장된 원시 시세 파일의 실제 헤더입니다.

원시 시세는 분석 코드가 덮어쓰지 않는 불변 자산이므로, 코드가 데이터에 맞춰야 합니다.
소스마다 컬럼명이 다르면(예: 한글 컬럼을 반환하는 소스) **`data/` 계층에서 이 스키마로 정규화**하고,
그 위의 계층은 단일 스키마만 봅니다. 정규화되지 않은 컬럼이 `measure/`까지 올라오면
같은 판정이 소스별로 갈라집니다.
