# verify_lab 패키지 가이드

> CRITICAL: `src/verify_lab/` 작업 전에 이 문서를 반드시 읽어야 합니다.
> 프로젝트 전반의 공통 규칙은 [루트 CLAUDE.md](../../CLAUDE.md),
> 파이썬 코딩 표준은 [.claude/rules/python.md](../../.claude/rules/python.md)를 참고하세요.

## 패키지 목적

`verify_lab`은 순수 비즈니스 로직만 담당합니다. CLI 인터페이스는 `scripts/`에서 제공합니다.

## 계층 구조

```
src/verify_lab/
├── common_constants.py  # 공통 상수 (경로, 컬럼명 등)
├── data/                # 시장별 데이터 로더 — 자산군이 늘 때만 어댑터 추가
├── measure/             # forward return·베이스라인·통계 — 검증이 바뀌어도 안 바뀜
├── report/              # 표·CSV·마크다운 출력 — 검증이 바뀌어도 안 바뀜
├── studies/             # 개별 검증의 이벤트 정의 — 검증마다 새로 작성
├── strategy/            # 측정 결과로 도출한 매매 규칙 — **예외 계층** (아래 참고)
└── utils/               # 횡단 관심사 (로거, 포맷팅, CLI 헬퍼, 메타 관리)
```

### 계층 간 의존 방향 (단방향)

```
studies  →  measure  →  data
   ↓          ↓
      report        utils

strategy  →  studies      (이벤트 구동 — 신호 목록을 받는다)
strategy  →  data         (상태 구동 — 시세 자체를 받는다)
```

- `measure`·`report`는 **어떤 검증이 자기를 쓰는지 몰라야 합니다.** `studies`를 import하지 않습니다
- `studies`가 `measure`의 함수 시그니처를 바꿔야 한다면, 그 검증에만 필요한 것인지 먼저 의심합니다.
  한 검증 때문에 공통 계층이 특수해지면 다음 검증에서 다시 갈라집니다
- `utils`는 도메인 로직에 의존하지 않습니다
- **`strategy`만 두 갈래로 들어옵니다.** `studies`가 낸 신호 목록을 받는 이벤트 구동과,
  시세 자체를 받는 상태 구동 둘 다 허용합니다. 상태 구동이 필요한 이유와 그때도 지켜야 하는 것은
  [.claude/rules/strategy.md](../../.claude/rules/strategy.md)가 SoT입니다

### strategy 계층은 예외입니다

루트 `CLAUDE.md`가 "하지 않는 일"로 규정한 **진입·손절·익절 설계를 유일하게 허용하는 폴더**입니다.
경계는 폴더 단위이며 **`measure/`·`studies/`·`report/`에서는 여전히 금지**입니다.

- 허용 범위와 제약의 SoT: [.claude/rules/strategy.md](../../.claude/rules/strategy.md)
- **성적을 무엇으로 재는지는 매매법의 성격이 정합니다.** 포지션이 끊기지 않는 **상시 보유형**은
  일별 총자산 곡선과 그로부터 낸 표준 지표를 쓰고, 신호가 올 때만 들어가는 **이벤트형**은
  신호 수·사건 수·평균·승률·보유일을 씁니다. 노출 비율이 1% 대인 매매법에 CAGR·MDD·Sharpe 를
  붙이면 **셋 다 거짓이 됩니다** — 근거와 실측은 [.claude/rules/strategy.md](../../.claude/rules/strategy.md)
- 곡선을 내는 매매법에서는 **미실현 평가손익이 반드시 들어갑니다** — 실현손익만 집계하면
  익절형 매매법의 자산곡선은 구조적으로 항상 우상향합니다
- **상태 구동이라고 해서 미래를 봐도 되는 것이 아닙니다.** 상태는 판정일까지의 체결로만 쌓입니다

### studies의 계약

각 검증이 공통 계층에 넘기는 것은 **"어느 날이 신호인가"** 하나입니다.

```python
def find_events(df: pd.DataFrame) -> pd.Series:
    """신호인 날은 True인 bool Series (인덱스는 df와 동일)."""
```

이 계약을 지키면 `measure`·`report`를 손대지 않고 검증을 추가할 수 있습니다.
계약을 못 지키는 검증(예: 이벤트가 하루가 아니라 구간인 경우)이 나오면,
우회하지 말고 **공통 계층 확장이 필요한지 먼저 판단**합니다.

넘기는 값의 상세 규격(집계 시작일의 소유자, 확장창 순위의 동률 처리, 부가 컬럼의 단위와 역할)은
아래 「계층 간 계약」의 **이벤트 정의 계약**에 있습니다.

## 아키텍처 원칙

### 1. 계층 분리

| 계층 | 책임 | 금지 |
| --- | --- | --- |
| CLI (`scripts/`) | 인자 파싱, 로거 초기화, 예외 처리, 결과 표시 | 도메인 로직 구현 |
| 비즈니스 로직 (`src/verify_lab/`) | 계산, 검증, 변환 | **ERROR 로그** (예외를 raise로 전파) |

### 2. 상수 관리 (3계층)

사용 범위를 기준으로 배치합니다. **계층 간 중복 정의는 발견 즉시 통합합니다.**

| 사용 범위 | 배치 위치 |
| --- | --- |
| 2개 이상 계층에서 사용 | `common_constants.py` |
| 한 계층 내 2개 이상 파일에서 사용 | `<계층>/constants.py` |
| 1개 파일에서만 사용 | 해당 파일 상단 |

카운트에서 테스트 코드와 단순 로그 출력은 제외합니다.

상수 명명 접두사:

- `COL_`: DataFrame 컬럼명 (내부 계산용 영문 토큰)
- `KEY_`: dict/JSON 키
- `DISPLAY_`: CSV 출력·화면 표시용 한글 레이블
- `DEFAULT_`: 기본값 파라미터

**내부/출력 분리**: 내부 계산은 `COL_*`(영문), 저장 직전에 `rename(COL → DISPLAY)`로 한글 헤더를 붙입니다.

> **이 규칙은 CSV 산출물에 예외 없이 적용됩니다.** 사용자가 여는 파일이라 영문 토큰이 그대로
> 나가면 무슨 값인지 알 수 없습니다. 실제로 검증 #7 이 이 연결을 빠뜨려 `ticker,price_basis,
> SignalCount,…` 로 나간 적이 있고, 쓰이지 않는 `DISPLAY_*` 상수만 쌓여 있었습니다.
> **`DISPLAY_*` 를 정의만 하고 `rename` 에 연결하지 않으면 규칙을 지킨 것이 아닙니다.**
> `measure`·`report` 가 내는 공통 컬럼은 `report/constants.py` 의 `DISPLAY_*` 를 재사용합니다 —
> 검증마다 다른 말을 쓰면 두 결과를 나란히 읽을 수 없습니다.

### 3. 핵심 패턴

#### 데이터 로딩은 중앙 집중

모든 시세 파일 로딩은 `data/` 계층을 통합니다. 각 검증이 직접 `pd.read_csv`를 부르지 않습니다.
로딩 시 자동으로 수행할 것: 파일 존재 확인 → 필수 컬럼 검증 → 날짜 파싱 → 시간순 정렬 → 중복 제거.

#### 데이터 검증은 즉시 실패

- 결측치·0값·음수·비정상 급등락을 검사합니다
- **보간 금지.** 이상을 발견하면 메우지 않고 즉시 예외를 던집니다
- 검증을 통과한 데이터만 저장합니다

#### 난수는 시드를 고정

무작위 베이스라인처럼 난수를 쓰는 계산은 **시드를 인자로 받고 기본값을 상수로 둡니다.**
결과 문서에 시드를 기록해야 재현됩니다. 시드 없는 난수 사용은 금지입니다.

#### 예외는 숨기지 않는다

- 하위에서 올라온 예외를 삼키거나 다른 타입으로 바꾸지 않습니다
- 계산 불가 상황에서 조용히 `0`·`None`·빈 DataFrame을 반환하지 않습니다

## 구현 원칙

### 상태 비저장 (순수 함수 지향)

- 함수는 상태를 유지하지 않습니다. 모든 입력을 파라미터로 받습니다
- 전역 가변 상태를 두지 않습니다
- 같은 입력에 항상 같은 출력을 냅니다 — 측정 결과의 재현성이 이 프로젝트의 존재 이유입니다

### 데이터 불변성

- 원본 DataFrame을 변경하지 않습니다. 계산 시 `df.copy()`를 씁니다
- 수집된 원시 시세 파일(`storage/market/`)은 분석 코드가 덮어쓰지 않습니다

### 명시적 검증 / 불가능 조건

- 입력 파라미터는 즉시 검증하고, 잘못된 값이면 `ValueError`
- 코드 흐름상 도달 불가능한 조건은 `RuntimeError` — 메시지에 "내부 불변조건 위반" 접두사와
  위반된 변수·값을 포함합니다. 조용히 기본값을 반환하거나 건너뛰지 않습니다

상세는 [.claude/rules/python.md](../../.claude/rules/python.md)를 따릅니다.

## 측정 계층의 절대 원칙

이 프로젝트에서 아래를 어기면 결과 전체가 무효입니다.

1. **look-ahead 금지** — 신호는 판정일까지의 정보로만 산출합니다.
   판정일 종가로 판정하고 집행은 다음 거래일 시가로 가정합니다.
   전체 기간을 한 번에 보고 순위·통계를 매기는 코드는 금지입니다
2. **가격 기준 일관성** — **원본가 파일 하나로 잽니다**(루트 `CLAUDE.md` 측정의 원칙 14).
   등락률과 forward return이 같은 파일에서 나와야 하며, 한 검증 안에서 두 기준을 섞지 않습니다.
   수정주가 파일(`*_adjusted_max.csv`)과 수집기의 `adjusted` 경로는 **배당 총수익을 따로 물을 때를
   위해 남겨둔 자산**이지, 측정의 기본 입력이 아닙니다
3. **보간 금지** — 결측·이상은 메우지 않습니다. 제외하거나 예외를 던지고, 제외한 건수를 보고합니다
4. **표본 수 보존** — 표본을 줄이는 처리(구간 절단, 제외)를 하면 **몇 건이 왜 빠졌는지** 함께 반환합니다.
   조용히 사라진 표본은 생존편향을 만듭니다
5. **판정식 단일화** — 같은 판정을 두 곳에서 구현하지 않습니다. 복제하면 두 곳이 조용히 갈라집니다

## 데이터 저장 규칙

| 위치 | 내용 | git |
| --- | --- | --- |
| `storage/market/` | 수집한 원시 시세 | 동기화 |
| `storage/results/<실행시각>_<검증명>/` | 검증 산출물 (CSV, summary.json) | 제외 (재생성 가능) |

- 경로는 `common_constants.py`의 상수로만 참조합니다. 하드코딩 금지
- 검증 산출물은 덮어쓰지 않고 실행 시각으로 구분합니다 — 같은 검증을 파라미터만 바꿔 여러 번 돌리는 것이 전제입니다
- 저장 직전 반올림 규칙은 [.claude/rules/python.md](../../.claude/rules/python.md)를 따릅니다

### 경로 기준점은 실행 위치가 아니라 파일 위치다

`common_constants.py`의 경로 상수는 **이 파일의 위치를 기준으로** 저장소 루트를 계산합니다.
실행 디렉터리(CWD)를 기준으로 삼지 않습니다.

같은 검증을 파라미터만 바꿔 여러 번 돌리는 것이 이 프로젝트의 전제이고, 실행 위치를 매번
보장할 수 없습니다. CWD 기준으로 두면 어디서 실행했느냐에 따라 결과가 다른 폴더에 흩어지고,
나중에 그 결과들이 같은 검증의 산출물인지 알 수 없게 됩니다.

### 시세 컬럼명은 저장된 데이터가 정한다

`COL_*` 상수는 `Date`·`Open`·`High`·`Low`·`Close`·`Volume` 처럼 **대문자로 시작합니다.**
이것은 취향이 아니라 이미 저장된 원시 시세 파일의 실제 헤더입니다.

원시 시세는 분석 코드가 덮어쓰지 않는 불변 자산이므로, 코드가 데이터에 맞춰야 합니다.
소스마다 컬럼명이 다르면(예: 한글 컬럼을 반환하는 소스) **`data/` 계층에서 이 스키마로 정규화**하고,
그 위의 계층은 단일 스키마만 봅니다. 정규화되지 않은 컬럼이 `measure/`까지 올라오면
같은 판정이 소스별로 갈라집니다.

## 계층 간 계약

계층이 서로에게 보장하는 **형태**입니다. 원칙이 "무엇을 지향하는가"라면 계약은
"무엇을 주고받는가"이고, 한쪽만 바뀌면 **예외 없이 결과만 조용히 달라집니다.**

여덟 개가 있습니다. 각 검증의 **설계 근거**는 `docs/spec/<검증명>.md` 가 SoT이며,
여기에는 계층 사이에서 지켜야 할 것만 둡니다.

### 원시 시세 저장 규칙 — data 와 수집기

수집기와 로더가 같은 전제를 공유해야 "받아는 놨는데 읽을 수 없는" 파일이 생기지 않습니다.

| 항목 | 규칙 | 왜 |
| --- | --- | --- |
| 파일명 | **가격 기준 하나에 파일 하나.** 기본 기준은 `<종목>_max.csv`, 같은 종목의 다른 기준은 `<종목>_<기준>_max.csv` | 파일명이 **기간**에 따라 갈리면 로더가 어느 파일을 읽어야 하는지 모호해집니다. 그래서 기간은 파일명에 넣지 않고 항상 전 기간을 받습니다. 반면 **가격 기준이 다르면 내용이 다른 데이터**이므로 한 파일에 섞지 않고 나눕니다 |
| 수집 범위 | **받을 수 있는 전 기간.** 분석 시작일로 잘라 저장하지 않는다 | 원시 시세는 불변 자산이고, 기간 절단은 측정 계층의 판단입니다. 잘라서 저장하면 나중에 구간을 넓힐 때 다시 받아야 합니다 |
| 최근 구간 | **확정되지 않은 최근 며칠은 저장하지 않고, 제외 건수를 결과에 담아 반환한다** | 미국장은 한국 시각 기준 하루가 밀리고 마감 직후 값은 확정값이 아닙니다. 국내는 시차가 없어 전일 종가가 확정이지만, **장중에도 당일 행이 그대로 반환되는 것이 실측**됐으므로(2026-08-12 14:09 실행) 당일은 반드시 뺍니다. 미확정 종가가 남으면 그날이 극단 이벤트로 잡힙니다. 제외 건수를 보고하는 것은 표본 보존 원칙 때문입니다 |
| 저장 시점 | **이상치 검증을 통과한 뒤에만 저장한다** | 예외만 던지고 파일을 남기면 반쪽짜리 원자료가 남습니다 |
| 이상치 판정 | 수집기가 자기 판정을 두지 않고 **로더와 같은 함수**를 쓴다 | 판정이 갈라지면 "수집은 통과했는데 로딩에서 막히는" 데이터가 생깁니다 |
| 날짜 표기 | 파일에는 `YYYY-MM-DD`, 로딩 후에는 `datetime64[ns]` | 이미 저장된 원시 시세의 표기이며, 창 기반 연산이 벡터화되려면 로딩 후에는 datetime이어야 합니다 |
| 가격 표기 | **소수점 4자리까지만.** 원화 정수 가격은 정수 그대로 둔다. 자릿수 값의 SoT 는 `.claude/rules/python.md` 반올림 규칙표이며 코드에서는 `common_constants.PRICE_DECIMALS` 한 곳이 정한다 | 그보다 깊은 자리는 실제 시세에 없는 부동소수점 표현 잡음이라 **차트와 대조할 때 그대로 방해가 됩니다**(`169.300003` vs 차트 `169.30`). 수집기와 결과 출력이 **같은 값**을 써야 하므로 두 계층이 각자 정의하지 않습니다 — 갈라져도 예외가 나지 않습니다 |

현재 저장 대상과 그 가격 기준은 아래와 같습니다.

| 파일 | 가격 기준 | 구간 | 소스 |
| --- | --- | --- | --- |
| `QQQ_max.csv` | **원본가** | 전 기간 | yfinance `history(auto_adjust=False)` |
| `069500_max.csv` | **원본가** | 상장일부터 전 기간 | pykrx `get_etf_ohlcv_by_date` |

> **두 종목 모두 원본가입니다.** 사용자가 결과를 차트와 직접 대조하는 것이 전제인데 보통의 차트는
> 배당 미포함이기 때문이며, 확정 근거는
> [docs/spec/index_extreme_events.md](../../docs/spec/index_extreme_events.md) §7 결정 ⑰ 입니다.
> 그 대가로 배당락·분배락이 하루짜리 하락으로 남지만, **왜곡이 신호군과 베이스라인에 똑같이 걸려
> 초과분에서는 지워집니다**(같은 절의 전환 실측).
> 결과 문서에는 어느 파일로 계산했는지를 반드시 적습니다.

> 외부 라이브러리를 부를 때는 **결과를 좌우하는 인자를 기본값에 맡기지 않고 명시적으로 넘깁니다.**
> yfinance·pykrx 모두 웹 API 래퍼라 기본값이 버전 사이에 조용히 바뀝니다.
> 어느 인자가 왜 그런지는 [docs/spec/index_extreme_events.md](../../docs/spec/index_extreme_events.md) §8에 있습니다.


### forward return 반환 계약 — measure

`measure` 가 내는 결과는 2-b(통계 집계)와 2-c(CSV 출력)의 입력이므로 계층 간 계약입니다.
**신호일 × 기준 × 구간을 한 줄씩 담은 long-form 한 장**입니다.

| 컬럼 | 내용 |
| --- | --- |
| `Date` | 신호일. 시세 스키마의 날짜 컬럼을 그대로 재사용합니다 |
| `Basis` | 수익률 기준점 (`close` / `next_open`) |
| `Horizon` | 측정 구간 (거래일) |
| `ForwardReturn` | 수익률 (비율, 0.03 = 3%). 제외된 칸은 비어 있습니다 |
| `ExcludedReason` | 제외 사유. 유효한 칸은 빈 문자열입니다 |

행 수는 언제나 **`신호 수 × 기준 수 × 구간 수`** 이고, 순서는 신호일 → 기준 → 구간 오름차순입니다.

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 반환 형태 | **long-form** | wide(신호일 한 줄, 구간별 컬럼)로 두면 제외 건수를 별도 자료구조로 들고 다녀야 하고, 그 둘이 어긋나도 테스트가 잡지 못합니다. long-form 은 행 수가 고정돼 **표본 보존 검사가 행 세기로 끝납니다.** 대가는 신호일 한 줄짜리 표를 `report` 가 pivot 해서 만드는 것이며, 표를 만드는 것은 원래 그 계층의 책임입니다 |
| 두 기준의 산식 | 출구는 `D+h 종가` 로 **같고** 입구만 `D 종가` / `D+1 시가` 로 갈립니다 | 두 값의 차이가 곧 "갭으로 새는 몫"이라는 [docs/spec/index_extreme_events.md](../../docs/spec/index_extreme_events.md) §7 결정 ⑥ 의 해석이 출구가 같을 때만 성립합니다 |
| 제외 조건 | `D+h` 가 데이터 마지막을 넘으면 **두 기준 모두** 제외 | 구간이 1 이상이라 출구가 있으면 익일 시가도 반드시 있습니다. 기준별로 갈릴 수 없습니다 |
| 제외 표본 | 행을 지우지 않고 값만 비운 뒤 사유를 답니다 | 행이 사라지면 생존편향이 생깁니다. `count_excluded()` 가 (기준, 구간) 칸별 신호 수와 제외 수를 함께 냅니다 |
| 측정 구간의 단위 | 거래일. 날짜 연산이 아니라 **위치 인덱스**로만 계산합니다 | 달력일이 섞이면 휴장 구간에서 구간 길이가 조용히 달라집니다 |
| 사건 단위 묶기·참고용 z-score | `measure` 가 아니라 **`studies`** | 확인된 재사용처가 0건입니다. "두 번째 검증에서 재사용되는지 확인한 뒤 확정"(루트 `CLAUDE.md`) 규칙을 그대로 따릅니다. 둘 다 forward return 계산에 관여하지 않아 이 계약에 영향이 없습니다 |

> **look-ahead 감시 계약**은 "뒤를 잘라낸 입력의 결과가 전체 입력의 결과와 **겹치는 범위에서** 같다" 입니다.
> 비교 대상은 **짧은 입력에서 값이 있는 칸**뿐입니다 — forward return 은 정의상 미래를 보므로
> 뒤를 자르면 그 구간이 제외로 바뀌는 것이 정상이고, 그 칸까지 비교하면 계약이 항상 실패합니다.
> 이벤트 판정(bool)은 빈 칸이 없어 같은 헬퍼로 겹치는 구간 전체가 비교됩니다.
> **이벤트 정의를 추가할 때마다 이 헬퍼로 계약을 겁니다.**


### 베이스라인·통계 계약 — measure

세 베이스라인은 따로 계산하지 않고 **전 거래일을 신호로 넣은 forward return 테이블 하나에서
파생**시킵니다. 수익률 산식이 한 곳에만 있어야 판정이 갈라지지 않습니다.

| 베이스라인 | 모집단 | 답하는 질문 |
| --- | --- | --- |
| 단순 보유 | 그 테이블 **전체** | 평소보다 나은가 |
| 조건부 | 종가가 200일 이동평균 아래인 날만 거른 것. **SMA 하나만** (2026-08-30 축소) | 같은 국면 안에서 이 날이 특별한가 |
| 무작위 진입 | 위 모집단에서 **신호 수만큼 비복원 추출**을 반복한 것 | 운이 아닌가 |

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 초과분의 단위 | **통계량끼리 대응해 뺍니다** (평균−평균, 중앙값−중앙값, 승률−승률) | 베이스라인 셋 중 둘은 하나의 숫자가 아니라 분포이고, 신호일과 베이스라인 날짜가 달라 **신호 하나에 대응하는 베이스라인 값이 없습니다.** 따라서 "중앙값 초과"는 중앙값의 차이이지 차이의 중앙값이 아니며, 결과 문서에 그렇게 적습니다 |
| 무작위 베이스라인의 반복 단위 | 반복마다 **신호 수만큼** 뽑아 통계량을 하나씩 냅니다 | "같은 표본 수에서 우연히 이 값이 나올 빈도"를 답해야 합니다. 뽑은 것을 전부 합치면 전체 기간 평균에 수렴해 단순 보유와 같은 값이 되고 질문에 답하지 못합니다 |
| 조건부 모집단의 크기 | 해당하는 날 **전부**. 표본 수 차이는 표에 적습니다 | 표본 수를 맞추는 역할은 무작위 베이스라인이 이미 합니다. 여기서 또 뽑으면 난수가 한 겹 더 끼고 두 베이스라인의 역할이 겹칩니다 |
| 이동평균 창이 차기 전 | 판정하지 않고 **판정 불가 일수를 함께 반환**합니다 | 창이 차기 전 값은 초기 구간에 끌려다닙니다. 판정하지 못한 일수를 돌려주지 않으면 표본이 조용히 줄어듭니다 |
| 이동평균의 종류 | **SMA 하나만 씁니다** (2026-08-30 확정, 측정의 원칙 15) | 전에는 SMA·EMA 를 나란히 냈습니다. 그런데 **두 축의 답이 경계에서 갈렸고**(검증 #1 에서 SMA 3개월 우연확률 0.0509 대 EMA 유의), 둘을 다 내면 "어느 쪽이 유리한가"를 고를 여지가 생깁니다. 과최적화를 막으려면 **보통 쓰는 것 하나**로 고정해야 합니다. 창 길이도 같은 이유로 관행값을 씁니다 |
| 유의성 검정 | **순열 검정 단독.** t-test 는 쓰지 않습니다 | 검증 #1 의 표본은 신호 7건·실질 사건 3개라 정규성과 독립 가정이 확실히 깨져 있고, 그 상태의 p 값은 실제보다 큰 확신을 줍니다. 순열 검정은 같은 표본 수·같은 기간에서 그 값이 나오는 빈도를 직접 세므로 가정이 필요 없습니다 |
| 검정 대상 통계량 | **평균·중앙값·오른 비율·내린 비율 넷 다** (2026-08-29 확장) | **평균은 드문데 중앙값은 그렇지 않다면 소수 사건이 결과를 만들었다는 신호**이며, 이 프로젝트가 반드시 드러내야 하는 상황입니다. 여기에 방향 비율이 더해진 것은 **평균이 방향을 가리는 칸이 실재**하기 때문입니다 — 검증 #7 의 SPY 3월 만기가 평균 +0.312% 인데 내린 비율 64.7% 였고, 그 평균을 근거로 한 판정이 축을 바꾸자 뒤집혔습니다. **네 통계량을 같은 추출 표본에서 냅니다** — 축마다 따로 뽑으면 같은 시드에서도 판정 근거가 어긋납니다 |
| 표본 부족 판정선 | 유효 표본 **10건 미만이면 검정하지 않고 사유를 남깁니다.** 백분위도 함께 비웁니다 | 스펙 §6 의 "표본이 한 자릿수인 칸에는 검정을 붙이지 않는다"를 코드로 옮긴 것입니다. 백분위는 사실상 검정 통계량이라 남겨두면 유의성으로 읽힙니다 |
| p 값 산식 | `(관측만큼 극단인 횟수 + 1) ÷ (반복 수 + 1)` (양측) | 0 이 나오면 "절대 우연이 아니다"로 읽히지만 실제로는 반복 수가 유한하다는 뜻일 뿐입니다 |
| 오른 비율 | 수익률이 **0보다 큰** 비율. 정확히 0인 날은 들어가지 않습니다 | 스펙 §6 이 "양수 비율"로 적었고, 국내 ETF 에서 등락률 0 이 실제로 발생합니다. **표시 이름은 `승률` 이 아닙니다** — "승"은 오르는 쪽에 걸었다는 전제가 숨어 있어 아래로 거는 신호에서 정반대를 가리킵니다 (`.claude/rules/docs.md` 용어 대응표) |
| 내린 비율 | 수익률이 **0보다 작은** 비율. **`1 − 오른 비율` 이 아닙니다** | 보합이 어느 쪽에도 들어가지 않으므로 여집합으로 만들면 값이 부풉니다 — 실측에서 두 비율의 합이 99.70~99.89% 입니다. **2026-08-29 부터 `studies` 가 방향을 고르지 않습니다** — 두 비율을 언제나 나란히 내고, 어느 쪽으로 거는지는 결과를 읽는 쪽이 정합니다 (측정의 원칙 11). 그전에는 `studies` 가 골라 넘겼습니다 (2026-08-21 §7 결정 ㉒) |

> **표본 부족 정책의 결과를 미리 알아 둡니다.** 검증 #1 의 QQQ 신호는 7건이므로
> **(기준 × 구간) 7칸이 전부 "표본 부족으로 검정 불가"** 가 됩니다. 버그가 아니라 결론의 일부이며,
> 결과 문서에 그대로 적습니다.


### 출력 계약 — report

`report` 는 **계산하지 않습니다.** `measure` 가 낸 값을 사람이 읽는 형태로 바꾸고 저장하기만 합니다.

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 표시 단위 | **저장 직전 백분율 2자리** (우연확률만 4자리). `measure` 는 비율(0~1) 그대로 | `.claude/rules/python.md` 반올림 규칙표가 "백분율(수익률·승률) → 2자리"로 확정했습니다. `measure` 부터 백분율로 내면 "모든 비율 값은 0~1 소수"라는 표기 규칙이 깨집니다 |
| 터미널과 CSV 의 값 | **같은 표시용 프레임 하나**를 함께 씁니다 | 따로 가공하면 반올림 시점이 갈려 화면에서 본 숫자를 CSV 에서 찾지 못합니다. 사용자가 직접 대조하는 것이 이 프로젝트의 전제입니다 |
| 행 정렬 | **구간 → 기준** | 같은 구간의 두 기준이 위아래로 붙어야 "둘의 차이 = 갭으로 새는 몫"이 눈에 보입니다 |
| 집계 3표의 기준 | **한 기준만 받고, `기준` 컬럼을 내지 않습니다.** 둘 이상이면 `ValueError` | 값이 `종가` 하나뿐이라 고를 것이 없는 필터가 됩니다(2026-08-21 §7 결정 ㉔). 다만 컬럼이 없는 채로 두 기준이 섞여 들어오면 같은 구간이 두 줄로 나오는데 어느 줄이 무엇인지 알 수 없으므로, 조용히 통과시키지 않고 거부합니다 |
| 방향 비율 | **오른 비율과 내린 비율을 그대로 나란히 냅니다.** 어느 쪽이 "이긴 것"인지 정하지 않습니다 (2026-08-29 변경) | 전에는 `studies` 가 방향을 골라 `reverse_rate_column` 인자로 넘겼습니다. 그런데 **방향을 가리지 않기로 하면서**(측정의 원칙 11) 고를 필요가 사라졌고, 하락 방향 신호에서는 같은 값이 두 열에 오는 중복도 있었습니다. `report` 가 방향을 모른다는 성질은 그대로입니다 |
| 신호일 목록 | **신호일 한 줄**에 구간별 수익률을 펼칩니다. 컬럼 이름은 `기준 구간`(예: `종가 1개월`) | long-form 은 한 신호일이 칸 수만큼 여러 행으로 흩어져 눈으로 대조할 수 없습니다. 2-a 가 long-form 을 택하면서 이 pivot 을 `report` 의 몫으로 미뤄 뒀습니다. 검증별 컬럼(순위·사건 번호·z-score)은 `studies` 가 넘겨 날짜 뒤에 붙습니다 |
| 제외·미검정 칸 | 제외는 **빈칸**, 미검정은 **사유 문자열** | 제외된 칸을 0 으로 채우면 "수익률 0%"로 읽힙니다. 반대로 검정 사유는 결론의 일부라 빈칸으로 두면 "아직 안 돌았다"로 읽힙니다 |
| 산출물 | `storage/results/<실행시각>_<검증명>/` 에 CSV 4개(`signals`·`statistics`·`excess`·`test`)와 `summary.json` | 네 표는 컬럼 구성이 완전히 달라 한 파일에 못 섞습니다. 베이스라인 long-form 원자료(전 거래일 × 7칸 = 5만 행)는 재생성 가능하므로 남기지 않습니다. **폴더 생성과 저장은 `report` 가 소유**합니다 — 스크립트마다 두면 경로 규칙이 조용히 갈라집니다 |
| 마크다운 | **내지 않습니다** (2026-08-30 삭제) | 원래는 "표 렌더링까지만" 이었습니다 — 결과 문서 구조의 SoT 가 `docs/research/CLAUDE.md` 하나여야 하므로 코드가 뼈대를 찍지 않는다는 뜻이었습니다. 그런데 **표 렌더링조차 호출된 적이 없습니다.** 결과 문서의 표는 사람이 산출물 CSV 를 보고 직접 씁니다. 필요해지면 git 이력에서 꺼냅니다 |


### 이벤트 정의 계약 — studies

`studies` 가 공통 계층에 넘기는 것은 **"어느 날이 신호인가"** 하나입니다. 설계 결정의 근거는
[docs/spec/index_extreme_events.md](../../docs/spec/index_extreme_events.md) §7 결정 ①~⑬ 이 SoT이며,
여기에는 **계층 사이에서 지켜야 할 형태**만 적습니다.

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 넘기는 값 | 시세와 **같은 인덱스의 bool Series 하나**. 부가 컬럼은 별도 함수로 따로 낸다 | 이 계약을 지키면 `measure`·`report` 를 손대지 않고 검증을 추가할 수 있습니다. 판정과 부가 정보를 한 반환값에 섞으면 공통 계층이 검증별 컬럼을 알아야 합니다 |
| **집계 시작일** | **이벤트 정의 함수가 인자로 받아 안에서 처리한다.** 시작일 이전의 날은 신호로 세지 않되 순위 축적과 연속 길이 누적에는 넣는다 | 호출 측이 시세를 먼저 잘라 넘기면 순위가 그 지점부터 다시 쌓이고 걸쳐 있던 연속이 끊깁니다. **결과는 달라지는데 예외는 나지 않습니다.** 사고를 구조로 막으려고 시작일을 함수가 소유합니다 |
| 확장창 순위 | **자기보다 극단인 날의 수 + 1.** 동률은 같은 순위를 받는다 | 동률에 순번을 매기면 나중 날이 컷 밖으로 밀려 신호 수가 조용히 달라집니다. 국내 원본가는 정수 가격이라 같은 등락률이 실제로 나옵니다 |
| 등락률 산식 | **한 곳에만 둔다.** 두 테스트와 z-score 가 같은 함수를 쓴다 | 판정식 단일화입니다. 같은 값을 두 곳에서 계산하면 두 곳이 갈라지고, 그때 어느 쪽이 맞는지 판별할 방법이 없습니다 |
| 부가 컬럼의 단위 | **내부 토큰과 비율(0~1)로 낸다.** 한글 레이블과 백분율 변환은 하지 않는다 | 표시용 변환은 `report` 의 몫이라는 기존 경계를 그대로 따릅니다. 다만 `report` 는 검증별 컬럼을 모르므로, 그 컬럼을 붙이는 것은 실행 스크립트의 일입니다 |
| 부가 컬럼의 역할 | **해석 보조이며 판정에 쓰지 않는다** | 스펙 §11 이 z-score 를 "판정 기준이 아니라 참고 컬럼"으로 못 박았습니다. 판정에 섞이면 이벤트 정의가 두 개가 됩니다 |
| look-ahead 감시 | **이벤트 정의뿐 아니라 부가 컬럼에도 건다** | 사건 번호와 z-score 도 신호일 목록에 실려 사용자가 읽는 값입니다. 미래를 참조하지 않는다는 절대 원칙에 예외를 두지 않습니다 |


### 실행 계층 계약 — studies/runner 와 scripts

실행 계층은 **계산하지 않습니다.** 이벤트 정의·측정·출력을 조합해 돌리고, 어느 행이 어떤 설정의
결과인지를 붙여 쌓기만 합니다. 설계 결정의 근거는
[docs/spec/index_extreme_events.md](../../docs/spec/index_extreme_events.md) §7 결정 ⑭~⑯ 이 SoT입니다.

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 로직의 위치 | 조합 순회와 조립은 **`studies/<검증명>/runner.py`**, `scripts/` 는 인자 파싱·호출·표시·저장만 | `scripts/CLAUDE.md` 가 CLI 계층에 도메인 로직을 금지했고, 수집 경로 2곳이 이미 같은 관용입니다. 이 저장소의 테스트는 전부 `src` 모듈에 붙으므로, 조합 순회를 스크립트에 두면 **가장 조용히 틀릴 수 있는 코드가 테스트 밖에 남습니다** |
| 잘라내는 대상 | **언제나 신호 선택이지 시세가 아닙니다.** 시작일은 이벤트 정의 함수에 넘기고, 구간의 끝은 판정이 끝난 뒤 거릅니다 | 시세를 먼저 자르면 확장창 순위가 그 지점부터 다시 쌓이고 걸쳐 있던 연속이 끊깁니다. **결과는 달라지는데 예외가 나지 않습니다.** 끝을 자르는 것은 안전합니다 — 판정이 미래를 보지 않으므로 뒤를 잘라도 앞의 값이 그대로입니다 |
| 베이스라인 모집단 | 전 거래일 forward return 테이블 **하나에서 파생**시키고, **신호군과 같은 기간**으로 자릅니다 | 수익률 산식이 한 곳에만 있어야 판정이 갈라지지 않습니다. 기간을 맞추지 않으면 초과분의 차이에 "그 사이 시장이 어땠는가"가 섞입니다 (결정 ⑭) |
| 식별 컬럼 | **`report` 가 아니라 실행 계층이 붙입니다.** 네 표 모두 같은 순서로 앞에 옵니다 — 종목·테스트·파라미터·시작연도·방향·시대 구간 **6개**입니다 | `report` 는 어떤 검증이 자기를 쓰는지 몰라야 하므로 검증별 컬럼을 알 수 없습니다. 계산이 아니라 조립이라 실행 계층의 몫입니다 |
| 가격 기준의 자리 | **식별 컬럼이 아니라 `summary.json` 의 `datasets` 와 터미널 "검증 대상 시세" 표에 둡니다** (스펙 §7 결정 ⑲) | 가격 기준은 **행 단위가 아니라 데이터셋 단위 속성**입니다. 원본가 단일 기준으로 확정된 뒤로는 값이 하나뿐이라, 행마다 반복하면 고를 것이 없는 필터가 대조에 하나 끼어듭니다. 대신 **산출물의 데이터셋 구분자가 `종목` 하나뿐**이 되므로 티커가 겹치면 행이 조용히 뒤섞입니다 — `DATASETS` 의 `ticker` 중복 금지를 불변조건 테스트로 겁니다 |
| 신호 수·사건 수 | 네 표에 **각각 정확히 한 번씩** 실립니다 (`statistics` 는 신호 수를 `report` 가 이미 내므로 사건 수만 더합니다) | 스펙 §6 이 "신호 건수와 사건 건수를 함께 낸다"를 요구합니다. 같은 수가 한 표에 두 번 들어가면 어느 쪽이 맞는지 판별할 수 없게 됩니다 |
| 신호 0건 신호군 | **집계에서 빼되 뺐다는 사실을 요약에 남깁니다** | 조용히 사라진 표본은 생존편향을 만듭니다. 실무적으로도 빈 표는 아래 계층이 예외로 거부합니다 — `excess` 는 칸 구성이 다르면 실패하고 `save_table` 은 빈 표를 거부합니다 |
| 화면과 CSV | 터미널 출력은 **저장한 표시용 프레임에서 발췌**합니다 | 따로 가공하면 반올림 시점이 갈려 화면에서 본 숫자를 CSV 에서 찾지 못합니다 |
| 종가 반올림 | **데이터셋이 자릿수를 정합니다** (KRX 원화 정수 / 그 외 4자리) | 한 파일에 여러 시장을 쌓으므로 컬럼 하나에 자릿수를 고정하면 원화 가격에 없는 소수 자리가 붙습니다. 소수 자릿수는 **원시 시세를 저장한 값과 같아야** 하므로 `common_constants.PRICE_DECIMALS` 를 그대로 씁니다 |
| 방향 축 | 이벤트 정의가 내는 두 방향에 **`역방향 전체`** 가 하나 더 붙습니다. **이벤트 정의가 아니라 집계 단계의 합성**이며 집계 3파일에만 실립니다 (스펙 §7 결정 ㉕) | 사용자의 실제 매매가 방향 구분 없이 역방향으로 진입하는 것이라, 방향별로만 나뉜 산출물로는 그 성적을 한 줄로 볼 수 없습니다. **합성이므로 어느 날이 신호인지는 바뀌지 않습니다** — 상승 방향 수익률의 부호만 뒤집어 이어 붙이고, 베이스라인은 같은 거래일을 원본과 부호 반전 두 벌로 둔 대칭 모집단을 씁니다. `signals.csv` 에 넣지 않는 것은 같은 날이 두 줄로 실려 차트 대조를 방해하기 때문이며, 방향별 두 블록을 합치면 복원됩니다 |


### 단일 값 시계열 계층 계약 — data

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 데이터 스키마의 구분자 | **폴더.** OHLCV 는 `storage/market/`, 일별 단일 값은 `storage/series/` | 한 폴더에 두 스키마를 섞으면 파일을 열어보기 전에는 어느 로더로 읽어야 할지 알 수 없다. 폴더가 다르면 그 판단이 경로에서 끝난다 |
| 두 로더의 판정 차이 | 시계열 로더는 **구조와 결측만** 본다. 값의 부호와 변동폭은 보지 않는다 | 마이너스 금리와 0% 금리가 실재하고, 원달러는 하루 20% 넘게 움직인 해가 있다. 시세의 판정을 그대로 걸면 정상 데이터가 막힌다 |
| 값 컬럼 이름 | **`Value`** (중립) | 환율은 원, 금리는 백분율이라 단위가 소스마다 다르다. `Close` 나 `Rate` 로 두면 그 이름이 맞지 않는 소스가 들어올 때 컬럼을 다시 갈라야 한다. 단위는 각 수집기의 대상 정의가 소유한다 |
| 휴장일·결측 | 수집기는 **제외하고 건수를 보고**한다. 전일값 이월은 하지 않는다 | 이월은 측정 계층의 판단이다. 수집이 미리 메우면 "원래 값이 없던 날"과 "메운 날"을 구분할 수 없다 |
| 비밀값 취급 | ECOS 인증키는 **환경 변수로 올리지 않고 값으로 돌려주며**, URL·예외 메시지는 마스킹을 거친다 | ECOS 는 키를 URL 경로에 넣는다. `urllib` 예외에는 URL 이 통째로 담겨 그대로 올리면 키가 로그에 남는다. KRX 가 환경 변수를 쓰는 것은 pykrx 의 제약이지 일반 규칙이 아니다 |


### 이벤트가 없는 검증의 계약 — studies

| 항목 | 확정 | 왜 |
| --- | --- | --- |
| 이벤트가 없는 검증 | **`measure/` 를 쓰지 않는다.** 자체 회귀 통계를 내고 `report/writer.py` 의 저장만 재사용한다 | `studies` 의 통상 계약은 "어느 날이 신호인가"인데 이 검증에는 신호가 없다. forward return 이 필요 없으므로 공통 계층을 억지로 확장하지 않았다. **저장 규칙은 계산과 달리 검증마다 같아야 하므로 그쪽만 공유한다** |
| 데이터 계열의 시점 정합 | **소스마다 "그 값이 어느 날의 시장인가"를 확인하고 필요하면 옮긴다** | 매매기준율은 고시일 기준이라 하루 늦다. 모르고 쓰면 **예외가 나지 않고 결과만 틀린다** — 상관이 −0.03 으로 나왔다 |
| 축을 고르지 않는 원칙의 적용 범위 | **데이터 계열도 축이다** | 어느 환율 계열을 쓰느냐로 상관이 −0.03 과 0.99 로 갈린다. 하나를 골라 산출했다면 그 선택이 결론에 숨는다 |
| 비용을 재는 방법 | **공시값을 읽지 않고 NAV 로 잰다.** 공시값은 교차확인용 | 공시 총보수에는 기타비용·내부 매매비용이 빠져 있다. NAV 는 그것들이 이미 반영된 값이라 **실제 부담**을 직접 잰다. 다만 **기준선이 상품 구조를 반영해야 한다** — 노출 배수를 빼먹으면 261250 에서 원화금리가 비용으로 둔갑한다 |
