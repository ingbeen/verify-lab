# docs 폴더 규칙

`docs/`는 verify-lab의 설계 문서, 검증 결과, 변경 계획서를 관리한다.

## 문서의 두 종류

| 종류 | 파일 | 수명 |
| --- | --- | --- |
| **살아있는 문서** | `ROADMAP.md`, `COMMANDS.md`, `spec/*.md`, `research/RESEARCH_*.md` | 영구. 계속 갱신한다 |
| **계획서** | `plans/PLAN_*.md` | **임시.** 사용자가 주기적으로 전부 삭제한다 |

각 문서의 SoT 역할:

- `ROADMAP.md` — 검증 대상 목록, 진행 상태, Phase별 산출물, 계획서 승격 목적지
- `spec/<검증명>.md` — 개별 검증의 **확정 설계와 데이터 실측 기록**.
  확정된 결정뿐 아니라 **탈락안과 그 이유**를 함께 남긴다. "이미 해봤다"의 근거가 된다
- `research/RESEARCH_<검증명>.md` — 측정 결과와 판정. 작성 규칙은 `docs/research/CLAUDE.md`
- `COMMANDS.md` — 모든 실행 명령어. 설치용 일회성 명령어는 제외하고 평상시 반복 실행하는 것만 둔다

## 스펙과 결과의 분리

한 검증에 대해 **설계는 `spec/`, 결과는 `research/`** 로 나눈다.

- 설계를 바꾸면 `spec/`을 갱신하고 변경 사유를 "확정된 설계 결정"에 남긴다
- 데이터를 갱신해 재실행하면 `research/`만 바뀐다
- 실측으로 알게 된 데이터 소스의 성질(라이브러리 동작, 품질 문제)은 `spec/`의 "데이터 실측 기록"에 쌓는다.
  기억이 아니라 실측으로만 고친다

## 계획서

- 작성·갱신 절차는 `/plan` 스킬이 SoT다.
- **살아있는 문서에서 계획서를 링크하지 않는다.** 계획서는 주기적으로 삭제되므로 링크가 깨진다.
  필요한 내용은 복사해 살아있는 문서가 자립하게 만든다.
- **Done 처리 전에 근거를 살아있는 문서로 승격한다.** 판단 기준은
  "이 계획서를 지금 지워도 잃는 것이 없는가". 승격 목적지는 `docs/ROADMAP.md` "계획서의 수명"이 SoT다.
- `plans/.gitkeep`은 지우지 않는다 — 디렉토리가 사라지면 계획서 게이트 훅이 비활성화된다.
