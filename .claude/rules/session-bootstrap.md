# 세션을 시작할 때

> 이 문서에는 `paths` frontmatter 가 없다. **매 세션 조건 없이 로드된다.**
> 내용을 쌓지 않고 **어디를 봐야 하는지만** 적는다 — 지식을 복사하면 두 벌이 되고 한쪽이 낡는다.

## 1. 무조건 — 첫 작업 전에 문서 지도를 연다

**[docs/INDEX.md](../../docs/INDEX.md) 를 `Read` 도구로 연다.**

무엇이 어디 있는지가 거기 있다. `Read` 로 여는 이유 — 셸로 읽으면
그 경로의 규칙이 함께 주입되지 않는다.

## 2. 조건부 — 작업 성격에 따라 이어 읽는다

| 이번 세션에 할 일 | 더 읽을 것 |
| --- | --- |
| **검증·측정·결과 문서** | 그 검증의 `docs/<등급>/<매매법>/설계.md` |
| **매매 규칙** | `docs/<등급>/<매매법>/규칙.md` §1 (확정 규칙) → `.claude/rules/trading.md`. **검증 등급에도 규칙.md 가 있다** — 아직 값이 확정 전이라는 뜻이다 |
| **패키지 코드** | `src/verify_lab/CLAUDE.md` — 특히 「계층 간 계약」 |
| **하네스 설정·문서 정리·단순 질의응답** | 1 절에서 멈춘다 |

**전부 읽지 않는다.** 필요 없는 문서를 여는 것도 비용이다.

## 3. 이미 밟은 함정은 각 매매법의 `설계.md` 에 있다

함정 목록을 여기에 두지 않는다. **원본이 있는 곳을 본다.**

| 찾는 것 | 어디 |
| --- | --- |
| 데이터 소스의 성질, 라이브러리 동작, 품질 문제 | `docs/<등급>/<매매법>/설계.md` 「데이터 실측 기록」 |
| 왜 그 설계로 정했나, 무엇을 버렸나 | `docs/<등급>/<매매법>/설계.md` 「확정된 설계 결정」 |
| 측정 결과를 어떻게 읽나, 무엇이 한계인가 | `docs/<등급>/<매매법>/결과.md` 「한계」·「해석」 |
| 판정 기준·측정의 원칙 | 루트 `CLAUDE.md` |
| 산출물 폴더를 재실행이 덮는 규칙과 그것이 조용히 값을 바꾸는 자리 | `src/verify_lab/CLAUDE.md` 「데이터 저장 규칙」 |

## 4. 규칙 자동 로드는 `Read` 도구에만 걸린다

이 저장소에서 실측한 주입은 아래다
(실측 2026-08-09 · 2026-08-29 · python.md 는 전역으로 옮긴 뒤 2026-09-28 에 다시 확인).

| 패턴 | 읽은 파일 | 주입된 것 |
| --- | --- | --- |
| `**/*.py` | `src/verify_lab/` 의 `.py` | 전역 `~/.claude/rules/python.md` + `src/verify_lab/CLAUDE.md` |
| `docs/**` | `docs/` 의 문서 | `.claude/rules/docs.md` |

**`paths:` 를 고치거나 문서를 다른 폴더로 옮기면 주입을 실측으로 다시 확인한다** — 경로가 어긋나면
규칙이 조용히 안 걸린다.
