# 파이썬 구현 규칙

> 이 문서는 파이썬 파일을 다룰 때만 로드됩니다.
> 프로젝트 전반의 공통 규칙은 루트 `CLAUDE.md`를 참고하세요.

## 구현 원칙

비즈니스 로직 구현 시 준수해야 하는 원칙입니다.

#### 데이터 불변성

- 원본 DataFrame을 변경하지 않음
- 계산 시 복사본 사용 (예: `df.copy()`)
- 함수 호출 후 원본 데이터 보장
- 수집한 원시 시세 파일은 불변으로 취급한다 — 분석 코드가 원본 파일을 덮어쓰지 않는다

#### 명시적 검증

- 파라미터 유효성 즉시 검증
- 유효하지 않은 입력 시 즉시 예외 발생 (ValueError)
- 암묵적 가정 금지
- 수집 데이터는 검증 통과 후에만 저장 (보간 금지, 이상 발견 시 즉시 예외)

#### 불가능 조건 처리

내부 불변조건이 보장하는 "로직상 절대 발생할 수 없는 조건"에 대한 방어 코드 규칙:

- 조용히 기본값을 반환하거나 건너뛰지 않는다 (return, continue, 0 대체 금지)
- RuntimeError를 발생시켜 사용자가 즉시 인지할 수 있도록 한다
- 메시지에 "내부 불변조건 위반" 접두사와 위반된 변수/값을 포함한다

구분 기준:

- 입력 파라미터 검증 (외부에서 잘못된 값 전달 가능) → ValueError
- 내부 로직 불변조건 (코드 흐름상 절대 도달 불가) → RuntimeError

#### 미사용 판정에는 「왜 안 쓰이는가」가 함께 필요하다

참조를 전수 집계해 호출되지 않는 정의를 찾았다면, **그 목록을 그대로 지우면 안 된다.**
두 종류가 섞여 있다.

| 왜 안 쓰이는가 | 처리 | 실물 사례 |
| --- | --- | --- |
| 필요 없어서 | **지운다** | `SUPPORT_TOTAL_WITHOUT_PERIOD` — 실제로는 `len(checks)` 로 계산하고 있었다 |
| 결론이 난 축의 잔여물 | **지운다** | `HolidayExit` — 「휴장 규칙 네 조합」 대조축이 사라졌는데 enum 만 남았다 |
| **연결을 빠뜨려서** | **쓰게 만든다** | `DISPLAY_PRICE_BASIS`·`COL_NAV`·`ETF_TARGETS` — 표와 코드가 하드코딩 문자열을 쓰고 있었다 |

세 번째를 지우면 **하드코딩이 정답인 것처럼 굳는다.** `DISPLAY_PRICE_BASIS` 는 실제로 삭제
목록에 올랐다가, `src/verify_lab/CLAUDE.md` 「계층 간 계약」의 실행 계층 계약이
「가격 기준을 터미널 표에 둔다」고 명시한 것을 보고 되살렸다.

## 코딩 표준

### 필수 규칙

타입 안정성:

- 모든 함수에 타입 힌트 필수
- Optional 타입은 `|` 문법 사용 (예: `str | None`, `int | None`)
- 여러 타입 허용 시에도 `|` 사용 (예: `int | float`, `Path | str`)

파일 처리:

- Path 객체만 사용 (문자열 경로 금지)

비율 표기 규칙:

- 모든 비율 값은 0~1 사이 소수로 정의 (0.03 = 3%)
- 주석에서 % 표기 시 혼란 방지를 위해 "비율 (0.03 = 3%)" 형식 사용
- 변수명 접미사: `_rate`, `_ratio`, `_pct` (모두 0~1 범위)
- 예외: pykrx가 반환하는 `등락률`은 % 단위 값이다. 저장 컬럼(`change_rate`)은 pykrx 반환값을 그대로 유지하되, 내부 계산에서 비율로 쓸 때는 명시적으로 변환한다

출력 데이터 반올림 규칙:

CSV/JSON 결과 파일 저장 시 적절한 소수점 자릿수로 반올림합니다.
비즈니스 로직 내부 계산 정밀도는 변경하지 않으며, 저장 직전에만 적용합니다.

| 데이터 유형                            | 소수점 자릿수 | 예시         |
| -------------------------------------- | ------------- | ------------ |
| KRX 원화 가격 (원본가·거래대금·시총)   | 정수 (0자리)  | `83000`      |
| 소수가 나오는 가격 (미국 시세 등)      | 4자리         | `103.4500`   |
| 자본금 (equity, pnl)                   | 정수 (0자리)  | `10000000`   |
| 백분율 (수익률, MDD, 승률, 등락률)     | 2자리         | `22.47`      |
| 비율 (0~1)                             | 4자리         | `0.0300`     |

**가격은 어떤 경우에도 소수점 4자리를 넘기지 않는다.** 그보다 깊은 자리는 실제 시세에 존재하지 않는
부동소수점 표현 잡음이며(예: `169.300003`), 사용자가 결과를 차트와 대조할 때 그대로 방해가 된다.
원화 정수 가격은 이미 이 상한 안에 있으므로 **소수 자리를 붙이지 않는다** — 실제 호가에 없는 자리가 생긴다.

적용 패턴:

- DataFrame: `df.round({컬럼명: 자릿수, ...})` (저장 직전)
- JSON: `round(float(value), 자릿수)` (dict 구성 시). 값 타입이 불명확한 경우(TypedDict의 Any, numpy/pandas scalar 등)에만 `round(float(str(value)), 자릿수)` 로 안전 변환한다.

문서화:

- Google 스타일 Docstring
- 한글 작성
- 복잡한 로직은 넘버링 주석
- 주석 작성 원칙:
  - 현재 코드의 상태와 동작만 설명
  - 과거 상태, 변경 이력, 계획 단계는 기록하지 않음
  - 금지 패턴: "Phase 0", "Phase 3", "레드", "그린" 등 개발 단계 표현 사용 금지
- 문서 내구성 원칙 (CLAUDE.md, 주석/docstring 공통):
  - 역할/책임 중심 설명을 사용한다 ("이 파일은 무엇을 담당하는가")
  - 구체적 수치(개수, 파라미터 값)와 가변 정보를 직접 기재하지 않는다
  - 코드에서 파생 가능한 정보는 문서에 복제하지 않고 해당 코드 파일을 참조한다
  - 리팩토링 후에도 쉽게 깨지지 않는 설명을 목표로 한다
  - **계획서(`docs/plans/`)를 참조하지 않는다.** 계획서는 주기적으로 삭제되는 임시 산출물이라
    참조가 깨진다. 근거를 가리켜야 하면 살아있는 문서(`docs/spec/`·`docs/research/` 나
    `src/verify_lab/CLAUDE.md` 「계층 간 계약」)를 참조한다

네이밍:

- 함수/변수: `snake_case`
- 클래스: `PascalCase`
- 상수: `UPPER_SNAKE_CASE`
- 상수 접두사: `COL_`(DataFrame 컬럼명), `KEY_`(dict/JSON 키), `DISPLAY_`(출력용 한글 레이블), `DEFAULT_`(기본값 파라미터)

품질 검증:

- 모든 품질 검증은 `validate_project.py`를 통해서만 수행 (Ruff + PyRight + Pytest 통합)
- 직접 명령어 실행 금지 (원칙): `poetry run ruff check .`, `poetry run pyright`, `poetry run pytest tests/` 등
- 예외: 특정 모듈/파일만 테스트할 때 직접 pytest 명령 허용
- 실행 명령어는 [docs/COMMANDS.md](../../docs/COMMANDS.md)를 참고
- 타입 체커: PyRight 단일 사용
  - 설정 파일: `pyrightconfig.json` (`executionEnvironments` 방식)
  - 전역: strict 모드, reportUnknown\* 5개 규칙 + reportMissingTypeStubs는 none (pandas 타입 스텁 한계 대응)
  - tests, scripts 폴더: `executionEnvironments`로 추가 규칙 완화

### 로깅 정책

레벨 사용:

- DEBUG: 실행 흐름, 데이터 처리 상태
- WARNING: 잠재적 문제 상황
- ERROR: CLI 계층에서만 사용

금지 사항:

- INFO 레벨 사용 금지 (일반 정보는 DEBUG 사용)
- 이모지 사용 금지
- 함수명 중복 기재 금지 (로그 포맷에 자동 포함)
