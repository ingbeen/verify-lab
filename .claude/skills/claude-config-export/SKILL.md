# 전역 설정 내보내기

`~/.claude` 는 git 저장소가 아니라 다른 PC 로 옮길 통로가 없다. 이 스킬이 옮길 가치가 있는
것만 골라 `claude-config/` 에 사본을 만든다. **받는 쪽은 `claude-config-import` 를 쓴다.**

## 실행

```bash
# 무엇이 담기는지 먼저 본다 (파일을 쓰지 않는다)
poetry run python .claude/skills/claude-config-export/export.py --dry-run

# 번들 생성
poetry run python .claude/skills/claude-config-export/export.py
```

`--dry-run` 은 담길 항목을 **하나씩 전부** 출력한다. 수십 개 규모라 눈으로 대조할 수 있고,
담기면 안 되는 것이 섞였는지 그 자리에서 보인다. **번들을 만들기 전에 한 번 본다.**

## 무엇을 담는가

`~/.claude` 의 최상위에서 아래만 담는다. **허용목록 방식이다** — 금지목록으로 하면
Claude Code 가 새 폴더를 만들 때마다 조용히 딸려온다.

| 담는 것 | 왜 |
| --- | --- |
| `CLAUDE.md` · `settings.json` | 하네스의 본체 |
| `skills/` · `commands/` · `rules/` · `hooks/` | 규칙과 자동화 |
| `tools/` · `db/` | 도구 스크립트 (venv 는 제외) |
| `~/.claude.json` 의 `mcpServers` 와 프로젝트별 권한 | **빠뜨리면 받는 쪽에서 MCP 가 통째로 사라진다.** 이 파일은 `~/.claude` 밖에 있어 놓치기 쉽다. 단 **자격증명 값은 가려서** 담는다 (아래 참고) |

## 무엇을 담지 않는가 — 받는 쪽이 "왜 없지"를 되묻지 않게

### 자격증명 (`keys/**`·`credentials/**`·`secrets/**` · 이름 조각이 `env`·`pem`·`key`·`credentials`·`token`·`secret` 인 파일 · `id_rsa`·`.netrc` 같은 고전 이름)

**이 저장소는 PUBLIC 이다.** 한 번 커밋되면 파일을 지워도 git 이력에 남는다.
회사 식별 정보는 걸러내지 않기로 했지만(사용자 결정), 자격증명은 층위가 다르다 —
유출되면 실제 접근권이 넘어간다.

**판정은 확장자가 아니라 이름을 `.` 으로 쪼갠 토큰으로 한다.** `Path.suffix` 는 마지막
확장자 하나만 주고 **도트파일에서는 빈 문자열이 된다** — 파이썬이 앞의 점을 이름의 일부로
보기 때문이다. 확장자로 재던 시절에는 `.env` 라는 **가장 흔한 자격증명 파일명이 한 번도
안 걸렸고**, `acme-prd.env.local` 처럼 뒤에 한 조각이 더 붙어도 샜다. `.suffixes` 로 바꾸는
것도 답이 아니다 — `Path('.env.local').suffixes` 가 `['.local']` 이라 도트파일을 여전히 놓친다.
`[실측] 2026-09-12` (그때 7종이 담기는 것을 확인했고, 실재 파일이 없어 유출은 없었다)

- **견본 예외를 두지 않는다.** 처음에는 「마지막 조각이 `example`·`sample`·`template` 이면
  통과」라는 규칙이었는데 **그것이 우회로가 됐다** — 이름 뒤에 `.sample` 만 붙이면 판정이 통째로
  꺼져 `real-secret.key.sample` · `credentials.json.example` · `.env.template` 이 전부 빠져나갔다.
  경로 목록으로 바꿔 봤으나 **담을 값어치가 있는 파일이 애초에 없었다** — 실물
  `db/acme-prd.env.example` 에 운영 DB 의 host·port·name 이 채워져 있었다.
  **「견본이면 비어 있다」는 전제가 틀렸다.**
  받는 PC 는 아무것도 잃지 않는다 — 적용은 `shutil.copy2` 만 하고 **파일을 지우지 않으므로**
  안 보내도 그쪽 견본은 그대로 남는다
- **`.`·`-`·`_` 로 쪼갠다** — `.` 만으로는 `.env-prod` · `env_local` 이 샌다
- **`.md`·`.py`·`.rst` 는 탈출구지만 «구분자 조각에만» 걸린다.** 이것이 구분자 분리를 안전하게
  만드는 장치이며, 없으면 `key-rotation-guide.md` 와 `api_key_helper.py` 가 `key` 조각을 갖게 되어
  죽는다. **점 조각이 표식이면 확장자와 무관하게 막는다** — 한때 탈출구를 앞에 두었다가
  `.env.txt` · `aws.key.sh` · `server.pem.md` 가 통째로 빠져나갔다
- **`sh`·`txt` 는 탈출구에 넣지 않는다.** `.sh` 는 `export API_KEY=...` 의 표준 그릇이고
  `.txt` 는 토큰을 붙여넣어 두는 흔한 자리다 — **자격증명 그릇이지 문서가 아니다**
- **모든 조각을 센다** — 한때 `env.py` 를 살리려고 첫 조각을 뺐으나, 그러면
  `key.json`(GCP 서비스계정 키의 표준 파일명) · `env.json` · `key` 가 샌다.
  지금은 `env.py` 도 막힌다(점 조각이 표식이다). 대신 `api_key_helper.py` 처럼 **합성어에
  표식이 섞인** 모듈은 탈출구가 지킨다
- **고전 이름은 구분자 «경계» 로 찾는다** — 자격증명은 앞뒤에 무엇이 붙어도 자격증명이다.
  접두로만 맞추던 때는 `prod.netrc` · `backup.id_rsa` · `old-id_rsa` 가 빠져나갔다
- **폴더명도 내려 맞춘다** — mac 은 파일시스템이 대소문자를 구별하지 않아 `tools/Keys/` 와
  `keys/` 가 같은 폴더인데, 그대로 비교하면 한쪽만 막힌다
- **폴더 이름도 본다** (`keys`·`credentials`·`secrets`). 이름 판정은 파일명만 보므로
  `db/credentials/prod.json` 처럼 **폴더로 묶으면 통째로 빠져나간다**
- **`token`·`secret` 을 표식에 둔 이유는 이 PC 의 실제 자격증명이 그 이름을 쓰기 때문이다**
  (`keys/sheets-mcp-token.json`). 지금은 폴더가 막지만, 도구가 같은 파일을 허용 폴더 밖에 쓰면
  이름 판정 말고는 막을 것이 없다
- **정상 파일을 죽이는 쪽이 유출보다 «조용한» 실패라** 이 경계도 테스트로 함께 고정돼 있다

**받는 PC 에서 필요한 자격증명은 그 PC 에서 새로 만든다.** 다만 「새로 만든다」가 무엇을
뜻하는지는 파일마다 갈린다 — 구글시트의 두 파일이 그 예다.

| 파일 | 받는 PC 에서 |
| --- | --- |
| `keys/sheets-mcp-token.json` | 동의화면이 「테스트」 상태라 **7일마다 만료**된다. **재인증하면 생긴다** |
| `keys/sheets-mcp-oauth.json` | Google Cloud Console 에서 받은 **클라이언트 시크릿**이다. **재인증으로는 생기지 않는다** — 그 PC 로 따로 옮기거나 Console 에서 다시 내려받는다 |

지라(atlassian)처럼 브라우저 OAuth 로 인증하는 서버는 토큰이 `.credentials.json` 이나
Keychain 에 있어 애초에 담기지 않는다. 받는 PC 에서 한 번 인증하면 된다.

### MCP 서버의 자격증명 «값» — 파일이 아니라 설정 안에 있다

`~/.claude.json` 의 `mcpServers[*].headers` · `env` · **`url`** 에는 **API 키가 값으로 들어간다.**
이 파일은 `~/.claude` **밖**에 있어 위의 경로 판정을 아예 거치지 않고, 실제로 이 자리에서
Context7 키가 번들에 들어간 적이 있다. 그래서 내보낼 때 **그 값을 센티널로 가린다.**

- 판정은 **허용목록**이다 — `headers`·`env` 의 문자열 값 중 **절대경로가 아닌 것을 전부** 가린다
- **`url` 은 «부분»만 가린다** — query 의 **값** · `user:password@` · fragment 다.
  scheme·host·path 와 query 의 **키는 남는다.** HTTP 형 서버는 토큰을 url 에 싣는 방식이 흔한데
  두 블록만 훑던 때는 이 자리가 통째로 샜다. **url 전체를 가리면 받는 쪽에서 서버가 뜨지 않는다.**
  가릴 것이 없는 url 은 **손대지 않는다** — 모양이 달라지면 받는 쪽 해시가 어긋나 괜히 다시 물어진다
- 🔴 **url 의 «경로» 구간은 가리지 못한다.** 어느 구간이 키인지 구조로 판별할 수 없고 통째로
  가리면 서버가 죽는다. **경로에 키를 넣는 API 가 실제로 있으므로**(ECOS 가 그렇다)
  그런 서버를 등록했다면 **사람이 번들을 확인해야 한다.** 두 번째 겹인 번들 전체 패턴 스캔은
  알려진 키 형식만 잡는다
- 🔴 **url 의 센티널은 문자열 «안에» 박힌다.** 그래서 받는 쪽 복원이 완전일치로 보면 이 자리를
  지나치고, **번들의 센티널 url 이 작동 중인 url 을 덮어써 서버가 조용히 죽는다.** 실제로 그
  상태로 한 번 구현됐고 받는 쪽 테스트가 없어 그린으로 통과했다 `[실측] 2026-09-12`.
  지금은 `restore_redacted` 가 포함 여부로 보고 **이 PC 의 url 을 통째로** 되돌린다
- **경로는 남긴다.** 그것은 자격증명이 아니라 자격증명이 놓인 곳이고,
  받는 쪽이 그 문자열에서 출처 PC 의 홈을 찾아 자기 경로로 바꾼다
- 이름 패턴(`KEY`·`TOKEN` 이 든 키)으로 고르지 않는다 — 구글시트의 `TOKEN_PATH` 가 걸려
  **살려야 할 경로가 죽고**, 새 서버가 다른 이름을 쓰면 조용히 샌다.
  **url 의 query 도 같다** — 어느 키가 비밀인지 이름으로 가리지 않고 값을 전부 가린다
- `command`·`args` 는 가리지 않는다. 실행 인자라 가리면 받는 쪽에서 서버가 뜨지 않는다.
  그 자리는 `tests/test_claude_config_bundle.py` 의 **번들 전체 패턴 스캔**이 맡는다

무엇을 가렸는지는 **실행 출력에 나온다**(`--dry-run` 에서도). 허용목록이라 자격증명이 아닌
설정값까지 가릴 수 있으므로 그 목록을 한 번 본다.

받는 쪽은 센티널을 알아보고 **그 PC 에 이미 있던 값을 유지한다.** 없으면 센티널을 남기고
채워야 할 항목으로 알려준다.

### 그 밖에

| 담지 않는 것 | 왜 |
| --- | --- |
| `projects/` · `sessions/` · `history.jsonl` · `file-history/` 등 | 세션 상태와 이력. `projects/` 만 426MB 이고, 다른 PC 의 이력이 섞이면 되돌릴 수 없다 |
| 이름 조각이 `jsonl`·`log`·`lock` 인 파일 | 실행하며 쌓이는 기록과 상태 파일. 그 PC 에서만 뜻이 있고, **매번 달라져 아래 「실행 후」 1단계의 `git diff` 검토를 무력화한다** — 설정이 한 글자도 안 바뀐 내보내기에서도 번들이 달라 보인다. 이름 «전체»가 아니라 조각으로 막는 것은 허용목록이 폴더를 통째로 담기 때문이다 — 이름으로 막으면 다음 도구가 만드는 로그에서 또 샌다(`hooks/toast.log` 가 실제로 그렇게 담겼다, 2026-09-12). **`.suffix` 로 재던 때는 절반만 막혔다** — 도트파일(`.log`)에서 빈 문자열이 되고 대문자(`toast.LOG`)와 로테이트(`toast.log.1`)를 놓쳐, 자격증명과 같은 규율로 통일했다. 조각 «전체 일치» 라 `changelog.md` 는 그대로 담긴다 |
| `**/venv/**` | 플랫폼 바이너리. 받는 쪽에서 쓸 수 없고 필요하면 재생성한다 |
| `plugins/**` | 공식 마켓플레이스 사본 6.4MB. `officialMarketplaceAutoInstalled` 가 말하듯 **받는 쪽에서 자동으로 다시 설치**되고, `known_marketplaces.json` 은 절대경로를 담고 있어 옮기면 변환 대상만 는다 |
| `cache/` · `backups/` · `*.bak-*` | 캐시와 자동·수동 백업본 |

## 실행 후

1. **`git diff` 로 무엇이 바뀌었는지 본다.** 매니페스트에 항목별 해시가 있어 변경된 파일이 드러난다
2. **git 은 사용자가 직접 한다.** 이 스킬은 파일만 만든다

## 주의

- 🔴 **내가 «안 보낸» 것은 받는 쪽에서 사라진다. 묻지도 않는다.**
  받는 쪽의 `rebuild_settings` 는 **번들의 `settings.json` 만** 훑어 결과를 새로 조립하고,
  그 PC 의 기존 `settings.json` 은 **읽지도 않는다**(`~/.claude.json` 만 `merge_claude_json` 으로 병합된다).
  그래서 판정은 「번들에 있는 것」에만 걸리고, **번들에 없는 항목은 「제외」로 판정되는 것이 아니라
  애초에 판정 대상이 아니라서 조용히 없어진다.**

  이것이 **방향에 따라 규모가 달라진다.** 이 PC 가 지난 회차에 제외한 항목은 이 PC 의
  `settings.json` 에 없으므로 **다음 내보내기에 실리지 않고**, 그 번들을 받는 PC 는 그만큼을 잃는다.
  실측 — mac → WSL 1회차에 WSL 이 `wsl_toast.py` 등록 3건을 잃었고, **WSL → mac 1회차에는
  mac 이 잃을 등록이 9건**이었다(acme 부트스트랩 3 · `report_lint` 1 · acme 전용 2 · terminal-notifier 3).
  `2026-09-12`

  **스크립트 파일은 대체로 안전하다** — 제외된 훅의 `.py` 는 받은 PC 디스크에 남아 다시 실리고,
  `~/.claude` 밖(다른 저장소)에 사는 것은 애초에 건드려지지 않는다. **없어지는 것은 등록뿐이다.**

  막는 것은 보내는 쪽이 아니라 **받는 쪽 절차**다 — `claude-config-import` SKILL.md 5단계가
  적용 전에 떠두고 적용 후 대조하게 한다. **보내기 전에 받는 쪽에 이 사실을 알린다.**
- **`home/` 은 통째로 지우고 다시 만든다.** 원본에서 지운 파일이 번들에 남으면 받는 쪽이
  이미 없어진 설정을 적용하게 된다. `decisions/` 는 받는 쪽의 결정 누적이라 지우지 않는다
- **저장소에 번들이 없는 것이 정상이다.** 받는 쪽은 적용을 마치면 번들 본체를 지우고
  `decisions/` 만 남긴다 — 사본이 원본과 함께 검색에 걸리기 때문이다. 보낼 때마다
  이 스킬로 새로 만든다
- **담을 것이 0개가 된 폴더는 통째로 사라진다.** `venv` 만 든 폴더가 그렇다 — 허용 목록에
  있어도 `DENY_SEGMENTS` 가 안을 전부 걸러내면 폴더가 없는 것과 같아진다.
  실측(2026-09-09)으로 `tools/xlsx/` 가 그랬고, 같은 `tools/` 의 `msg/`·`pptx/` 는 정상으로 담겼다.
  **이것을 고장으로 읽지 않는다** — 보낼 파일이 애초에 0개였다. 설계대로 동작한 것이다
- **그래서 「무엇이 빠졌는가」를 매니페스트에 사실로 적는다** (`excluded_venvs`).
  venv 의 경로와 설치 패키지(`이름==버전`)가 들어가고 번들 README 에 표로 실린다.
  `dist-info` 폴더명만 읽으므로 **`pip freeze` 서브프로세스가 필요 없다** — 인터프리터가
  깨진 venv 가 있어도 내보내기가 죽지 않고, 이름은 PEP 503 으로 정규화해 만든 도구
  (`pip`·`uv`)가 달라도 두 PC 의 목록이 같아진다
- **간접 증거로 알아내게 두면 못 잡는 조합이 남는다** (2026-09-09 실측).
  그전까지 받는 쪽의 탐지 기제는 둘 다 간접이었다 — 권한 규칙의 절대경로와, 온 스크립트의 import.

  | 폴더 상태 | 권한 규칙으로 | 스크립트 import 로 | 실물 |
  | --- | --- | --- | --- |
  | venv + 스크립트, 규칙 있음 | 잡힌다 | 잡힌다 | — |
  | venv + 스크립트, **규칙 없음** | 놓친다 | 잡힌다 | `tools/pptx` |
  | **venv 뿐**, 규칙 있음 | 잡힌다 | 놓친다 (담긴 파일이 0개) | `tools/xlsx` |
  | **venv 뿐, 규칙 없음** | 놓친다 | 놓친다 | 다음에 만들 도구 |

  네 번째 칸이 다음 사고였다. 두 번째 칸인 `tools/pptx` 에서는 받는 쪽이
  **「mac 이 venv 하나를 공용으로 쓴다」는 틀린 가설**을 세웠다 — 실제로는 venv 가 둘이고
  패키지가 겹치지 않는다. **매니페스트 기록은 네 칸을 모두 덮는다.**
  보내는 쪽은 venv 를 직접 보고 있어 추론할 필요가 없기 때문이다
- **0개 폴더를 스캔해 «경고»하지는 않는다** (2026-09-09 결정, 그대로 유지). 경고는 «보내는 쪽»에
  뜨는데 보내는 쪽은 이미 아는 사람이고 모르는 것은 받는 쪽이다. **경고(알림)와 기록(사실)은
  다른 층이며**, 이 스킬이 만드는 것은 기록이다
- **새 venv 도구를 만들면 권한 규칙을 함께 넣는다.** 매니페스트가 재생성은 덮지만,
  규칙이 없으면 받는 쪽에서 그 도구를 부를 때마다 승인창이 뜬다
- **매니페스트에 키를 늘려도 받는 쪽은 깨지지 않는다.** `plan_apply.py` 는 `source` 하나만 읽고
  스키마를 검사하지 않는다(실측 2026-09-09). 그래서 옛 번들에 새 키가 없어도, 새 번들에 키가
  늘어도 양쪽이 함께 돈다 — 결정 누적도 **항목별 해시**로 판별하므로 영향받지 않는다
- 담기면 안 되는 항목이 번들에 들어가면 **스크립트가 스스로 중단한다.** 같은 판정을
  `tests/test_claude_config_bundle.py` 가 다시 검사한다 — 두 층 모두 `export.py` 의
  **같은 함수**를 쓴다. 판정을 두 벌로 만들면 한쪽이 담아도 된다고 한 파일을 다른 쪽이 거부한다
