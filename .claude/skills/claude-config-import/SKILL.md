# 전역 설정 받기

다른 PC 에서 `claude-config-export` 로 내보낸 번들을 이 PC 에 적용한다.
**경로를 입력할 필요가 없다** — 스크립트가 저장소 안의 `claude-config/` 를 스스로 찾는다.

## 절차

### 1. 판정

```bash
poetry run python .claude/skills/claude-config-import/plan_apply.py
```

항목을 셋으로 나눠 보여준다.

| 분류 | 뜻 |
| --- | --- |
| **그대로 적용** | OS·경로와 무관한 것. 스킬·커맨드·규칙·대부분의 권한 |
| **변환 후 적용** | 출처 PC 의 경로가 박힌 것. **바꿔서 적용하고 무엇을 바꿨는지 보고한다** |
| **제외 (승인 필요)** | 자동으로 판단할 수 없거나 이 PC 에 대상이 없는 것 |

### 2. 승인 — 이 단계를 건너뛰지 않는다

**제외 후보를 사용자에게 하나씩 사유와 함께 보여주고 결정을 받는다.**
목록만 던지면 사용자가 판단할 수 없다. 각 항목에 대해 「적용」과 「제외」 중 무엇을 원하는지 묻는다.

훅은 **전부 이 단계로 온다.** 자동 판정을 하지 않기 때문이며, 그 이유는 아래에 있다.

### 3. 결정 저장

```bash
poetry run python .claude/skills/claude-config-import/plan_apply.py --save-decisions
```

승인 결과를 반영하려면 `claude-config/decisions/<pc_id>.json` 의 `items[<키>].decision` 을
`apply` 또는 `exclude` 로 고친다. 다음 실행부터 그 항목은 다시 묻지 않는다.

### 4. 적용

```bash
poetry run python .claude/skills/claude-config-import/plan_apply.py --apply
```

**승인받지 않은 제외 후보가 남아 있으면 스크립트가 중단한다.** 2·3 단계를 먼저 끝낸다.

적용 전에 `~/.claude/settings.json` 과 `~/.claude.json` 을 타임스탬프로 백업한다.
적용 후 Claude Code 를 다시 시작해야 반영된다.

### 5. 대조 — 이 PC 에만 있던 것이 사라졌는지 본다

**`settings.json` 은 병합이 아니라 번들 기준으로 통째로 재작성된다**(`rebuild_settings()`).
그래서 **번들에 없는 키는 이 PC 에 있었더라도 조용히 빠진다.** 백업과 대조해 되살린다.

```bash
python3 - <<'EOF'
import json, pathlib
home = pathlib.Path.home()
backup = sorted((home / ".claude").glob("settings.json.bak-*"))[-1]
before = json.loads(backup.read_text())
after = json.loads((home / ".claude/settings.json").read_text())
print("사라진 키:", [k for k in before if k not in after] or "없음")
def hooks(d):
    return {(e, g.get("matcher", "*"), x.get("command", ""))
            for e, gs in d.get("hooks", {}).items() for g in gs for x in g.get("hooks", [])}
print("사라진 훅:", [f"{e}[{m}]" for e, m, _ in hooks(before) - hooks(after)] or "없음")
EOF
```

**완료 기준: 둘 다 「없음」이 될 때까지 되살린다.**

되살릴 것을 **적용 전에 먼저 떠둔다** — 이 PC 고유의 알림 훅이 대표적이다.
번들의 대응 훅을 「제외」로 정했다면 그 자리는 비고, 이 PC 것도 함께 사라진다.

### 6. 옮겨왔지만 못 쓰는 것을 쓸 수 있게 만든다

**적용은 설정을 옮길 뿐 실행 환경을 만들지 않는다.** 온 것 중 이 PC 에서 실행되지 않는 것을
찾아 **바로 갖춘다.** 「나중에」로 미루면 다음 세션이 원인을 다시 찾는다.

| 무엇을 보나 | 어떻게 |
| --- | --- |
| MCP 서버의 실행 파일 | `~/.claude.json` 의 `command` 가 실재하는지 확인하고, 없으면 설치한다. **`type` 이 `http` 인 서버는 `command` 가 없는 것이 정상**이다 |
| MCP 서버가 참조하는 파일 | `env` 의 경로(`CREDENTIALS_PATH` 등)가 실재하는지 확인한다 |
| 훅이 부르는 도구 | 판정 단계가 「이 PC 에 없는 도구」로 이미 알려준다 |
| **매니페스트의 `excluded_venvs`** | **1순위다.** 보내는 쪽이 실제로 본 venv 의 경로와 설치 패키지(`이름==버전`)가 그대로 들어 있다. 번들 README 에도 표로 실린다 |
| **권한 규칙이 가리키는 실행 파일** | 위 목록이 없는 **옛 번들**의 보조 수단. `Bash(/...)` 규칙의 절대경로를 본다 |
| **번들에 온 스크립트의 서드파티 import** | 같은 보조 수단. 권한 규칙은 **규칙이 있는 venv 만** 잡으므로(실측 2026-09-09 `tools/pptx`) 온 `.py` 의 import 도 함께 본다 |

**venv 는 매니페스트의 목록을 그대로 설치해 재생성한다.** 무엇을 넣을지 추측하지 않는다.
그 키가 없는 옛 번들에서만 스크립트의 import 를 읽으며, 그때도 표준 라이브러리가 아닌
import 가 곧 설치 목록이다.

**목록은 `이름==버전` 이지만 버전을 고정할지는 이쪽 판단이다.** 기록은 사실이고 사용은 선택이다 —
실측(2026-09-09)에서는 이름만 넘겨 설치했는데 보내는 PC 와 **버전까지 전부 일치**했다.
전이 의존(`lxml`·`pillow` 등)은 따라오므로 직접 설치분만 넘겨도 된다.

**두 보조 수단만으로는 못 잡는 조합이 있다** — venv 뿐인 폴더에 권한 규칙까지 없으면
어느 쪽에도 걸리지 않는다. 그래서 1순위가 매니페스트다(네 칸 표는 `claude-config-export`
스킬의 「주의」 절에 있다).

```bash
uv venv ~/.claude/<도구>/venv --python 3.12
uv pip install --python ~/.claude/<도구>/venv/bin/python <패키지>
```

**`python3 -m venv` 를 쓰지 않는다** — Debian 계열은 `ensurepip` 가 별도 패키지라 실패한다.
`uv` 는 시스템 패키지 없이 만든다.

**설치할 수 있는 것은 승인만 받고 바로 설치한다.** 사용자만 만들 수 있는 것(브라우저 인증,
발급받아야 하는 시크릿)은 **무엇을 어디서 받아야 하는지까지 적어** 보고한다.

### 7. 번들을 지운다

적용이 끝나면 `claude-config/` 의 **번들 본체를 지우고 `decisions/` 만 남긴다.**

```bash
rm -rf claude-config/home claude-config/claude_json.json claude-config/MANIFEST.json claude-config/README.md
```

**git 은 사용자가 직접 한다.** 지운 자국은 `git status` 에 그대로 드러난다.

**왜 지우나**: 번들은 `~/.claude` 사본이라 스킬·규칙·설정 문서가 저장소에 **두 벌**로 존재한다.
저장소를 검색하면 사본이 원본과 함께 걸려 결과를 오염시킨다.

**왜 `decisions/` 는 남기나**: 다음 마이그레이션에서 **이미 승인한 항목을 다시 묻지 않게** 한다.
경로 매핑도 여기 있어, 지우면 같은 함정을 다시 밟는다.

**번들이 필요해지면 보내는 PC 에서 `claude-config-export` 를 다시 돌린다.** 그것이 원본이고
이 폴더는 사본이다. 테스트는 번들이 없으면 통과하도록 이미 짜여 있다.

## 훅을 자동 판정하지 않는 이유

셸 명령의 이식성은 **문맥을 알아야** 판단할 수 있다.

- `terminal-notifier` 는 macOS 전용이라 다른 곳에서는 못 쓴다
- 반면 `PY=$(command -v python3 || command -v python)` 은 **폴백이 있어 그대로 동작한다**

이 차이를 파서가 알 수 없다. 실제로 명령을 파싱해 실행 파일을 뽑아 봤더니
`]` · `2>/dev/null)` · `/.claude/hooks/plan_gate.py` 를 실행 파일로 오인했고,
고칠 때마다 새로운 실패 형태가 나왔다. **잘못된 자동 판정은 멀쩡한 훅을 버리거나 깨진 훅을
넣으며, 둘 다 조용히 나쁘다.**

그래서 훅은 사람이 판단하고, 스크립트는 **판단 재료만** 준다 — 전체 명령과, 그 안에 등장하지만
이 PC 에서 찾을 수 없는 도구 목록.

기본 제안은 「제외」다. 깨진 훅은 매 이벤트마다 실패하므로 그쪽이 안전하다.

## 권한 규칙은 명령이 없어도 빼지 않는다

`Bash(rg *)` 의 `rg` 가 이 PC 에 없어도 **제외하지 않는다.** 권한 규칙은 「이 명령을 쓰면
승인 없이 실행한다」는 뜻이라 명령이 없으면 그냥 안 쓰일 뿐 해가 없고, 나중에 설치하면
그대로 살아난다. **빼면 오히려 그때 승인창이 뜬다.**

실행 여부를 따지는 것은 훅과 경로뿐이다.

## 경로가 홈만으로 안 맞을 때

기본 치환은 「출처 PC 의 홈 -> 이 PC 의 홈」 하나다. 작업 폴더가 홈 밖에 있거나 이름이
다르면 그것만으로 부족하다. 결정 파일의 `path_map` 에 쌍을 추가한다.

```json
{
  "path_map": {
    "/Users/yubeen/Workspace": "D:/dev"
  }
}
```

**긴 경로가 먼저 치환된다** — 짧은 홈 경로를 먼저 바꾸면 그 안에 든 긴 경로가 이미 바뀌어
뒤 규칙이 걸리지 않는다.

## 결정이 쌓여도 내용이 바뀌면 다시 묻는다

결정은 항목 내용의 SHA-256 과 함께 저장된다. **재사용은 「키」와 「해시」가 둘 다 맞을 때만**
일어나고, 한쪽이라도 어긋나면 다시 묻는다. 옛 결정을 바뀐 내용에 적용하면 사용자가 승인한 적
없는 상태가 조용히 만들어진다.

| 다음 실행에서 | 어떻게 되나 |
| --- | --- |
| 키도 해시도 같다 | **안 묻고 그대로 재사용한다** |
| 키는 같은데 내용이 바뀌었다 | 그 항목만 다시 묻는다 (「지난 결정이 있으나 내용이 바뀌어 다시 묻습니다」) |
| **내용은 같은데 키가 달라졌다** | 저장된 항목을 찾지 못해 **다시 묻는다** |

**세 번째 줄을 놓치기 쉽다.** 훅의 키는 `이벤트 + 그룹 라벨 + 그룹 안 순번` 인데, 보내는 PC 에서
**그룹 순서만 바꿔도** 라벨이나 순번이 달라져 재승인 대상이 된다. 내용이 한 글자도 안 바뀌었는데
다시 물어도 고장이 아니다 — 조용히 잘못 적용하는 것보다 다시 묻는 쪽이 안전하다.

`[실측] 2026-09-12` — `block-emoji-in-code.py` 가 해시(`01336f…`) 그대로인 채 키만
`[Write|Edit|NotebookEdit|Bash][0]` → `[…Bash#2][0]` 로 갈려 재승인 대상이 됐다.

결정 파일은 **PC 별로 갈린다**(`<hostname>-<platform>.json`). 회사 mac 에서 제외할 것과
집 Windows 에서 제외할 것이 다르기 때문이다. git 으로 공유되므로 다른 PC 에서
「저쪽은 무엇을 뺐는지」 볼 수 있다.

## 가려진 자격증명은 이 PC 의 값으로 되돌아간다

MCP 서버의 API 키는 파일이 아니라 `~/.claude.json` 안에 **값**으로 들어 있어, 내보낼 때
`__CLAUDE_CONFIG_REDACTED__` 로 가려져 온다.

- **이 PC 에 이미 그 키가 있으면 그대로 유지된다.** 번들이 덮어쓰지 않는다
- 없으면 센티널이 남고, **채워야 할 항목**으로 보고된다. 서버를 통째로 빼지 않는 이유는
  빼면 「MCP 가 통째로 사라진다」는 이 기능의 취지에 역행하기 때문이다

**판정 단계의 「그대로 적용하되 알아둘 것」 절을 본다.** 적용한 뒤에 알면 늦다.
센티널이 남은 항목은 `~/.claude.json` 에서 그 자리를 찾아 실제 키로 바꾼다.

## 무엇이 애초에 번들에 없는가

내보낼 때 빠지는 것은 아래가 전부다. 없다고 놀라지 않는다.

| 빠지는 것 | 왜 |
| --- | --- |
| 자격증명 (`keys/**` · `*.env` · `*.pem` · `*.key`) | 이 저장소가 PUBLIC 이다 |
| MCP 서버의 자격증명 «값» (`headers`·`env` 의 비경로 값) | 센티널로 가려 담는다. 위 절이 처리를 정한다 |
| 세션 상태와 이력 (`projects/` · `sessions/` · `history.jsonl` · `file-history/`) | 다른 PC 의 이력이 섞이면 되돌릴 수 없다 |
| 감사 로그 (`db/*.jsonl`) | 그 PC 에서만 뜻이 있다 |
| 플랫폼 venv (`**/venv/**`) | 바이너리라 받는 쪽에서 쓸 수 없다. 필요하면 재생성한다 |
| 플러그인 (`plugins/**`) | 공식 마켓플레이스 사본이며 받는 쪽에서 자동으로 다시 설치된다 |
| 캐시와 자동 백업 (`cache/` · `backups/` · `*.bak-*`) | 옮길 값이 아니다 |

**받는 PC 에서 필요한 자격증명은 그 PC 에서 새로 만든다.** 다만 「새로 만든다」가 무엇을
뜻하는지는 파일마다 갈린다 — 구글시트의 두 파일이 그 예다.

| 파일 | 이 PC 에서 |
| --- | --- |
| `keys/sheets-mcp-token.json` | 동의화면이 「테스트」 상태라 7일마다 만료된다. **재인증하면 생긴다** |
| `keys/sheets-mcp-oauth.json` | Google Cloud Console 에서 받은 **클라이언트 시크릿**이다. **재인증으로는 생기지 않는다** — 따로 옮기거나 Console 에서 다시 내려받는다 |

**「재인증하면 되겠지」로 넘기면 두 번째 파일에서 막힌다.** 지라(atlassian)처럼 브라우저
OAuth 로 인증하는 서버는 이 PC 에서 한 번 인증하면 된다.

## 실측 기록 — 회사 mac 에서 집 WSL 로 (2026-09-09)

`yubeens-Mac-mini.local` (darwin) -> `DESKTOP-4CN5LK3` (linux, WSL2).
**그대로 249건 · 변환 40건 · 제외 14건**으로 끝났고, 권한 규칙이 allow 49->142 · deny 9->68 ·
ask 4->26 으로 늘었다.

### 판정이 그대로 통과시키면 틀리는 것 넷

| 무엇 | 어떻게 드러났나 | 어떻게 했나 |
| --- | --- | --- |
| **홈 이름은 같아도 폴더 이름이 다르다** | mac 은 `~/Workspace`, 이 PC 는 `~/workspace` (**소문자**). 홈 치환만 걸려 `/home/yblee/Workspace` 라는 없는 경로가 됐고, **판정은 이것을 「변환 후 적용」으로 통과시킨다** — 권한 규칙 12건이 조용히 빗나간다 | `path_map` 에 쌍을 넣었다. 넣지 않으면 저장소를 읽을 때마다 승인창이 뜬다 |

### 「보내는 PC 를 봐야 한다」는 대개 사실이 아니다 (2026-09-09 정정)

위 두 줄 때문에 보내는 PC 에 `pip freeze` 를 물으러 갔지만 **답은 이미 번들 안에 있었다** —
전역 `CLAUDE.md` 의 「로컬 엑셀 파일 (.xlsx) 편집」·「로컬 파워포인트 파일 (.pptx) 편집」
두 절이 venv 경로와 설치 패키지를 적어두고 있고, mac 의 `pip freeze` 와 일치했다.
**도구를 만들 때 그 절차를 `CLAUDE.md` 에 적어두면 번들이 그것을 함께 나른다.**

- **venv 는 둘이고 패키지가 겹치지 않는다.** 「mac 이 하나를 공용으로 쓴다」는 가설은 틀렸다 —
  권한 규칙에 `xlsx` 만 있던 것은 공용이라서가 아니라 **`pptx` 규칙을 만든 적이 없어서**다.
  그 뒤 보내는 PC 에 규칙을 넣었으므로 다음 번들에는 두 경로가 다 온다
- **그 두 절의 생성 명령은 mac 전용이다**(pyenv 절대경로). 설치 «목록»만 가져다 쓰고
  만드는 명령은 위 `uv` 로 대체한다
- `tools/msg/` 는 표준 라이브러리만 써서 **아무것도 안 해도 된다**

**「권한 규칙은 왔는데 그 도구는 없다」가 이 스킬의 정상 상태다.** venv 는 번들에 담기지 않는다.
**무엇을 다시 만들지는 매니페스트의 `excluded_venvs` 가 경로와 패키지까지 적어 온다**
(2026-09-09 이후 번들). `Bash(/...)` 규칙과 스크립트의 import 는 그 키가 없는 옛 번들에서만
쓰는 보조 수단이다.

### `--apply` 가 영구히 막혔다 — matcher 가 같은 그룹이 여럿일 때

**증상**: 결정을 저장해도 pending 2건이 사라지지 않아 `--apply` 가 매번 중단됐다.

**원인**: `hook_key` 가 `이벤트 + matcher + 순번` 으로만 키를 만들었다. 한 이벤트에
**matcher 까지 같은 그룹이 여럿** 달릴 수 있는데(이 번들의 `SessionStart` 두 그룹이 모두 `*`,
`PreToolUse` 두 그룹이 모두 `Write|Edit|NotebookEdit|Bash`) 그때 키가 겹친다.
`save_decisions` 의 `items` 는 키로 만든 dict 라 **한 키에 해시가 하나만** 담기므로,
겹친 쌍의 앞 항목은 해시가 영영 맞지 않아 `needs_confirmation` 이 풀리지 않는다.

**같은 뿌리에서 나온 두 번째 결함이 더 조용하다** — `_decision_map` 도 키로 만든 dict 라
**나중 항목의 결정이 앞 항목에 적용된다.** 즉 「제외」로 정한 훅이 조용히 적용될 수 있었다.
이번 번들은 두 쌍 모두 같은 결정을 원해 결과가 우연히 맞았을 뿐이다.

**고친 방법**: `matcher_labels()` 가 같은 matcher 의 **두 번째 그룹부터** 순번 접미사(`#2`)를
붙이고, `classify_settings` 와 `rebuild_settings` 가 **그 함수 하나를 공유**한다.
첫 그룹은 matcher 를 그대로 두어 **기존 키가 보존**되므로 지난 결정 대부분이 계속 맞는다.
`tests/test_claude_config_import.py` 가 키 유일성과 **결정 독립성**을 함께 고정한다.

> **탈락안**: ① 항상 그룹 번호를 넣는다 — 기존 훅 키가 전부 바뀌어 11건을 다시 물어야 한다.
> ② 명령문 해시를 키로 쓴다 — 키와 값에 해시가 두 벌이 되고 역시 기존 키가 전부 바뀐다.

### 훅 «스크립트» 안의 경로는 `path_map` 이 못 잡는다

`block-harness-memory-write.py` 가 `~/Workspace`(대문자 W)로 슬러그를 만드는데 이 PC 는
`~/workspace`(소문자)다. 스크립트가 `~` 에서 **런타임에 조립**하므로 번들 텍스트 치환이 닿지 않는다.

**결과는 조용한 무동작이다** — 훅은 등록되고 실행되는데 슬러그가 영영 일치하지 않아
아무것도 막지 않는다. 에러도 로그도 없다. 실측으로 이 PC 의 슬러그는
`-home-yblee-workspace-verify-lab` 인데 훅이 만든 값은 `-home-yblee-Workspace-verify-lab` 이었다.

- **판정은 이것을 잡지 못한다.** 「그대로 적용」으로 통과시킨다 — 파일 안에 출처 홈 경로
  문자열이 없기 때문이다. 2026-09-09 의 「홈 이름은 같아도 폴더 이름이 다르다」와 같은 함정이
  **권한 규칙이 아니라 스크립트 안에서** 재발한 것이다
- 고친 자리는 `~/.claude/hooks/` 의 **적용본**이다. **다음 번들 적용이 덮어쓴다** —
  영구히 고치려면 **보내는 PC(mac)의 원본도 같은 방식으로** 고쳐야 한다
- 확인은 훅을 직접 실행해서 한다. 다만 **테스트 명령 자체가 훅에 걸린다** —
