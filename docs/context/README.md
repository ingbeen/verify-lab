# context — 현재 운용 상태와 이 프로젝트가 시작된 이유

이 폴더의 두 문서는 **사용자의 현재 투자 상태를 나타내는 가장 중요한 문서**입니다.
verify-lab이 왜 존재하는지, 검증 결과를 어떤 판단에 쓸 것인지가 여기서 나옵니다.

**작업 전에 반드시 읽으세요.** 검증 설계를 논의하거나 결과를 해석할 때 이 맥락을 모르면
"통계적으로 유의한가"에만 답하고 **"그래서 내 포트폴리오에 무슨 의미인가"** 를 놓칩니다.

## 두 문서

### RESEARCH_q2_2xs_qqq_correlation.md — 이 프로젝트가 시작된 이유

운용 중인 포트폴리오(Q-2-2XS)와 QQQ의 상관 구조를 분해한 연구입니다.

핵심 결론: 이 포트폴리오의 낮은 상관(0.673)은 **자산 분산이 아니라 하락장에서 주식을 비우는
타이밍 신호**에서 나왔습니다. 평상시(전체의 74.2%)에는 QQQ와 0.972로 거의 같은 자산이고,
주식을 비운 21.8% 구간에서만 연결이 끊깁니다.

> **verify-lab은 이 연구의 후속입니다.** "QQQ와 다르게 움직이는 매매법을 찾자"가 출발점이며,
> 12장 "후속 연구 방향"에 적힌 두 갈래(연동 단절 구간 확대 / 보유 중 상관 자체 저감) 중
> 어느 쪽도 아직 검증되지 않았습니다.

검증 결과를 해석할 때 함께 물어야 할 질문: **이 신호는 QQQ와 다르게 움직이는가, 아니면
QQQ가 흔들릴 때 같이 흔들리는가.**

> **[2026-08-30 갱신] 이동평균이 EMA200 → SMA200으로 바뀌면서 수치가 전량 재산출됐습니다.**
> 전체 상관은 0.708 → 0.673으로 내려갔지만 **이것을 개선으로 읽으면 안 됩니다.**
> 원인은 주식을 비운 날이 744일 → 1,060일로 늘어난 것이고, 시장 참여를 줄이면 상관은
> 자동으로 내려갑니다. 같은 변화가 CAGR을 16.23% → 15.43%로 깎았습니다 —
> **낮아진 상관은 성과 개선이 아니라 그 수익 희생의 다른 얼굴입니다.**
>
> **반면 verify-lab의 출발점은 오히려 강화됐습니다.** 주식 보유 구간 상관이
> 0.9718 → 0.9719로 사실상 불변이므로, "낮은 상관은 자산 분산이 아니라 타이밍 신호에서
> 나온다"는 결론이 **이동평균 유형과 무관한 구조적 사실**임이 확인됐습니다.

### RESEARCH_qqq_late_entry.md — 현재 보유 판정

`buffer_zone_qqq` 전략의 진행 중 트레이드에 뒤늦게 합류할지에 대한 판정입니다.

핵심 결론: **이번 사이클에는 진입하지 않고 다음 정식 매수 시그널을 기다립니다.**
9장에 현재 트레이드 상태(진입일, 지나간 기회, 다음 기회 발동 조건)가 있습니다.

> **[2026-08-30 갱신] 결론은 유지되지만 대상 트레이드와 근거가 모두 바뀌었습니다.**
> SMA 기준으로 최초 대상이던 2025-05-16 트레이드는 **2026-03-30에 청산**됐고(+8.85%),
> 전략은 **2026-04-17에 새로 진입**했습니다. 운용자는 **이 시그널에도 참여하지 못했습니다.**
> 진입하지 않는 근거도 "2번째 이후 & 1년 이후 부류의 나쁜 표본"에서
> **휩소 규칙(직전 기회로부터 60일 미달)** 으로 교체됐습니다 —
> 옛 근거로 인용하면 틀린 설명이 됩니다.
>
> 미참여가 **2회 연속**(2025-05-16, 2026-04-17)이 되면서 문제의 성격도 바뀌었습니다.
> 첫 번째는 전략을 몰라서였고 두 번째는 아니므로, **「발견 시점」의 문제에서
> 「시그널 포착·실행」의 문제로 옮겨갔습니다.** 후자는 이 연구의 범위 밖입니다.

> 데이터 기준일이 **2026-08-21**로 고정된 문서입니다. 9장(현재 트레이드 적용)의 수치는
> 시간이 지나면 낡습니다. 7~8장(기회별 성과표·통계)은 해당 트레이드가 끝나기 전까지 유효합니다.

## 읽을 때 주의

- **이 문서들은 다른 프로젝트에서 이관됐습니다.** 본문의 파일 경로 링크(`src/qbt/...`,
  `전략_검증_보고서.md` 등)는 verify-lab에 존재하지 않아 열리지 않습니다. 내용을 읽는 용도입니다
- 원본을 **임의로 수정하지 않습니다.** 사용자가 갱신하는 문서이며,
  **사용자가 명시적으로 갱신을 요청한 경우에만** 수정합니다 (`.claude/rules/context.md`와 같은 규정).
  원본 저장소가 갱신돼 동기화가 필요해 보이면 고치지 말고 **먼저 사용자에게 알립니다**
- 두 문서는 `.claude/rules/research.md`가 규정한 결과 문서 형식의 **실물 예시**이기도 합니다.
  새 검증 결과를 쓸 때 구성(결론 요약표 → 근거 → 해석 → 기각된 가설 → 한계 → 재현 방법)을 참고하세요
