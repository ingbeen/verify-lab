## 1. 목적

극단적인 등락 이벤트와 연속 등락 이후, 향후 수익률이 통계적으로 유의미한 패턴을 보이는지 검증한다.

**이것은 매매 전략 개발이 아니라 측정이다.** 최적 파라미터를 찾지 않는다.
"유의미한 패턴이 없다"도 유효한 결론이며, 그 결론이 나오면 그대로 보고한다.

**지수가 아니라 실제 매매 가능한 상품을 대상으로 한다.** 검증 결과를 그대로 집행할 수 있어야 하므로,
이벤트 판정과 수익률 측정 모두 아래 종목의 실제 체결가로 수행한다.

| --- | --- | --- | --- |
| 미국 | **QQQ** (Invesco QQQ Trust) | yfinance | 1999-03-10 |
| 한국 | **KODEX 200** (`069500`) | pykrx `get_etf_ohlcv_by_date` | 2002-10-14 |

- **수익률 계산은 수정주가 기준으로 한다.** 두 종목 모두 분배금을 지급하므로, 원본가로 계산하면
  분배락일에 인위적 하락이 잡히고 장기 구간 수익률이 과소 계상된다.

  - KODEX 200: 분배락 조정 여부를 **실측으로 확인**하고, 조정되지 않았다면 별도 처리한다 (§9)
- **일간 등락률과 forward return 모두 동일한 기준(수정주가)을 사용한다.** 혼용 금지.

## 3. 이벤트 정의

### 테스트 A — 역대급 등락

**정의**: 판정 시점까지 누적된 데이터 기준으로, 일간 등락률이 **역대 상위 10위** 안에 드는 날.

**순위 산정 방식 (확장 창, Expanding Window)**

- 각 종목의 데이터 시작일을 고정 시작점으로 하고, 판정일까지의 모든 데이터로 순위를 매긴다.
- 예: 2015-08-24 판정 → 2000-01-01 ~ 2015-08-24 데이터 내 순위
- **미래 데이터를 절대 참조하지 않는다.** 전체 기간으로 한 번에 순위를 매기는 것은 금지(look-ahead).
- 순위는 시간이 지나며 계속 바뀐다. 판정 당시 1위였던 날이 나중에 3위가 될 수 있으며,
  그 사실 자체를 결과표에 "당시 순위" 컬럼으로 남긴다.

**순위 컷**: 메인은 **K=10**. 강건성 확인을 위해 K=5·20 결과도 함께 산출한다 (§6).

**폭락과 폭등을 분리 집계한다.**

**사건 단위 집계를 함께 낸다.** 30일 이내에 붙어 있는 신호는 같은 사건에서 파생된 것으로 보고
사건 번호를 부여한다. 신호를 버리지는 않되, "신호 N건 = 사건 M개"를 항상 병기한다 (근거: §7 결정 ③).

### 테스트 B — 연속 등락

**정의**: **N일 연속 상승 또는 하락이 달성된 그날.** 그날 종가로 판정이 끝나고 다음 날 시가에 집행할 수 있다.

> 원 요청문의 "연속 구간의 마지막 날"은 채택하지 않는다. 그날이 마지막인지는 **다음 날 주가를 봐야**
> 알 수 있어 미래 참조가 된다. 이 정의로 낸 결과는 실제 매매에 쓸 수 없다 (근거: §7 결정 ④).

**N 범위**: 3, 4, 5, 6, 7, 8, 9, 10 전부 산출한다. 발생 빈도(연간 몇 회)를 먼저 보고하고,
너무 자주 발생해 의미가 없는 N이 있으면 그 판단 근거를 함께 제시한다.

**중복을 허용한다.** 7일 연속 랠리는 N=5·6·7 신호를 모두 만든다. N별로 독립 집계하되,
**"N=5와 N=7은 같은 랠리를 공유하므로 서로 독립된 결과가 아니다"** 를 결과 문서에 명시한다
(근거: §7 결정 ⑤).

**등락률이 정확히 0%인 날**은 연속을 끊되 방향을 부여하지 않는다.

**연속 상승과 연속 하락을 분리 집계한다.**

**집계 기간**: 테스트 A와 동일. 그 이전 구간 결과는 참고용으로 별도 표에 제시한다.

## 4. 측정 방법

**측정 구간 (forward return)**: 이벤트 발생 다음 거래일부터 아래 각 시점까지의 수익률

- 단기: 1일, 1주(5거래일)
- 장기: 1개월(21거래일), 3개월(63거래일), 6개월(126거래일), 1년(252거래일)

**수익률 기준점**: 이벤트일 종가 기준과 익일 시가 기준을 **모두** 산출한다.
두 값의 차이가 갭으로 새는 몫이며, 실제 집행 가능 구간은 익일 시가 기준이다.

**측정 구간 끝이 데이터 범위를 넘어가는 신호**는 해당 구간에서 제외하되, 몇 건이 제외됐는지 명시한다.

## 5. 베이스라인 (필수 — 3종 모두)

수익률 절대값만으로는 판단할 수 없다. 아래 셋을 모두 산출해 비교한다.

| 베이스라인 | 내용 | 답하는 질문 |
| --- | --- | --- |
| **단순 보유 대비** | 같은 기간 전체의 평균 forward return | "평소보다 나은가" |
| **무작위 진입 대비** | 같은 기간에서 무작위 날짜를 뽑아 forward return 분포 생성 (1,000회 반복, **난수 시드 고정**) | "운이 아닌가" |
| **조건부 대비** | 하락 국면 내에서만 비교 — **종가가 200일 이동평균 아래인 날.** EMA·SMA 둘 다 산출해 병기 | "같은 국면 안에서 이 날이 특별한가" |

세 결과가 어긋나는 지점이 있으면 그 자체를 명시적으로 보고한다.

## 6. 통계 처리와 강건성

각 이벤트 × 각 측정 구간마다 아래를 모두 보고한다.

- **평균과 중앙값을 반드시 병기한다.** 평균은 소수의 극단 사례에 왜곡된다.
- 평균과 중앙값이 크게 벌어지면 → 소수 사건이 결과를 만들고 있다는 신호이므로 명시적으로 지적한다.
- 승률 (양수 비율) / 최고값 / 최악값 / 표준편차
- **표본 수 (절대 생략 금지)** — 신호 건수와 사건 건수를 함께 낸다
- 유의성 검정 (t-test 등, 사용한 방법 명시). **표본이 한 자릿수인 칸에는 검정을 붙이지 않고
  "표본 부족으로 검정 불가"로 표기한다.** 숫자를 만들어내는 것이 더 나쁘다

### 강건성 체크

| 항목 | 방법 | 무너지면 의미 |
| --- | --- | --- |
| 순위 컷 민감도 | K = 5 / 10 / 20에서 방향이 일관되는가 | 특정 값에만 붙은 우연 |
| 집계 시작 민감도 | 2003 / 2005 / 2008 / 2011년 시작에서 일관되는가 | 구간 선택에 의존 |
| 연속 N 민감도 | N 값들에서 방향이 일관되는가 | 동일 |
| 구간별 일관성 | 2010년대 / 2020년대로 나눠 방향이 일관되는가 | 레짐 의존적, 사용 불가 |
| 코스피 하위표본 | 2015년 6월 이후만 별도 집계 | 가격제한폭 30% 확대 효과 |

> **가격제한폭 항목은 실측 후 판단한다.** 2015년 6월 개별종목 제한폭이 15%→30%로 확대됐지만,
> KODEX 200은 지수 ETF라 일간 등락이 ±15%를 넘긴 적이 사실상 없을 것으로 예상된다.
> 실제로 그렇다면 이 체크는 무의미하므로 "해당 없음"으로 기록하고 넘어간다.

설치된 `pykrx 1.2.8`에서 **함수의 존재 여부와 호출 가능 여부**를 확인한 결과다.

| 항목 | 결과 |
| --- | --- |
| §2가 지정한 `get_etf_ohlcv_by_date` | **존재한다.** 함께 `get_etf_price_deviation`(괴리율), `get_etf_ticker_list`, `get_etf_tracking_error`도 제공된다 |
| 인증 | **필수.** `KRX_ID`/`KRX_PW` 환경 변수가 없으면 `KRX 로그인 실패`로 모든 조회가 실패한다 |
| 자격증명 보관 | `.env` (`.gitignore`에 제외돼 있음을 `git check-ignore`로 확인). **준비 완료** — 키는 `KRX_ID`·`KRX_PW` |

`reference/pykrx_실측기록.md` §0이 개별종목 조회에서 같은 제약을 기록해 뒀고, ETF 함수에서도
동일하게 적용됨을 이 저장소 환경에서 재확인했다.

> **함수가 있다는 것과 반환값이 쓸 만하다는 것은 다른 문제다.** 실제 반환 컬럼 구성과
> 분배락 조정 여부는 **아직 확인되지 않았다.** §9를 실측해 확정한다.

### KRX 자격증명을 코드에 연결하는 방법 (구현 시 참고, 2026-08-10)

**`.env`를 만들어 둔 것만으로는 pykrx가 동작하지 않는다.** 설치본 소스를 직접 확인한 결과다.

| 확인한 것 | 결과 |
| --- | --- |
| pykrx가 자격증명을 읽는 방법 | `os.getenv("KRX_ID")` / `os.getenv("KRX_PW")` — **환경 변수만 본다** |
| pykrx가 `.env`를 읽는가 | **읽지 않는다.** 패키지 안에 dotenv 참조가 하나도 없다 |
| `python-dotenv` 설치 여부 | **미설치.** `pyproject.toml` 의존성에도 없다 |
| 세션 만료 | 만료 시 `get_auth_session()`이 환경 변수를 다시 읽어 **자동 재로그인**한다 |

근거 위치는 설치본의 `pykrx/website/comm/auth.py`다.

따라서 구현 시 아래 세 가지가 필요하다.

1. **`python-dotenv`를 의존성에 추가한다.** 지금은 없다
2. **`.env`를 환경 변수로 올리는 로더를 만든다.** 셸 환경 변수보다 `.env`를 우선(`override=True`)해야
   어느 환경에서 실행하든 같은 계정을 쓴다
3. **그 로더를 `pykrx` import보다 먼저 호출한다.** `build_krx_session()`의 기본 인자가
   `login_id: str = os.getenv("KRX_ID")` 형태라 **import 시점에 값이 고정**되기 때문이다.
   `get_auth_session()`은 호출 시점에 다시 읽어 복구하지만, 순서를 지키는 쪽이 안전하다

`reference/pykrx_collect/krx_credentials.py`가 이 세 가지를 이미 만족하는 구현이다.
**읽고 이해한 뒤 새로 작성한다** — reference는 옛 패키지를 참조해 그대로는 동작하지 않는다.

> **로그 주의**: 로그인 성공 시 pykrx가 **로그인 ID를 표준 출력에 찍는다**(비밀번호는 찍지 않는다).
> 실행 로그를 공유하거나 결과 문서에 붙일 때 이 줄이 섞이지 않게 한다.

## 9. 착수 전 실측이 필요한 항목

아래는 아직 확인되지 않았다. Phase 1에서 실측하고 그 결과를 이 문서에 추가한다.
**결과에 따라 순위 축적 구간 조정이 필요하다고 판단되면 먼저 사용자에게 보고하고 판단을 받는다.
임의로 데이터를 잘라내지 않는다.**

1. **KODEX 200 분배금 조정 여부** — `get_etf_ohlcv_by_date` 반환값이 분배락 조정된 값인가.
   조정되지 않았다면 조정 방법과 그 근거를 문서에 남긴다
2. **초기 유동성** — 2002~2008년 구간의 일별 거래량·거래대금 추이. 거래가 극히 적은 구간의 가격 변동은
   실제 시장 움직임이 아닐 수 있고, 순위 축적 구간을 오염시킨다
3. **괴리율(NAV 대비 시장가)** — 극단적 괴리가 발생한 날이 이벤트로 잡히는지 확인
4. **결측·거래정지일** 유무
5. **국내도 "사건이 소수" 문제가 있는가** — 국내는 2008·2011·2020·2024-08 등 사건이 더 많을 가능성이 있다

## 11. 부가 출력 (필수)

- **신호일 전체 목록**: 날짜, 등락률(%), 판정 시점 순위, 사건 번호, 참고용 z-score(직전 60일 변동성 대비)
- **연도별 신호 발생 분포**: 특정 시기에 몰려 있는지 확인 가능해야 함
- **상위 기여 사건**: 결과 평균을 크게 좌우한 상위 3~5개 사건과 그 기여도

> z-score는 **판정 기준이 아니라 해석 보조용 참고 컬럼**이다. 이벤트 판정은 순위 기준으로만 한다.
