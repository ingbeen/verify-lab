> 작업하며 알아낸 것 중 **모르면 틀리는 것**을 모은다 — 함정 · 작업 규율 · 환경 노하우.
>
> 루트 `CLAUDE.md` 가 `@import` 로 불러오므로 **매 세션 자동으로 읽힌다.** git 으로 추적되어
> 다른 PC 에서도 그대로 보인다 — 그것이 하네스 메모리 대신 이 파일을 쓰는 이유다.
>
> **이미 루트 `CLAUDE.md`·전역 `~/.claude/CLAUDE.md`·`docs/` 문서가 담고 있는 것은 여기 쓰지 않는다.**
> 그쪽도 읽히므로 두 벌이 되고, 한쪽이 낡는다. 규칙은 현재형으로 쓰고 근거가 된 사건에
> `[실측] 날짜` 를 붙인다 (전역 `~/.claude/CLAUDE.md` 「문서」 절 · 2026-09-26 확정).

## 작업 방식

### 기대 이익을 «먼저 재고», 작으면 시스템을 짓지 않는다

규칙을 설계할 때는 **기대 이익의 크기를 먼저 재서 보여주고**, 작으면 정교한 자동화 대신 단순한 수동 방식을 택한다.
선택지는 여러 질문으로 묶기보다 **핵심 판단 하나로 좁혀 글로 제시**하는 편이 잘 맞는다.

### 공유 계층의 테스트는 «자기 픽스처»를 갖는다

공유 계층은 자기를 쓰는 쪽을 몰라야 하고(계층 계약) **그 계층의 테스트도 같다.** 테스트가 매매법의
`constants.py` 에서 값을 빌려 쓰면 그 매매법을 지우는 순간 공유 계층의 검사가 함께 무너진다 —
`[실측] 2026-09-22` 매매법 둘을 지우자 `measure/calendar_*` 의 테스트가 만기 규칙 값과 구간 표지를
지워진 매매법에서 가져오고 있어 함께 깨졌다. 값 자체는 매매법이 갖는 것이 맞고, **틀린 것은 테스트가 그 값을 빌려 쓴 것**이다.

**픽스처는 실제 쓰이는 값과 «다르게» 고른다.** 쓰는 쪽이 모두 셋째 금요일이면 그 값만 검사하게 되므로,
픽스처에 둘째 목요일을 두어 「셋째」와 「금요일」이 하드코딩돼도 걸리게 한다.

### 문서 절을 스크립트로 자를 때는 «코드 펜스»를 인식한다

다음 제목을 `^#{1,4} ` 로 찾으면 **코드블록 안의 `# 주석` 이 제목으로 잡혀** 절이 중간에 끊긴다 —
`[실측] 2026-09-22` `docs/COMMANDS.md` 에서 제목만 사라지고 본문 170여 줄이 남았고, 잘린 자리에서
**코드 펜스 짝이 깨져** 그다음 절단이 연쇄로 어긋났다.

**에러가 나지 않는다** — 마크다운은 무엇을 써도 저장된다. 판별은 **`문서.count("\\`\\`\\`") % 2 == 0`** 과
제목 목록 출력 둘로 한다. 절단 함수는 펜스 안을 제목 후보에서 빼고, 자른 뒤에는 이음매를 눈으로 본다.

### 이름만 바꾸는 변경과 값을 바꾸는 변경을 한 커밋에 섞지 않는다

**섞으면 diff 가 무엇을 말하는지 구별되지 않는다.** `storage/results/` 를 git 으로 추적하는 이유가
「재실행이 숫자를 바꿨는가」를 diff 로 아는 것인데(`src/verify_lab/CLAUDE.md` 「데이터 저장 규칙」),
한 커밋에 둘을 넣으면 그 신호가 죽는다. **파일 이름이 바뀌면 git 의 rename 탐지도 함께 깨진다** —
내용이 같아야 rename 으로 잡힌다. 그래서 **이름만 바꿔 재실행하고 바이트 대조로 값이 안 바뀐 것을
확인한 뒤** 값을 바꾸는 변경으로 넘어간다 `[실측] 2026-09-16`.

`summary.json` 은 대조에서 뺀다 — `row_counts` 의 키가 파일 이름이라 **이름 변경만으로
내용이 바뀐다.** 그것을 값 변화로 읽으면 대조가 매번 실패한다.

### 변형 확인은 바이트코드를 끄고 돌린다

테스트가 무엇을 잡는지 보려고 코드를 일부러 깨고(변형) 되돌릴 때, **파일 크기가 같은 변형을 같은 초 안에
되돌리면 파이썬이 변형 때의 `.pyc` 를 그대로 쓴다** — 캐시 무효화가 소스의 수정 시각(초)과 크기로만 판정하기
때문이다. 소스는 사본과 바이트가 같은데 테스트가 변형된 동작으로 실패해 원인을 코드에서 찾게 된다
`[실측] 2026-09-29` (`= 1` → `= 0` 변형 뒤 공개 지연 테스트가 「허용 지연 0일」로 실패).

변형 실행은 `PYTHONDONTWRITEBYTECODE=1` 로 돌리고, 이미 돌렸다면 그 모듈의 `__pycache__` 를 지운 뒤 다시 잰다.
**변형 문자열은 들여쓰기까지 맞춰 넣는다** — 블록 안의 줄을 바깥 들여쓰기로 바꾸면 문법 오류로 수집 단계에서 죽고,
`FAILED` 줄만 세면 「실패 없음」으로 읽혀 테스트가 약한 것처럼 보인다(같은 날 실측 — `ERROR` 줄도 센다).

### HTML 차트는 헤드리스 크롬으로 렌더링해 눈으로 본다

테스트는 차트의 **모양**을 보지 못한다 — 축이 깨져도 전부 통과한다. 만든 HTML 은 헤드리스 크롬으로 캡처해 이미지를 연다
(이 맥: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --window-size=1400,2400 --virtual-time-budget=10000 --screenshot=<png> "file://<html>"`).
테마 · 호버 상태가 필요하면 페이지가 주소 끝 표지(예: `#theme=light` · `#hover=18`)를 읽게 만들어 둔다.

- **plotly.js 로그 축에 도형(shape)을 두지 않는다** — 1배 기준선을 도형으로 그리자 축이 10⁻⁴⁸ 까지 늘어 선이 한 줄로
  눌렸고 **예외는 없었다** `[실측] 2026-09-30` (plotly 7.1.0 번들). 기준선은 trace 로 그리고 로그 축 범위를 명시한다
- **unified 호버는 가장 가까운 점을 문다** — 데이터가 먼저 끝난 계열의 마지막 값이 그 뒤 x 의 호버에 끼었다(같은 날).
  `hoverdistance` 를 좁혀 막는다. 프로그램으로 호버를 흉내 낸 캡처의 세로선 위치는 실제 마우스와 다를 수 있다
- **히트맵 호버를 프로그램으로 띄울 때는 좌표를 준다** — `Plotly.Fx.hover(gd, { xval, yval })` 는 뜨고, 칸 번호(`[{ curveNumber, pointNumber: [행, 열] }]`)는 **예외 없이 아무것도 띄우지 않았다** `[실측] 2026-09-30` (plotly 7.1.0 번들)

### 판단용 차트에는 설명 블록을 두지 않는다

차트 HTML 에는 제목 · 보기 제목 · 범례 · 축 · 호버 · 차트 안 라벨 · 표와 **데이터 기간 · 만든 시각 한 줄**만 둔다 — 머리 설명 · 「먼저 읽을 것」 ·
보기마다 부제 · 「무엇을 보나 / 주의」 같은 글을 넣지 않는다(2026-10-01 사용자 결정). **차트로 고르는 값(폭의 기간 · 회차 수 같은 매개변수)은
설명이 아니라 데이터라 제목 줄에 남긴다.** 데이터 기간 줄은 남긴다 — 실행 이력을 남기지 않는
차트에서 「어느 시세로 그렸나」를 말하는 자리가 그것뿐이다(`docs/검증/반감기_사이클/설계.md` 결정 ㊿ · 55).

## 인계사항

### 전역 Claude 설정을 저장소 경유로 나르지 않는다 (2026-09-12 결정)

`~/.claude` 를 이 저장소로 내보내고 받는 방식은 폐기했고 **다시 만들지 않는다.** 이유는 버그가 아니라
구조다 — PUBLIC 저장소를 경유하면 그 저장소가 **회사 데이터의 통로**가 되고, 반드시 옮겨야 하는 파일
(전역 `CLAUDE.md`·`settings.json`) 자체가 사내 정보를 담아 어떤 필터로도 막지 못한다.
하네스를 옮겨야 하면 **저장소를 경유하지 않는 방법**을 쓴다.

🔴 **설정을 통째로 덮으면 받는 PC 의 권한 가드가 조용히 사라진다** — `[실측] 2026-09-12` 서비스 계정 키가
든 폴더의 `ask` 가드가 그렇게 사라졌고 한참 뒤에야 발견했다. **가드가 사라져도 아무 신호가 없다.**

### 이 PC 의 하네스가 하는 일

- **하네스 메모리 쓰기가 차단된다**(`block-harness-memory-write.py`). 이 저장소에서 알아낸 것은
  하네스 메모리가 아니라 **이 문서**에 쓴다. **검증을 종료코드로 하지 않는다** — 이 훅은
  `permissionDecision: "deny"` 를 내면서 종료코드가 0 이라 코드만 보면 무동작과 구별되지 않는다
