## 1. 이 검증이 묻는 것

**비트코인 반감기(약 4년)마다 「3년 상승 · 1년 하락」이 되풀이되는가, 그리고 그 패턴으로 실제 매매가 가능한가.**
(2026-09-26 사용자 지시 — `사전조사.md` §1.1)

가격으로 먼저 패턴을 재고, 그 위에 보조지표 · 온체인 지표를 얹는다(같은 문서 §1.2).
**표본이 사이클 3 ~ 4개**라 어떤 측정도 통계적 증명이나 반증이 되지 못한다 — 나올 수 있는 최선은
「과거 몇 번은 이랬고, 아무 때나 산 것보다 이만큼 나았다(또는 아니었다)」이다.

### 1.1 단계 — 이어 갈 때는 여기서 시작한다

분석 순서는 사용자 지시(`사전조사.md` §1.2) 그대로 세 단계다. **결과가 「없음」인 가장 앞 단계가 다음에 잡을 단계**이고,
그 단계의 「시작 전에 정할 것」을 **사용자에게 먼저 묻는다** — 조사로 찾을 사실이 아니라 사용자의 결정이다.

| 단계 | 묻는 것 | 자료 | 결과 | 시작 전에 정할 것 |
| --- | --- | --- | --- | --- |
| 1 가격 패턴 | 반감기 뒤 몇 개월째에 들어가 몇 달 들면 어땠나 — 반감기 경과 격자 · 달력 연도 | `사전조사.md` §5.1 | `결과.md` | 없음 |
| 2 보조지표 · 온체인 | 1단계의 주기 위에 보조지표 · 온체인 지표를 얹으면 무엇이 더 보이나 | `사전조사.md` §3 · §6 · `도서.md` | 없음 | `사전조사.md` §2 질문 11(이동평균 · 평활 방식) · 12(MVRV-Z 표준편차의 기간) |
| 3 매매 | 어떤 식으로 매매할지 — 진입 · 청산 · 손절 · 분할매수 | `사전조사.md` §5.2 · §7.8 | 없음 — 이 폴더의 `규칙.md` 가 된다(`.claude/rules/trading.md`) | 질문 13(손절 · 분할매수) · `결과.md` 「한계」가 규칙 확정 전에 재라고 적은 하드포크 몫 |

- **2단계를 미리 정한 결정은 ⑧ 하나다**(온체인은 MVRV 계열만 데이터로 받는다). §2 의 나머지는 데이터와 1단계의 결정이다
- **`사전조사.md` §2 의 질문 가운데 답이 없는 것은 위 표의 셋뿐이다** — 나머지는 결정 ① ~ ⑥ · ⑧ · ⑳ 이 답했다.
  질문 9(라이트코인 교차 재현)는 결정 ⑳ 이 「1단계 결과 뒤로」 미룬 것이라 어느 단계에도 들지 않는다 — 1단계 결과가 있으면 잡을 수 있다
- 질문에 답하면 그 답을 §2 에 결정으로 더하고, **같은 수정에서 이 표의 그 칸을 지운다**

## 2. 확정된 설계 결정

### ① 주 계열은 Bitstamp, 보완 · 크로스체크 상대는 Coin Metrics

| **탈락안** | ① yfinance `BTC-USD` — 2014-09-17 부터라 2012 반감기 사이클을 못 재고, CoinMarketCap 집계값이다 ② CME CF BRR — 규제 벤치마크지만 2016-11 부터이고 하루 한 번 런던 16:00 값이라 UTC 일봉과 경계가 다르다 ③ FRED `CBBTCUSD` — 2014-12 부터 · 코인베이스 한 곳 · 사전 서면 허가 없는 복제 금지 |
| **근거** | 주 계열은 사용자 지시(2026-09-26)다 — 거래소 한 곳의 실제 체결가이고 OHLCV 를 준다. Coin Metrics 는 **2010-07 부터 끊김 없는 유일한 무료 계열**이고 날짜가 Bitstamp 와 **같은 UTC 하루**를 가리킨다(§4.4). 소스 비교의 원자료는 `사전조사.md` §4.2 · §4.3 |

### ② 크로스체크는 값을 바꾸지 않는다 — 허용폭을 넘은 날 목록만 남긴다

| | |
| --- | --- |
| **확정** | 같은 날 종가의 차이율 `Bitstamp ÷ Coin Metrics − 1` 을 재고, 절대값이 허용폭 5% 를 **넘는** 날 목록 · 연도별 요약 · 한쪽에만 있는 날 · 거래량 0 인 날을 보고한다. **어떤 값도 바꾸거나 빼지 않는다.** 수집할 때마다 돈다(`scripts/data/collect_btc.py`) |
| **탈락안** | ① 허용폭 하나를 넘는 날을 막거나 뺀다 ② 기간마다 다른 허용폭을 둔다 |
| **근거** | 사용자 결정(2026-09-29 · 사전조사 §2 질문 2). 2011 ~ 2013 에 5% 를 넘는 날이 105일이라(§4.3) **한 값으로 막으면 그 구간이 통째로 빠진다.** 허용폭은 목록의 범위만 정하므로 측정을 움직이지 않는다 — 5% 는 사전조사가 처음 잰 기준과 같다 |

### ③ 비트코인의 급등락 임계값은 공유 판정 함수의 인자로 넘긴다

| | |
| --- | --- |
| **확정** | `loader.validate_market_data` · `load_market_csv` 가 급등락 임계값을 **키워드 인자**로 받는다(기본값은 공용 값 그대로). 비트코인은 `data/crypto_common.CRYPTO_MAX_DAILY_CHANGE_RATE` = **0.75** 를 수집기와 로더 양쪽에 넘긴다 — 로더 쪽은 `crypto_common.load_crypto_market_csv` 하나가 넘긴다(결정 ⑮) |
| **탈락안** | ① **Bitstamp 를 2012-01-01 부터 저장한다** — 처음 추천했다가 뒤집었다(아래) ② 공용 임계값(0.50)을 그대로 쓴다 |
| **근거** | 공용 0.50 이면 **Bitstamp 2011-10-28 +56.1%** 가 막혀 전 기간을 저장할 수 없다(§4.1). ① 은 `src/verify_lab/CLAUDE.md` 「원시 시세 저장 규칙」의 **「받을 수 있는 전 기간. 잘라 저장하지 않는다」**와 부딪힌다 — 추천할 때 이 계약을 확인하지 못했고, 계획을 쓰며 찾아 사용자에게 다시 물었다(2026-09-29 (가) 확정). 0.75 는 실제로 있었던 가장 큰 변동(Bitstamp +56.1% · Coin Metrics +54.8%)보다 위이고 **자릿수 오류(×10 = +900% · ÷10 = −90%)는 여전히 걸린다.** 데이터 오류 판정값이지 측정 파라미터가 아니며, 값은 **자산군(암호화폐)의 수집 계층**이 갖는다 — 매매법의 값이 아니다. 기존 호출(판정 7곳 · 로더 15곳)은 기본값 그대로라 바뀌지 않는다 |

### ⑩ 「끝나지 않은 날」의 경계는 UTC 하루 — KST 09:00

| | |
| --- | --- |
| **확정** | 두 수집기가 **UTC 로 아직 끝나지 않은 날**의 행을 저장하지 않고 그 건수를 돌려준다. 시계는 `common_constants.KST` 에서 UTC 로 바꿔 쓴다. 판정은 `data/crypto_common.py` 하나가 갖는다 |

| **근거** | ① 은 빠진 날이 있어도 경고와 함께 **전체 파일을 덮는다** — 비트코인은 휴장이 없어 빠진 날은 곧 소스의 결함이고, 「빈 공간 없이 받는다」가 이 검증의 첫째 요구다(사용자 결정 2026-09-29). 지금 두 소스 모두 빠진 날 0 이라 막히는 실행이 없다 ② 는 중간이 빠진 이력을, 빠진 날 수만으로는 양 끝이 잘린 이력을 잡지 못한다 — 서버가 한 번에 주는 개수를 줄이거나 부하로 덜 준 페이지에서 멈추면 **앞부분만 남은 파일이 에러 없이 만들어진다**(2026-09-29 코드 리뷰 지적) ③ 이 그 경로다 ④ 는 리뷰 지적을 고치며 넣었다가 **실제 서버에서 끝나지 않아** 버렸다 — 시작이 마지막 봉보다 뒤면 Bitstamp 는 빈 목록이 아니라 최근 봉을 다시 준다(§4.1). Coin Metrics 의 1일은 공개 지연의 실측이다(§4.2) |

### ⑯ 진입 · 청산은 반감기일과 달력월로 정하고, 그날 종가에 사고판다

| | |
| --- | --- |
| **확정** | 진입 = 반감기일 + 진입 개월(달력월) 날의 종가, 청산 = 진입일 + 보유 개월(달력월) 날의 종가. 그 달에 같은 날이 없으면 말일이다. 목표일이 데이터 안인데 거래일에 없으면 **예외**를 낸다. 진입일이 데이터 뒤면 **행을 만들지 않고**, 청산일이 데이터 뒤면 **행을 남기고 제외 사유**를 단다 |
| **탈락안** | ① 다음날 시가 진입 ② 고정 일수 보유(91 · 182 · 365일) ③ 빠진 날을 앞뒤 날로 옮긴다 ④ 데이터 뒤의 진입도 제외 행으로 남긴다 |
| **근거** | 2026-09-29 대화에서 전제로 알렸고 이견이 없었다. ① 날짜가 달력으로 미리 정해져 판정이 필요 없어 종가 진입이 미래 참조가 아니고, 24시간 시장이라 그날 종가가 곧 다음날 00:00 UTC 값이다 — 중간선거_사이클과 같은 관용이다 ② 반감기 날(28 · 9 · 11 · 20일)은 어느 달에나 있어 신호 쪽은 어긋날 일이 없고, 기준선과 청산 규칙을 공유할 수 있다 ③ 휴장이 없어 빠진 날은 데이터의 빈틈이다 — 옮기면 다른 날을 잰다 ④ 아직 오지 않은 진입은 신호 자체가 없는 것이라, 제외로 세면 「신호 = 표본 + 제외」의 제외가 다른 뜻이 된다 |
