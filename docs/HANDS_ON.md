## 0. 왜 직접 대조하나

이 프로젝트의 전제는 **"집계값만 있고 원자료가 없는 보고는 미완성"** 입니다.
그래서 모든 결과에 신호일 전체 목록(날짜·가격·등락률)이 따라옵니다. 확인하라고 넣어 둔 것입니다.

대조에서 확인할 것은 세 가지입니다.

| 확인 | 무엇을 보나 |
| --- | --- |
| **① 신호일이 맞나** | 프로그램이 "이날이 역대급 폭락"이라 한 날이 차트에서도 실제로 폭락했나 |
| **② 숫자가 맞나** | 등락률·수익률을 내가 계산한 값과 프로그램 값이 같나 |
| **③ 해석이 맞나** | 그 숫자로 내린 결론이 과장되지 않았나 |

①②가 틀리면 코드 버그입니다. ①②가 맞는데 ③이 이상하면 해석 문제입니다. **순서대로 확인합니다.**

끝이 `verify-lab/.venv` 로 끝나야 정상입니다. 다른 경로가 나오면 [ROADMAP.md](ROADMAP.md) Phase 0 의
"`poetry run` 이 다른 가상환경을 잡는 경우" 를 봅니다.

**시세 파일 2개가 있어야 합니다.**

```
ls -la storage/market/
```

| 파일 | 무엇 |
| --- | --- |
| `QQQ_max.csv` | 미국 QQQ, **원본가** |

## 2. 1단계: 스크립트를 돌린다

```
poetry run python scripts/studies/run_index_extreme.py
```

**정확히 3분쯤 걸립니다** (실측: 10:49:57 시작 → 10:52:57 종료).
파라미터를 바꿔가며 **396가지 조합**을 전부 계산하기 때문입니다.

### ⚠️ 먼저 알아둘 것 — 화면이 로그로 뒤덮입니다

출력이 **약 2,000줄** 쏟아집니다. 이런 모양입니다.

```
2026-08-20 13:55:45.309 DEBUG [src/verify_lab/utils/formatting.py:211] [print_row] :     QQQ  원본가  6,903  ...
```

앞의 `날짜 DEBUG [파일:줄번호] [함수] :` 는 **전부 로그 접두사**입니다. 무시하고 뒤쪽만 보면 됩니다.

**그리고 표 3개는 맨 끝에 나옵니다.** 앞의 1,900줄은 진행 로그입니다.
스크롤을 끝까지 내리거나, 아예 파일로 받아서 뒤쪽만 보는 게 편합니다.

```
poetry run python scripts/studies/run_index_extreme.py > 결과.txt 2>&1
tail -100 결과.txt
```

### 화면에 나오는 것 ① — 검증 대상 시세

어떤 파일로 쟀는지 보여줍니다. 실제 출력입니다(로그 접두사 제거).

```
검증 대상 시세
  종목        가격기준      행 수  기간                      파일
--------------------------------------------------------------------------
  QQQ         원본가        6,903  1999-03-10 ~ 2026-08-18  QQQ_max.csv
  KODEX 200   원본가        5,881  2002-10-14 ~ 2026-08-11  069500_max.csv
```

**여기 행 수와 기간이 [결과 문서](research/RESEARCH_index_extreme_events.md) §3.1 과 같은지 먼저 봅니다.**
다르면 데이터를 다시 받은 것이고, 그러면 아래 모든 숫자가 조금씩 달라집니다.

#### 끝 날짜가 오늘이 아닌 것은 정상입니다

검증 스크립트는 **인터넷에 접속하지 않고** `storage/market/` 에 저장된 CSV 만 읽습니다.
게다가 수집할 때 **확정되지 않은 최근 며칠을 일부러 버립니다** — 미국 2일, 국내 1일
(`RECENT_EXCLUSION_DAYS`). 마감 직후 종가는 확정값이 아니고, 미확정 값이 남으면
**그날이 "역대급 폭락"으로 잘못 잡히기 때문**입니다.

| 파일 | 수집한 날 | 끝 날짜 | 계산 |
| --- | --- | --- | --- |
| `QQQ_max.csv` | 2026-08-20 | 2026-08-18 | 8/20 − 2일 = **8/18** |
| `069500_max.csv` | 2026-08-12 | 2026-08-11 | 8/12 − 1일 = **8/11** |

수집한 날은 `ls -l storage/market/` 의 파일 시각으로 확인합니다. 끝 날짜를 늘리려면 데이터를
다시 받아야 하고, **수집은 사용자가 직접 실행합니다**([COMMANDS.md](COMMANDS.md)).

> **대조 중에는 데이터를 갱신하지 마세요.** 기준값이 전부 미세하게 어긋나
> **"내가 틀린 건지 데이터가 바뀐 건지"를 구분할 수 없게 됩니다.** 검산이 끝난 뒤에 갱신합니다.

> **알려진 표시 문제:** 이 표의 헤더가 `행 수기간` 처럼 붙어 나옵니다(칸 폭 계산).
> 숫자에는 영향이 없습니다. 코드 수정은 계획서가 필요하므로 기록만 해 둡니다.

### 화면에 나오는 것 ② — 발췌 표

```
2011년 이후 · 종가 기준 1년 수익률 (전 조합은 CSV 참고)
  종목  가격기준  테스트  파라미터  방향  신호  사건  표본  평균(%)  중앙값(%)  승률(%)
```

**전체가 아니라 맛보기입니다.** 2011년 시작·종가 기준·1년 구간만 뽑은 것이고,
264개 조합 전부는 CSV 에 있습니다.

> **신호와 사건은 다릅니다.** 신호는 조건을 만족한 날 하나, 사건은 30일 안에 붙어 있는 신호를
> 한 덩어리로 묶은 것입니다. `신호 7건 = 사건 3개` 는 "7번 관측한 게 아니라 3번 관측한 것"이라는 뜻입니다.
> 이 표에 두 컬럼이 나란히 있는 이유입니다.

### 화면에 나오는 것 ③ — 산출물

```
산출물 (저장 폴더: .../storage/results/20260820_162937_index_extreme)

----------------------------------

맨 마지막 줄에 이렇게 나옵니다.

신호군 248개를 집계했습니다 (신호 0건이라 빠진 신호군 16개, 순열 검정 반복 1,000회·시드 0)
```

**264개 중 16개가 빠져 248개입니다.** 빠진 16개는 신호가 0건이라 집계할 게 없는 조합이고,
목록은 `summary.json` 에 남습니다. **조용히 사라지지 않게 하려고 적어 둡니다.**

**이 폴더 경로를 메모해 둡니다.** 다음 단계부터 계속 씁니다.

> 실행할 때마다 `storage/results/<실행시각>_index_extreme/` 폴더가 **새로 쌓입니다.**
> 덮어쓰지 않습니다 — 같은 검증을 여러 번 돌리는 게 전제라서, 나중에 어느 결과가 언제 것인지
> 알 수 있어야 하기 때문입니다.

### ✅ 재현성 확인 (실측)

2026-08-14 · 2026-08-18 · 2026-08-19 세 번의 실행에서 **CSV 4개가 바이트 단위로 완전히 같았습니다.**
`summary.json` 도 폴더 경로만 빼면 동일합니다. (당시는 QQQ 가 수정주가였고 지금은 원본가지만,
**"같은 데이터로 돌리면 같은 결과"라는 성질 자체는 그대로**입니다.)

```
signals.csv    : 완전 일치
statistics.csv : 완전 일치
excess.csv     : 완전 일치
test.csv       : 완전 일치
```

**직접 확인하는 법** — 실행 폴더 두 개를 골라 돌립니다.

```
md5 storage/results/<이전폴더>/signals.csv storage/results/<이후폴더>/signals.csv
```

두 줄의 값이 같으면 내용이 같습니다. (리눅스는 `md5sum`)

**같은 데이터로 돌리면 항상 같은 결과가 나옵니다.** 무작위를 쓰는 순열 검정도 시드가 0으로
고정돼 있어서입니다. 그래서 **다르게 나왔다면 데이터가 바뀐 것**이지 프로그램이 흔들린 게 아닙니다.

## 3. 2단계: 산출물 5개가 무엇인지 안다

방금 만들어진 폴더로 갑니다.

```
ls -la storage/results/
```

가장 최근(시각이 큰) `_index_extreme` 폴더 안에 5개가 있습니다.

| 파일 | 한 줄이 뜻하는 것 | 언제 보나 |
| --- | --- | --- |
| **`signals.csv`** | **신호일 하나** — 날짜·종가·등락률·당시 순위·사건 번호·z-score + 구간별 수익률 12칸 | **대조는 거의 여기서 합니다** |
| `statistics.csv` | 신호군 하나의 한 칸 — 평균·중앙값·승률·최고·최악·표준편차 | 집계값이 맞는지 볼 때 |
| `excess.csv` | 베이스라인 대비 초과분 (단위 %p) | "평소보다 나은가"를 볼 때 |
| `test.csv` | 순열 검정 결과 (p값) | "우연인가"를 볼 때 |
| `summary.json` | 파라미터 전체·시드·모집단 크기·신호 0건인 조합 목록 | 설정을 확인할 때 |

**CSV 는 엑셀에서 바로 열립니다.** `utf-8-sig` 로 저장돼 한글이 깨지지 않습니다.
폴더째 열려면 `open storage/results/<실행폴더>` 를 씁니다(macOS Finder).

> **터미널 화면은 미리보기입니다.** 화면의 발췌 표는 신호군 375개 중 66개(2011년 이후·종가 기준·
> 1년)뿐이고 신호일 목록은 아예 없습니다. **8단계 중 터미널을 쓰는 것은 1단계뿐이고 나머지는
> 전부 엑셀 작업**입니다. 실행 화면을 놓쳐도 잃는 것이 없습니다 — 결과는 폴더에 그대로 있습니다.

### 원하는 조합만 걸러 보는 법

네 파일 모두 **앞에 식별 컬럼 7개**가 있습니다. 엑셀에서 필터를 걸면 됩니다.

```
종목 | 가격기준 | 테스트 | 파라미터 | 시작연도 | 방향 | 시대 구간
```

⚠️ **헷갈리기 쉬운 이름 두 개**

- **`구간`** = 측정 구간 (1일·1주·1개월·3개월·6개월·1년)
- **`시대 구간`** = 2010년대 / 2020년대 / 전체

한 표에 두 축이 함께 들어 있어 이름을 나눠 뒀습니다.

## 4. 3단계: 신호일이 진짜 그날인가 (차트 대조)

**가장 먼저, 가장 쉽게 할 수 있는 확인입니다.**

`signals.csv` 를 열고 엑셀 필터로 이렇게 거릅니다.

```
종목        = QQQ
테스트      = 테스트 A(역대급 등락)
파라미터    = K=10
시작연도    = 2003
시대 구간   = 전체
```

**7줄이 나와야 합니다.** 이게 QQQ 의 "역대급 등락" 신호 전부입니다.

| 방향 | 날짜 | 종가 | 등락률 | 당시 순위 |
| --- | --- | --- | --- | --- |
| 폭락 | 2008-09-29 | 37.82 | -7.94% | 6위 |
| 폭등 | 2008-10-13 | 35.13 | +12.16% | 3위 |
| 폭락 | 2008-10-15 | 30.6 | -8.96% | 1위 |
| 폭등 | 2008-10-28 | 31.86 | +11.05% | 5위 |
| 폭락 | 2020-03-12 | 177.32 | -9.17% | 1위 |
| 폭락 | 2020-03-16 | 169.3 | -11.98% | 1위 |
| 폭등 | 2025-04-09 | 466.0 | +12.00% | 4위 |

### 확인 방법

증권사 앱이나 야후 파이낸스에서 **QQQ 일봉 차트**를 열고 위 날짜를 찾아봅니다.

- **2008년 9~10월** — 리먼 브라더스 파산 직후입니다. 폭락과 폭등이 번갈아 나옵니다
- **2020년 3월** — 코로나 급락입니다
- **2025년 4월 9일** — 관세 발표 관련 급등입니다

**이 세 시기 말고 다른 날에 신호가 있으면 이상한 것입니다.**

> **종가가 차트와 그대로 맞아야 합니다.** 두 종목 모두 **원본가**(배당·분배 미조정)입니다.
> 보통의 차트도 배당 미포함이라 숫자가 일치합니다. **어긋나면 그게 발견입니다.**

#### 끝자리가 짧은 것은 정상입니다

`466.0`·`169.3`·`30.6` 처럼 **끝자리 0이 붙지 않습니다.** 가격은 **소수점 4자리까지만** 저장하고,
그 안에서 필요 없는 0은 적지 않기 때문입니다.

2026-08-20 이전에는 `169.300003`·`177.320007` 처럼 꼬리가 붙어 있었습니다. 그것은 실제 시세가
아니라 **데이터를 소수로 담을 때 생기는 표현 잡음**이었고, 차트에는 존재하지 않는 자리였습니다.
자릿수를 4자리로 줄여 잘라 냈으며, **등락률·수익률·신호 판정은 하나도 바뀌지 않았습니다**
(근거는 [spec/index_extreme_events.md](spec/index_extreme_events.md) §8 "가격 자릿수 4자리 전환").

#### 종가가 차트와 다르면 — "조정 때문인가, 오류인가" 가리는 법

원본가로 바꾸기 전에는 QQQ 가 수정주가라 차트와 달랐고, 그 차이를 가리는 절차가 필요했습니다.
지금은 맞아야 정상이지만, **다른 자료(수정주가 차트, 배당 재투자 기준 자료)와 비교할 때는 다시 벌어집니다.**
그때 쓰는 방법입니다.

**하루만 보면 알 수 없습니다.** 조정 차이라면 **근처 모든 날에 같은 배율**이 걸립니다.
하루만 어긋나면 데이터 오류입니다.

1. 다른 자료의 종가 ÷ 파일 종가 = **배율**을 구한다
2. 그 배율을 **다른 날 파일 종가에 곱해** 얼마로 나와야 하는지 예측한다
3. 실제로 그 날을 확인한다

**실측 예 (2026-08-19).** 당시 수정주가 파일에서 2020-03-12 는 170.699097 이었고 차트는 177.32 로
**배율 1.038787** 이었습니다. 그 배율로 예측한 2020-03-13 **192.34**, 03-16 **169.3**, 03-17 **182.14** 가
차트와 전부 일치해 배당 조정임이 확인됐습니다. **지금은 파일이 곧 그 값입니다.**

배율이 분자와 분모에 똑같이 걸리므로 **등락률은 어느 기준이든 같습니다.** 실제로 원본가로 전환한 뒤에도
**테스트 A 신호 7건의 날짜·등락률·사건 번호가 하나도 바뀌지 않았습니다.**

> **⚠️ 배율은 항상 같지 않습니다.** 배당을 지급할 때마다 바뀝니다. 그래서 **수익률 계산은
> `QQQ_max.csv` 안에서만 하세요.** 두 자료의 가격을 섞으면 어긋난 값이 오차인지 배당인지 구분할 수 없습니다.

### 국내도 같은 방식으로

```
종목        = KODEX 200
가격기준    = 원본가
테스트      = 테스트 A(역대급 등락)
파라미터    = K=10
시작연도    = 2011
시대 구간   = 전체
```

**27줄이 나옵니다.** 그중 **18줄이 2026년**입니다.
국내 종가는 **원본가**(분배금 미조정)라 실제 호가와 같습니다. 차트 숫자와 그대로 맞아야 합니다.

## 5. 4단계: 등락률을 손으로 계산한다

여기서부터 **숫자가 맞는지**를 봅니다. 계산기만 있으면 됩니다.

### 등락률 공식

```
등락률 = (오늘 종가 − 어제 종가) ÷ 어제 종가 × 100
```

### 직접 해보기 — 2020-03-16 (QQQ, 폭락 1위)

`storage/market/QQQ_max.csv` 를 엑셀로 열고 2020-03-16 근처를 찾습니다.
엑셀 이름 상자(왼쪽 위)에 **`A5290`** 을 치면 바로 그 줄로 갑니다.

| 엑셀 행 | 날짜 | 시가(Open) | 종가(Close) |
| --- | --- | --- | --- |
| 5289 | 2020-03-13 | 187.07 | **192.34** |
| **5290** | **2020-03-16** | 174.15 | **169.3** |
| 5291 | 2020-03-17 | **175.47** | 182.14 |

> 행 번호는 현재 `QQQ_max.csv`(6,903행, 1999-03-10 시작) 기준입니다. 재수집하면 뒤에 행이
> 붙을 뿐이라 앞쪽 번호는 그대로지만, **시작일이 달라지면 전부 밀립니다.**

```
(169.3 − 192.34) ÷ 192.34 × 100 = -11.98%
```

`signals.csv` 의 `등락률(%)` 컬럼이 **-11.98** 이면 맞습니다.

> **직전 거래일과 비교합니다.** 3월 14~15일은 주말이라 데이터에 없습니다.
> 달력 날짜가 아니라 **파일에 있는 바로 윗줄**과 비교하는 게 맞습니다.

## 6. 5단계: 수익률을 손으로 계산한다

**"신호 다음에 무슨 일이 있었나"가 이 검증의 전부입니다.** 그 숫자를 직접 만들어 봅니다.

### 두 가지 기준이 있습니다

| 기준 | 언제 샀다고 보나 | 왜 둘 다 재나 |
| --- | --- | --- |
| **종가 기준** | 신호일 **종가**에 샀다 | 이론값. 실제로는 종가를 알고 나서 그 종가에 살 수 없습니다 |
| **익일 시가 기준** | **다음 날 아침 시가**에 샀다 | **실제로 집행 가능한 값** |

**둘의 차이가 "갭으로 새는 몫"** 입니다. 나가는 시점(파는 날 종가)은 똑같고 들어가는 값만 다릅니다.

### 측정 구간은 달력이 아니라 거래일입니다

| 이름 | 거래일 |
| --- | --- |
| 1일 | 1 |
| 1주 | 5 |
| 1개월 | 21 |
| 3개월 | 63 |
| 6개월 | 126 |
| 1년 | 252 |

> **"1개월 = 21거래일"이지 "한 달 뒤 같은 날짜"가 아닙니다.** 엑셀에서 셀 것은
> **아래로 21칸**입니다. 휴장일이 껴도 항상 21칸입니다.

### 직접 해보기 — 2020-03-16 의 1개월 수익률

`QQQ_max.csv` 에서 2020-03-16 줄부터 **아래로 21칸** 내려갑니다.

| | 엑셀 행 | 날짜 | 시가 | 종가 |
| --- | --- | --- | --- | --- |
| 신호일 | 5290 | 2020-03-16 | 174.15 | **169.3** |
| 다음 날 | 5291 | 2020-03-17 | **175.47** | 182.14 |
| 21칸 뒤 | **5311** | 2020-04-15 | 208.48 | **209.43** |

**종가 기준**

```
(209.43 − 169.3) ÷ 169.3 × 100 = +23.70%
```

**익일 시가 기준**

```
(209.43 − 175.47) ÷ 175.47 × 100 = +19.35%
```

`signals.csv` 의 `종가 1개월` 이 **23.70**, `익일시가 1개월` 이 **19.35** 이면 맞습니다.

**차이 -4.35%p 가 갭으로 샌 몫입니다.** 폭락 다음 날 아침에 이미 올라 있어서 그렇습니다.
"종가에 살 수 있었다면"과 "실제로 살 수 있는 값"의 차이가 이만큼입니다.

### 1년도 해보기

2020-03-16 에서 아래로 **252칸** → **5542행**, 2021-03-16, 종가 320.58.

```
(320.58 − 169.3) ÷ 169.3 × 100 = +89.36%
```

`종가 1년` 이 **89.36** 이면 맞습니다.

### 빈칸(`미완`)이 보이면

국내 2026년 신호를 보면 뒤쪽 칸이 비어 있습니다. **버그가 아닙니다.**
아직 1년이 안 지나 잴 수가 없는 것이고, 그 사실을 감추지 않고 빈칸으로 두었습니다.
**몇 건이 왜 빠졌는지는 `statistics.csv` 의 `제외` 컬럼에 숫자로 있습니다.**

> 빈칸을 0으로 채우면 "수익률 0%"로 읽힙니다. 그래서 비워 둡니다.

## 7. 6단계: "사건 묶기"가 맞는가

**이 검증에서 가장 중요한 개념입니다.** 여기서 결론이 갈립니다.

`signals.csv` 의 QQQ 7줄에서 `사건 번호` 컬럼을 봅니다.

| 날짜 | 사건 번호 |
| --- | --- |
| 2008-09-29 | 1 |
| 2008-10-13 | 1 |
| 2008-10-15 | 1 |
| 2008-10-28 | 1 |
| 2020-03-12 | 2 |
| 2020-03-16 | 2 |
| 2025-04-09 | 3 |

### 규칙: 앞 신호와 30일(달력) 이내면 같은 사건

직접 세어 봅니다.

- 09-29 → 10-13 은 **14일** → 같은 사건
- 10-13 → 10-15 는 **2일** → 같은 사건
- 10-15 → 10-28 은 **13일** → 같은 사건
- 10-28 → 2020-03-12 는 **11년** → 새 사건
- 03-12 → 03-16 은 **4일** → 같은 사건
- 03-16 → 2025-04-09 는 **5년** → 새 사건

**앞 신호와 재는 것**이지 사건 시작일과 재는 게 아닙니다.
그래서 2008년 사건은 9/29 ~ 10/28 로 **29일에 걸쳐 있어도 한 사건**입니다.

### 왜 이게 중요한가

**신호 7건은 서로 다른 7번의 관측이 아닙니다. 3번의 관측입니다.**

"1년 뒤 7건 전부 플러스, 승률 100%" 라는 말은 사실 **"금융위기·코로나·관세쇼크 세 번 다
결국 반등했다"** 는 뜻입니다. 반등하지 않은 사건이 하나만 섞여도 승률은 67%로 떨어집니다.

**표에서 `신호` 와 `사건` 두 컬럼을 항상 같이 보세요.**

## 8. 7단계: 베이스라인과 초과분이 맞는가

"수익률 +44%" 만으로는 좋은지 알 수 없습니다. **평소와 비교해야** 합니다.

### 베이스라인 3종

| 이름 | 무엇과 비교하나 | 답하는 질문 |
| --- | --- | --- |
| **단순 보유** | 같은 기간 **아무 날이나** 샀을 때 | 평소보다 나은가 |
| **조건부** | 200일 이동평균 **아래**인 날만 | 하락장 안에서도 특별한가 |
| **무작위 진입** | 같은 개수만큼 무작위로 뽑기를 1,000번 | 운이 아닌가 |

### 직접 확인하는 법

`excess.csv` 에서 QQQ · K=10 · 2003 · 폭락 · 1년 · 종가 · 단순 보유를 거릅니다.
`평균 초과(%p)` 가 **+38.67** 입니다.

`statistics.csv` 에서 같은 조합의 `평균(%)` 은 **+54.90** 입니다.

```
베이스라인 평균 = 54.90 − 38.67 = 16.23%
```

**즉 "같은 기간 QQQ를 아무 날이나 샀으면 1년 뒤 평균 +16.23%"** 라는 뜻입니다.
신호일에 샀으면 +54.90% 였으니 +38.67%p 더 벌었습니다.

> 이 조합의 신호는 **4건(사건 2개)** 입니다. 7건은 폭등까지 합친 수이고, 여기서는 `방향 = 폭락` 만 걸렀습니다.

> **초과분은 "통계량끼리 뺀 값"입니다.** 신호일과 베이스라인 날짜가 달라서 1:1로 뺄 수가 없습니다.
> 그래서 `중앙값 초과` 는 **중앙값끼리의 차이**이지 "차이들의 중앙값"이 아닙니다.

### ⚠️ 여기서 반드시 볼 것 — 승률의 함정

같은 방식으로 `승률 초과(%p)` 도 볼 수 있습니다. 그런데 **베이스라인 승률 자체가 이미 높습니다.**

**QQQ 는 아무 날이나 사도 1년 뒤 플러스일 확률이 85.82%** 입니다.
(`승률(%)` 100.0 − `승률 초과(%p)` 14.18 로 역산한 값입니다.)

그러면 신호 7건이 전부 플러스인 게 얼마나 특별할까요? 계산기로 해보세요.

```
0.8582 × 0.8582 × ... (7번) = 0.343  →  34.3%
```

**세 번에 한 번은 그냥 일어납니다.** 사건 3개로 세면 0.8582³ = **63.2%** 입니다.

승률 100%가 특별하다는 뜻이 전혀 아닙니다. **원래 오르는 자산에서 7일을 뽑았을 뿐입니다.**

## 9. 8단계: "검정 불가"는 버그가 아니다

`test.csv` 를 열고 QQQ · 테스트 A 를 거르면 `p값` 이 **전부 비어 있고** `비고` 에
"표본 부족으로 검정 불가" 가 적혀 있습니다.

**의도된 동작입니다.** 규칙은 이렇습니다.

> 유효 표본이 **10건 미만이면 검정하지 않고 사유를 남긴다.**

QQQ 신호는 7건(사건 3개)이라 이 선에 걸립니다. 표본이 한 자릿수인데 p값을 만들어내면
**없는 확신을 주는 숫자**가 됩니다. 그래서 만들지 않습니다.

**"검정 불가"가 결론의 일부입니다** — "역대급 폭락은 통계를 낼 만큼 자주 오지 않는다".

### 반대로 표본이 충분한 곳은

테스트 B(연속 등락)는 신호가 수백 건이라 검정이 정상 동작합니다. 그래서 결론이 나옵니다 —
**"우연과 구별되지 않는다."**

`test.csv` 에서 QQQ · 테스트 B · 단순 보유를 거르고 `p값 < 0.05` 인 줄을 세어 보세요.
**검정된 714칸 중 31칸**입니다. 비율로 **4.3%** 입니다.

> **아무 관계가 없어도 5%는 유의하게 나옵니다.** 714 × 5% = 36 인데 실제로는 31칸입니다.
> **기대치보다 오히려 적습니다.** 그래서 개별 칸의 p값 하나를 뽑아 "유의했다"고 말하면 안 됩니다.

> `모집단` 컬럼이 베이스라인 이름(`단순 보유`·`조건부 SMA200`·`조건부 EMA200`)을 담습니다.
