## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**이자가 그리드 매매 자체보다 크다.** 착수 전 실측(G3-1 곡선의 실제 잔고 × 사양서 §11.2 모델,
이자일수 −1 미적용이라 상한값):

| 항목 | 세전 | 현재 총수익(23,285,506원) 대비 |
| --- | --- | --- |
| 원화 파킹 이자 | 37,407,722원 | 1.61배 |
| 달러 RP 이자 | 10,823,278원 | 0.46배 |
| **합계 (세후 15.4%)** | **40,803,426원** | **1.75배** |

**투입률이 평균 36.7% 라 파킹이 RP 의 3.5배**다. 사양서 §17.1 이 "이 전략은 매매 전략이라기보다
이자 받으며 대기하다가 가끔 줍는 구조" 라고 적은 것이 그대로 나타난다.
**붙이는 순간 곡선의 성격이 통째로 달라진다.**

**RP 금리의 절반은 T-bill 이 아니라 모델 하한이 정한다.** 5,340 거래일 중 **2,605일(48.8%)** 이
하한 0.40% 에 걸린다. 사양서 §12 의 RP 하한 축(0.10 / 0.40 / 0.70%)이 그만큼 중요한 견고성
검사이며, 파킹 하한은 306일(5.7%)만 걸린다.

| **이자일수 −1 이 look-ahead 를 부른다** | 매도일을 보지 않고 **처리 순서**로 푼다. 순서를 테스트로 고정하고 look-ahead 감시 테스트를 함께 건다 |
| **이자 도입이 기존 결과를 바꾼다** | 이자율이 0이면 G3-1 곡선이 그대로 복원되는 테스트를 Phase 0 에 둔다 |
| **미인출 이자가 항등식에서 새어 나간다** | 총자산 항등식에 미인출 이자를 명시적으로 넣고 매일 검사한다. 새면 `RuntimeError` 로 즉시 중단한다 |

## 8) 메모(Notes)

### 이자일수 −1 을 처리 순서로 푸는 증명

**문제**: 「이자일수 = 보유일수 − 1」은 매도일을 알아야 계산되는데, 일별로 반영하려면
그날 시점에 미래를 봐야 한다. 그러면 look-ahead 다.

**해법**: 하루 처리 순서를 **이자 → 매도 → 평가 → 배분 → 매수** 로 두고,
거래일 D에서 보유 중인 슬롯에 **`[전거래일, D)` 구간 중 매수일을 뺀 날 수**만큼 얹는다.

- 매수는 이자 **이후**에 일어나므로 매수 당일에는 이자가 없다
- 매도는 이자 **이후**에 일어나므로 매도 당일에도 `[전거래일, D)` 만 받는다 (당일 미포함)
- 합계 = `|[매수일, 매도일) \ {매수일}|` = **`(매도일 − 매수일).days − 1`**

사양서 §9.1 의 표와 맞는다 — 보유 1일 → 0일, 5일 → 4일, 30일 → 29일.
**주말이 껴도 성립한다.** 달력일로 세므로 금요일 매수 → 다음 주 월요일 매도면
`3 − 1 = 2일`이고, 구간 합도 `|{금, 토, 일} \ {금}| = 2일`이다.
