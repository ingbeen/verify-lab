## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**① 매매 계층이 검증 계층을 따라가지 못했다.**

| 날짜 | 무슨 일 |
| --- | --- |
| 2026-09-06 | 코스닥만 검증 → 손절 격자를 **코스닥 4대상**으로 만듦 |
| 2026-09-09 | 검증에 코스피 4대상 추가 → **4·6월 재현 실패, 11월이 새로 나옴** |
| 지금 | 매매 격자는 여전히 코스닥뿐이라 **코스피 11월의 손절 성적을 볼 수 없다** |

`scripts/strategy/run_month_end_trading.py` 의 `_selected_datasets()` 가 `DATASETS_KOSDAQ` 을
하드코딩하고 있다. `DATASETS_KOSPI` 는 `studies/month_end/constants.py` 에 **이미 있고**
`run_month_end_trading()` 은 `datasets` 를 인자로 받으므로, 막고 있는 것은 CLI 한 곳이다.

**② 「2000년 이전 시장은 다르다」를 재볼 수단이 없다.**

지수를 넣어 30~46년 축을 얻었지만, 그 앞 구간은 외환위기·가격제한폭 확대 이전이라
사용자가 유효성을 의심하고 있다. 지금 스크립트의 인자는 `--ticker`·`--repeats`·`--seed` 뿐이라
**구간을 좁혀 대조할 방법이 없다.**

걸리는 표본은 대상마다 다르다 — 코스닥 종합 362건 중 42건(11.6%)이지만
**코스피 종합은 560건 중 240건(42.9%)** 이다.

**③ 분배락 판정에 조용한 구멍이 있다 (2026-09-12 실측).**

`check_month_end_dividend.py` 는 진입일·청산일이 수정주가 파일에 **있는지**만 보고,
그 값이 실제로 조정됐는지는 보지 않는다. 그래서 **최근 조정이 누락된 구간이
「확인 불가」가 아니라 「분배락 없음」으로 집계된다.**

실측: KODEX 코스닥150 의 2026-04-29 분배(₩28, 지급 2026-05-06)가 웹 공시에는 있는데
`229200_adjusted_max.csv`(2026-09-04 수집)에는 계단이 없다. 2022~2025는 역산 금액이
공시와 맞는다(70.3/49.4/19.8/40.1원 대 ₩70/₩50/₩20/₩44).
