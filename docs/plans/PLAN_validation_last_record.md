## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

검사 3이 Validation 절 안의 **모든** 기록을 검사한다. 그래서 아래가 차단된다.

```
- [x] 1차 `validate_project.py` (passed=100, failed=2, skipped=0) — 수정 후 재실행
- [x] `validate_project.py` (passed=102, failed=0, skipped=0)
```

**고정 규칙(수정 금지)이 「실패하면 즉시 수정 후 재검증한다」를 규정**하므로 이 두 줄은 규약이 시키는
모양이다. 지금은 **실패 기록을 지워야 Done 이 된다.**

**이건 불편이 아니라 «검사가 뜻하지 않는 것을 주장»하는 문제다.**
코드는 「기록된 모든 실행이 초록」을 검사하는데, Done 이 주장하는 것은 **「마지막 검증이 초록」**이다.

### 실측 (2026-09-10)

| 잰 것 | 결과 |
| --- | --- |
| Validation 절 안 기록이 **여러 줄**인 Done 계획서 | **0건 / 25건** |
| 실패 후 재검증 두 줄 | **차단됨** (고쳐야 할 것) |
| 마지막 실행이 실패한 두 줄 | **차단됨** (고친 뒤에도 유지해야 할 것) |

**0건이라 급하지 않다.** 다만 고치는 비용이 몇 줄이고, 고쳐도 **구멍이 새로 생기지 않는다** —
역방향이 그대로 막히는 것을 위에서 확인했다.

## 8) 메모(Notes)

### 🔴 이 계획은 «채택되지 않았다» — 구현 후 되돌렸다 (2026-09-10, 사용자 승인)

「마지막 기록으로 판정」을 구현했더니 **게이트가 열리는 쪽으로 틀렸다.** §2 비목표에
「마지막 실행이 실패했는데 앞의 기록으로 통과하는 일은 없어야 한다」고 못 박았는데,
**다른 경로로 정확히 그 일이 일어났다.**

```
- [x] `validate_project.py` (passed=100, failed=2, skipped=0)
- [x] 참고: 지난 릴리스의 `validate_project.py` 는 failed=0, skipped=0 이었다
```

뒷줄은 실행 기록이 아니라 **메모**인데, `VALIDATION_LINE` 이 「그 이름이 든 체크박스 줄」을 전부
기록으로 보므로 그것이 «마지막»이 되어 판정을 가져간다. **실측: 통과했다.** 되돌리기 전에는 막혔다.

같은 뿌리에서 셋이 더 나왔다 — 절 안의 후속 항목이 마지막 기록으로 잡혀 **초록인 계획서가 막히고**,
한 줄에 이력을 적으면 `failed=` 를 앞에서부터 찾아 **막히고**, 「마지막」이 파일 전체 기준이라
**마지막 Phase 가 아닌 Phase 의 기록으로 통과**했다.

**원인은 `VALIDATION_LINE` 이 「기록」을 정의하지 못한다는 것이다.** 전부를 판정할 때는 그 느슨함이
**안전한 쪽**으로 작동했는데(하나라도 나쁘면 막음), 마지막 하나만 보게 바꾸며 **위험한 쪽**으로 뒤집혔다.

그리고 **실측이 말한 0/25건을 가볍게 넘긴 대가**다 — 한 번도 일어난 적 없는 상황을 위해
게이트의 핵심 판정부를 손댔다.
