## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

#### ① 시기 항목이 보합을 「내림」으로 센다 (실증 완료)

`src/verify_lab/measure/screening.py:197` 이 시기별 적중률을 이렇게 만든다.

```python
[float(1.0 - value if downward else value) for value in cell_periods[COL_WIN_RATE]]
```

그런데 **같은 함수의 전체 축은 `:188` 에서 `COL_LOSS_RATE` 를 직접 쓴다.** 한 함수 안에서
같은 개념을 두 방식으로 계산하고 있으며, 이는 `src/verify_lab/CLAUDE.md` 「측정 계층의 절대 원칙 5
— 판정식 단일화」 위반이다.

`measure/statistics.py:189-191` 이 바로 이 방식을 금지하고 있다.

> 하락 비율은 **승률의 여집합이 아니다.** 보합(정확히 0)이 어느 쪽에도 들어가지 않으므로
> `1 − 승률` 로 만들면 보합이 하락으로 새어 들어가 값이 부푼다.

**실증 결과** (보합 20%인 시기 칸):

| 값 | 결과 |
| --- | --- |
| 실제 내린 비율 (`COL_LOSS_RATE`) | 0.50 |
| `screening` 이 쓴 값 (`1 − WinRate`) | **0.70** |
| 시기 하한 0.55 판정 | 실제는 **미충족**인데 쓰인 값은 **충족** |

즉 **등급이 관대해지는 방향으로 틀린다.** 「아래」 방향 칸에서만 발생하며, 보합이 0인 칸에서는
두 값이 우연히 일치해 눈으로 발견되지 않는다.

`halves` 프레임에는 `COL_LOSS_RATE` 가 이미 들어 있다 — `option_expiry/runner.py:478`
`_aggregate_month_halves` 가 `summarize()` 결과를 merge 하기 때문이다. **쓸 수 있는데 안 쓰고 있다.**

#### ② 「모든 매매법은 총자산 곡선을 낸다」는 계약이 성립하지 않는 매매법이 있다

`.claude/rules/strategy.md:89` · `src/verify_lab/CLAUDE.md:51-53` · `docs/ROADMAP.md:531-532` 가
**"모든 매매법은 일별 총자산 곡선을 낸다"** 를 공통 계약으로 규정한다. 그런데:

- `strategy/performance.py` 의 `evaluate_curve` 는 **프로덕션 호출이 0건**이다 (테스트 24회 참조뿐)
- `strategy/runner.py` 의 `run_strategy` 는 곡선을 만들지 않는다
- 곡선이 필요한 유일한 매매법이던 그리드는 2026-08-30 경량화에서 삭제됐다

**역방향 매매의 시장 노출 비율을 실측했다.**

| 대상 | 전체 거래일 | 노출일 | 노출 비율 |
| --- | --- | --- | --- |
| KODEX 200 K=10 (D+3) | 4,599 | 56 | **1.22%** |
| QQQ K=20 (D+3) | 4,691 | 18 | **0.38%** |
| QQQ K=10 (D+1~3) | 4,691 | 7 | **0.15%** |

자본이 **99% 이상의 기간 놀고 있다.** 이 상태로 곡선 지표를 내면 셋 다 거짓이 된다.

- **CAGR** — 44일 성적을 18년으로 연환산해 "매년 그만큼 벌었다"로 읽힌다
- **MDD** — 실제로는 44일 안의 낙폭인데 18년 최대낙폭으로 보고된다
- **Sharpe** — 4,599일 중 4,555일의 수익률이 0이라 **분모(변동성)가 무너져 구조적으로 부풀려진다.**
  `performance.py:16-18` 이 `rf=0` 에 대해 경고한 것과 **같은 왜곡이 노출 비율에서 다시 발생**한다

`docs/spec/usdkrw_grid.md` 결정 B2 가 이미 같은 판단을 기록해 뒀다 — "역방향 매매는 '매 신호 같은 금액
투입' 가정이라 자본 성장 모델이 없고, CAGR·MDD 가 정의되지 않는다."

**사용자 결정 (2026-08-30)**: 곡선은 **꼭 필요한 곳만** 낸다. 지금 필요한 매매법이 0개이므로
`performance.py` 를 삭제하고, 필요해지면 git 이력에서 꺼낸다 (그리드 6,042줄을 지울 때 쓴 것과 같은 논리).
