## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

- 측정의 원칙 14 가 「원본가 하나만 쓴다」(근거: 사용자가 차트와 대조)인데, 9개월 보유인 중간선거_사이클은 **분기 배당 3회가 매번** 빠져 성적이 과소평가된다.
  그래서 배당락 세 컬럼을 따로 냈다. 사용자가 「긴 보유의 매매법이 많아진다 — 수정주가로 고치자」로 정했다(2026-10-06)
- **중간선거의 시세 읽기는 한 자리로 모인다** — `runner.load_dataset(dataset)` 이 `Dataset.path`(= `directory / file_template`)를 읽고, 체결(`trading.py:935`)도 같은 함수를 쓴다.
  배당락 측정(`runner._dividend_row`)만 수정주가 파일을 따로 읽는다. 그래서 **`DATASETS` 의 ETF 셋의 `file_template` 을 `ADJUSTED_FILE_TEMPLATE` 로 바꾸면 측정 · 체결 · 분할매수 · 분기 · 진입 위치가 함께 넘어간다**
- **테스트 픽스처는 자기 `Dataset` 을 만든다**(`file_template=MARKET_FILE_TEMPLATE` 합성 파일) — 실제 `DATASETS` 를 바꿔도 기존 테스트는 깨지지 않는다. 그래서 **실제 `DATASETS` 의 템플릿을 고정하는 불변조건 테스트가 따로 필요하다**(Phase 2)
- **`dividend_impact` 의 운영 호출처는 중간선거 한 곳**(`runner.py:403`)이다. `dividend_adjustment` · `measure_distribution_share` 는 레버리지_ETF_괴리 · 선물_대_레버리지_ETF 가 쓴다
- **반감기 결정 ㊲ 의 근거가 「원본가 한 기준(측정의 원칙 14)이라 성적에 더하지 않는다 — 배당락과 같은 취급」**이다. 원칙을 바꾸면 근거가 사라진다.
  새 근거는 반감기 `결과.md` 가 이미 갖는 사실 — 「Bitstamp 는 BCH 를 지급했고 거래는 2017-12 에 열렸다 · BTG 지급은 확인하지 못했다 [미확인]」 — 위에 선다.
  출력 설명 `trading.NOTE_FORK`(「원본가에 없어 … 넣지 않는다」)가 `summary.json` 에 실려 **반감기 산출물은 그 한 줄만 바뀐다**
