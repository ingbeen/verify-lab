## 1) 목표(Goal)

사용자 결정(2026-10-06 · 10-07): **매매·검증 등급은 수정주가 하나로 잰다. 신호 판정도 수정주가이고, 원본 종가 대조 칸은 두지 않는다.
조사 등급은 잰 당시 기준의 기록으로 둔다.** 동기는 「앞으로 중간선거 사이클처럼 긴 보유의 매매법이 많아진다」 —
보유가 길수록 원본가가 놓치는 분배금이 커진다.

- [ ] 목표 1: 중간선거_사이클이 **수정주가 파일**로 측정 · 체결 · 분할매수 격자를 낸다. 반감기는 BTC 라 가격이 그대로다
- [ ] 목표 2: 배당락 장치(중간선거 `측정.csv` 의 배당락 세 컬럼 · `dividend_impact` · trading.md 「확정 전 필수 항목」 절)를 걷어내고, 수정주가의 한계(재투자 가정 · 원천징수 · 재수집 때마다 과거 값 변경 · 국내 3,000거래일)를 규칙으로 남긴다
- [ ] 목표 3: 산출물 diff 가 **두 커밋으로 갈린다** — 1단계는 재수집으로 인한 «기간 변화»만, 2단계는 «기준 변화»만 (`docs/MEMORY.md` 「섞지 않는다」)
- [ ] 목표 4: 확정 규칙의 성적(`규칙.md` §2.5 — QLD 2배)을 수정주가로 다시 재고, 중간선거 문서 셋과 원칙 14 · 관련 규칙 문서가 새 기준을 말한다

## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

- 측정의 원칙 14 가 「원본가 하나만 쓴다」(근거: 사용자가 차트와 대조)인데, 9개월 보유인 중간선거_사이클은 **분기 배당 3회가 매번** 빠져 성적이 과소평가된다.
  그래서 배당락 세 컬럼을 따로 냈다. 사용자가 「긴 보유의 매매법이 많아진다 — 수정주가로 고치자」로 정했다(2026-10-06)
- **중간선거의 시세 읽기는 한 자리로 모인다** — `runner.load_dataset(dataset)` 이 `Dataset.path`(= `directory / file_template`)를 읽고, 체결(`trading.py:935`)도 같은 함수를 쓴다.
  배당락 측정(`runner._dividend_row`)만 수정주가 파일을 따로 읽는다. 그래서 **`DATASETS` 의 ETF 셋의 `file_template` 을 `ADJUSTED_FILE_TEMPLATE` 로 바꾸면 측정 · 체결 · 분할매수 · 분기 · 진입 위치가 함께 넘어간다**
- **테스트 픽스처는 자기 `Dataset` 을 만든다**(`file_template=MARKET_FILE_TEMPLATE` 합성 파일) — 실제 `DATASETS` 를 바꿔도 기존 테스트는 깨지지 않는다. 그래서 **실제 `DATASETS` 의 템플릿을 고정하는 불변조건 테스트가 따로 필요하다**(Phase 2)
- **`dividend_impact` 의 운영 호출처는 중간선거 한 곳**(`runner.py:403`)이다. `dividend_adjustment` · `measure_distribution_share` 는 레버리지_ETF_괴리 · 선물_대_레버리지_ETF 가 쓴다
- **반감기 결정 ㊲ 의 근거가 「원본가 한 기준(측정의 원칙 14)이라 성적에 더하지 않는다 — 배당락과 같은 취급」**이다. 원칙을 바꾸면 근거가 사라진다.
  새 근거는 반감기 `결과.md` 가 이미 갖는 사실 — 「Bitstamp 는 BCH 를 지급했고 거래는 2017-12 에 열렸다 · BTG 지급은 확인하지 못했다 [미확인]」 — 위에 선다.
  출력 설명 `trading.NOTE_FORK`(「원본가에 없어 … 넣지 않는다」)가 `summary.json` 에 실려 **반감기 산출물은 그 한 줄만 바뀐다**

## 7) 리스크(Risks)

- **원본가 재수집이 과거 값을 바꾼다** — yfinance 원본가는 분할 조정이라 그 사이 분할이 있었으면 과거 행이 바뀐다. 레버리지_ETF_괴리의 입력이기도 하다.
  완화: Phase 1 에서 겹치는 구간의 변경 행을 세고, 0 이 아니면 멈춰 보고한다
- **수정주가는 받을 때마다 전 행이 바뀐다** — 앞으로 재수집마다 시세 파일 diff 가 전 행이고, 문서의 수치도 그때마다 움직인다(새 분배금이 과거 구간을 다시 조정한다).
  완화: 원칙 14 에 한계로 적는다. 산출물 diff 의 신호는 그대로 「재실행이 숫자를 바꿨는가」다
- **4자리 반올림 잡음** — 레버리지 상품의 옛 수정주가가 1달러 아래(QLD 0.2992 · TQQQ 0.1801)라 체결 수익률에 0.03% 안쪽의 잡음. 표시가 2자리라 끝자리가 흔들릴 수 있다.
  받아들인다 — 가격 4자리는 전역 규칙이고, 크기가 회당 성적보다 세 자리 작다
- **재수집이 중간에 실패한다** — yfinance 요청 20회 중 일부만 성공하면 파일마다 기간이 달라진 채 Phase 1 이 진행된다.
  완화: 실패한 것은 다시 받고, 20파일의 종료일이 종목 간에 맞는지(미국 같은 날 · 지수 같은 날) 대조를 통과하기 전에는 재실행하지 않는다
- **커밋 경계를 넘기면 diff 가 섞인다** — Phase 1 뒤 사용자 커밋 없이 Phase 2 로 가면 기간 변화와 기준 변화가 한 diff 가 된다.
  완화: Phase 1 끝에서 멈추고, Phase 2 착수 전 `git log` 로 커밋을 확인한다
- **손으로 잰 §2.5 가 틀린다** — 스크래치 계산이라 테스트가 없다.
  완화: 같은 스크립트로 1배를 다시 계산해 산출물 거래내역과 전 건 일치를 단언한다(지난 측정과 같은 검산)

- **배당락 컬럼 삭제가 `측정.csv` 스키마를 바꾼다** — 계약 테스트 · 판단용 차트가 그 컬럼을 기대하면 깨진다.
