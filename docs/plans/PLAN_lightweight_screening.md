## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**① 결과를 찾는 데 문서 611줄을 지나야 한다.**
`docs/research/옵션_만기일.md` 는 879줄이고, 「어느 달이 어느 방향인가」는 12A.4 표에 있다.
§1 결론 요약에는 "만기월 축의 그림이 달라졌다"는 서술만 있고 **구체적인 월과 방향이 없다.**

**② 판정 기준이 코드에 없다.**
루트 `CLAUDE.md` 「후보 판정 기준」의 네 조건(기준선 대비 ±10%p · 적중률 60% · 우연확률 0.05 · 시기 55%)을
코드에서 찾으면 **0건**이다. 2026-08-29 작업에서 판정은 전부 스크래치 스크립트로 했고 산출물에 남지 않았다.
15개 CSV 중 후보만 뽑은 표가 없어 사람이 48행에서 직접 걸러야 한다. **측정의 원칙 8(사용자가 직접 검증할 수 있어야 한다)에 미달이다.**

**③ 끝난 트랙이 저장소의 46% 를 차지한다.**

| 대상 | 줄 수 | 상태 |
| --- | ---: | --- |
| `src/verify_lab/strategy/grid/` (18개) | 6,042 | 그리드 채택 거부 (2026-08-27) |
| `tests/test_strategy_grid_*.py` (13개) | 7,910 | 위와 같음 |
| `scripts/strategy/run_usdkrw_grid*.py` (2개) | 892 | 위와 같음 |
| **합계 (코드만)** | **14,844** | 저장소 40,398줄의 **37%** |

**`strategy/` 를 통째로 지우면 안 된다.** 두 트랙이 한 폴더에 섞여 있다 —
`grid/` 는 기각됐지만 최상위의 `runner.py`·`reverse_trading.py`·`constants.py`·`performance.py`
**928줄은 현재 운용 중인 역방향 매매**의 구현이다. 실측으로 확인했다:
**역방향 코드가 `grid` 를 참조하는 곳은 0곳**이라 경계가 깨끗하게 갈린다.

**④ 검증 #7 의 부차 축은 결론이 이미 났다.**
offset 격자·월중 서수·가격기준 대조·휴장 4조합·국면×위칭은 "우위 없음"과 "규칙이 결론을 만들지 않았다"를
확인하는 데 쓰였고 **그 결과가 문서에 표로 남아 있다.** 코드를 유지해도 같은 답만 다시 나온다.

**⑤ 규칙끼리 충돌한다.**
루트 `CLAUDE.md` 는 "공통 계층을 미리 일반화하지 않는다"고만 적었고 **언제 해야 하는지가 없다.**
그런데 측정의 원칙 11·12·13 은 방향 판정과 축 분해를 **모든 검증에 강제**한다.
원칙이 강제하는 것을 검증마다 새로 구현하면 구현이 갈라져 **같은 원칙이 다른 답을 낸다.**

**⑥ 우연확률이 읽히지 않는다.**
사용자가 "1,000번 중 158번이면 좋은 것 아닌가"라고 물었다. 지금 문서는 그 숫자가
**무작위 뽑기가 기준선에서 멀어진 횟수**임을 밝히지 않아, 내 신호가 잘한 횟수로 읽힌다.
