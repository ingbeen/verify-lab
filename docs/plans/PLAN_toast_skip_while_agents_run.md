백그라운드 에이전트가 끝날 때마다 메인 세션이 깨어나 「(대기 중 — 남은 감사 4건)」 같은 한 줄을 쓰고 멈춘다.

### 판정 규칙

1. **도는 중인 에이전트** = 시작 기록은 있고, **전달된 완료 통지**도 **강제 종료**도 없는 에이전트. 단, **살아 있다고 볼 근거가 있을 때만** 센다 — 서브에이전트 기록 파일의 수정 시각(파일이 없으면 시작 시각)이 **30분 안**이어야 한다
2. 도는 중인 에이전트가 있으면 → 건너뛴다
3. 기록을 못 읽거나 형식이 달라 예외가 나면 → **알린다** (지금과 같은 동작)

**복귀 보고와 대기열 기록을 완료로 치지 않는 이유 — 이것이 중복 알림을 막는다.**
에이전트는 메인을 두 번 깨운다(복귀 보고 → 완료 통지). 복귀 보고를 완료로 치면 마지막 에이전트의 두 번 모두에서 「도는 것 0」이 되어 **알림이 두 번** 뜬다.
전달된 완료 통지만 완료로 치면 한 번이 된다.

- 최종 보고 턴이 길면 통지가 **턴 도중에 첨부로** 전달된다 → 그 턴의 `Stop` 에서 알린다 (`908f1c29` 가 이 경우)
- 최종 보고 턴이 짧으면 그 `Stop` 시점엔 아직 통지 전이다 → 건너뛰고, 몇 초 뒤 **통지로 열린 턴**에서 알린다

대기열 기록은 전달보다 **먼저** 남는 경우가 있다(에이전트 `af62…` — 대기열 기록이 복귀 보고보다 앞섰고, 전달은 복귀 보고 뒤였다). 대기열 기록을 완료로 치면 위 두 번 알림이 그 경우에 되살아난다.

**30분의 근거**: 서브에이전트는 도구를 부를 때마다 자기 기록에 쓴다. 기록이 가장 오래 멈추는 경우는 Bash 한 번의 최대 타임아웃(10분)과 긴 사고 시간이다. 30분은 그 위에 여유를 둔 값이다.
**이 장치가 막는 것**: 에이전트가 돌던 중에 세션을 닫고 이어 열면(resume) 에이전트는 죽었지만 완료 통지가 기록에 없다. 장치가 없으면 **그 세션의 알림이 영원히 꺼지고, 에러도 나지 않는다.**
**값이 틀렸을 때의 방향**: 너무 짧으면 중간 알림이 되살아난다(지금과 같은 동작, 무해). 너무 길면 이어 연 세션에서 그 시간만큼 알림이 꺼진다.

### 재설계 A1 — `Stop` 입력의 `background_tasks` 로 판정 (2026-09-26 17:08 사용자 승인)

2회차 리뷰의 설계 지적(그 외 1)을 받아들였다. 세션 기록을 뒤져 하네스 상태를 짜 맞추던 판정을 걷어내고, 하네스가 `Stop` 순간에 싣는 백그라운드 작업 목록을 그대로 쓴다. 경쟁·기록 지연·통지 파싱이 원천적으로 사라지므로 2회차 버그 5건은 코드와 함께 없어진다.

- **필드가 없는 버전**: 빈 목록으로 보고 지금처럼 알린다
- **목표 3(죽은 에이전트)**: 목록은 하네스의 작업 등록부에서 `running`/`pending` 만 싣고, 이어 연 세션은 새 프로세스라 이전 작업이 없다 — 시간 상한이 필요 없다
