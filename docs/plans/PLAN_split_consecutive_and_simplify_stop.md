## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**⑴ 연속 등락은 우연 수준인데 코드와 문서의 대부분을 차지한다.**
역방향 전체에서 검정된 1,368칸 중 우연확률 0.05 미만이 35칸(**2.6%**)으로 우연 기대치 5%보다도 낮다.
이미 매매 대상에서 제외됐는데(`역방향_매매_규칙.md` 결정 ⑭), 코드는 연속 일수 8개 × 시작연도 4개 ×
방향 3개를 매 실행 돌고 있고 산출물의 대부분이 테스트 B다. 결과 문서 1,017행에서도 §7·§8 전체와
§9.4·§10.2·§10.3·§11.4·§12·§14·§15 에 흩어져 있어, **역대급 등락을 읽으려면 연속 등락을 함께 읽어야 한다.**

**⑵ 매매 규칙의 복잡성이 성적에 기여하지 않는다.** 2026-08-30 실측(15가지 손절 방식 × 한도 3종 × 대상 3종):

| 발견 | 실측 |
| --- | --- |
| 손절선 -4% 아래는 매매법을 무너뜨린다 | KODEX 200 D+1 적중률이 -2%·-3%에서 **56.82%** 로 60% 기준 미달, 평균도 +0.79~0.94%로 반토막 |
| -4% 이상은 어디를 잡아도 같다 | 평균이 **+1.27 ~ +1.46%** 범위에 전부 들어가고 무손절(+1.31%)도 그 안 |
| 타이트할수록 손절선이 안 지켜진다 | 갭손절이 -2% 7건, -3% 4건, -4% 2건, **-5% 이상 0건** (D+1·D+2 기준) |
| 3분할이 단일 -5%보다 낫지 않다 | 3분할 D+2 `+1.55% / 72.73% / 최악 -5.30%` vs 단일 -5% D+2 `+1.57% / 75.00% / 최악 -5.00%` |
| D+3은 근거가 없다 | 3일 구간 평균 우연확률 **0.2917**(KODEX K=10). 갭손절도 D+3에서만 새로 생긴다 |

**⑶ 손절 대원칙과 세금 판단 기준이 어디에도 없다.** 사용자의 매매 대원칙은 "손절은 반드시 있다"인데
규칙 문서에 그 원칙이 없어 다음 매매 규칙에서 다시 논의하게 된다. 배당·세금도 어디까지 계산에 넣고
어디부터 사용자가 판단하는지의 경계가 없다.

### 승인된 규칙 이탈 1건 (2026-08-30 사용자 승인)

**연속 등락 문서에 신호일 전체 목록 대신 신호군 요약을 넣는다.**

`docs/research/CLAUDE.md` 는 "집계값만 있고 원자료가 없는 문서는 미완성"이라며 신호일 전체 목록을
요구하고, 건수가 많으면 CSV 경로를 명시하라고 한다. **이번에는 둘 다 지킬 수 없다.**

- 테스트 B 신호는 신호군 하나당 수백 건이고 신호군이 수백 개다. 본문에 실을 수 없다
- CSV 는 `storage/results/` 에 있는데 **git 제외라 다른 PC 에 없고 주기적으로 지워진다**
- **코드를 제거하면 재생성도 불가능하다** — 이것이 결정적이다

대신 아래 셋을 싣는다. **개별 신호일은 없어도 "무엇을 몇 건 쟀는가"는 남는다.**

| 싣는 것 | 무엇에 답하나 |
| --- | --- |
| **신호군 요약표** (종목 × N × 방향별 신호 수·사건 수) | 어떤 신호군을 쟀고 각각 표본이 얼마였나 |
| **연도별 분포** | 신호가 특정 시기에 몰렸나 |
| 원자료가 없는 이유와 되살리는 방법(git 이력) | 왜 대조할 수 없나 |

결론이 "우연 수준"이라 개별 신호일을 차트로 대조할 실익이 낮다는 점도 함께 적는다.
