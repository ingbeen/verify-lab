## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**A — 코드 리뷰가 절차에 없다.**
`plan_lint.py` 가 Done 조건으로 검사하는 것은 `validate_project.py` 의 `failed=0`·`skipped=0` 뿐이다.
품질 검증은 **린트·타입·테스트**를 보지만 **설계 결함과 논리 오류는 보지 않는다.**
`/code-review` 는 자체 컨텍스트를 가진 서브에이전트로 돌아 **내 가정을 물려받지 않은 눈**으로 diff를 읽는데,
지금은 이것이 절차 어디에도 없어 **내가 기억할 때만** 실행된다.

**C — 조사리포트가 「무엇을 못 봤는지」를 대부분 적지 않는다.**
`acme-docs/조사리포트/` 최상위 19건 + 디렉터리형 8건 = 27건을 전수 조사한 결과다.

| 절 | 27건 중 |
| --- | --- |
| 「확인하지 못한 것 / 미해결 / 한계」 | **6건** |
| 「조사 방법 / 쿼리」 | 5건 |
| 둘 다 | **1건** |

그 절이 없으면 리포트를 받는 사람은 **무엇을 확인 못 했는지 모른 채 결론만** 가져간다.
좋은 리포트의 모양은 이미 존재하지만(`INPD-1347_주소검증_폴백결함_원인분석.md` 는 둘 다 있다)

**설계 결정**

| 결정 | 내용 | 근거 |

| 범위 인자 | **생략** | 계획서 완료 시점에만 커밋하므로, 그때의 미커밋 diff = 그 계획서의 변경 그 자체다 |
