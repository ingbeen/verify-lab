## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**사용자가 매매법을 재검토하며 성적표 기준으로 범위를 좁혀 나간다.** 그런데 판정과 성적이 두 파일로 갈려 있어 대조가 끊긴다.

**① 판정과 집행이 다른 조건이다 (실측).** 판정표는 맨몸(무손절), 성적표는 손절 격자다. 확정 손절선 −5% 로 게이트를 다시 걸면 **96칸 중 3칸이 갈린다.**

| 칸 | 무손절 승률 / 평균 | −5% 승률 / 평균 |
| --- | ---: | ---: |
| DIA 7월 위 | 62.07% / **+0.18%** | 58.62% / **−0.17%** |
| KODEX 200 12월 위 | 62.50% / **+0.05%** | 58.33% / **−0.24%** |
| QQQ 3월 위 | 60.71% / +0.68% | 53.57% / +0.15% |

앞의 둘은 **기대값 부호까지 뒤집힌다.** 한 표에 있으면 그 자리에서 보인다.

**② 두 표는 맨몸에서 이미 완전히 일치한다 (실측).** 판정표 금요일 후보 27칸 ↔ 성적표 무손절·전체 게이트 통과 27칸, **불일치 0건.** 즉 판정표는 성적표의 한 행에 컬럼 하나를 더한 것과 같다.

**③ 방향 선택은 게이트가 자동으로 한다.** 오른 비율 + 내린 비율 ≤ 100% 이므로 **위·아래 두 행 중 게이트를 넘는 것은 최대 하나**다. `screening.py` docstring 이 이미 그렇게 적고 있다 — 판정표의 「방향 결정」은 별도 기능이 아니다.

**④ 판정표에만 있던 축은 옵션 만기일의 청산 요일 하나뿐이고, 그건 성적표에 넣으면 된다.** 목요일 청산에 후보가 5칸 있는데 **그 칸의 체결 성적이 지금 어디에도 없다** — 통합과 무관하게 이미 있는 구멍이다.

**⑤ 안 덮이는 판정표 둘도 값은 전부 남는다 (실측 대조).**

| 지울 표 | 복원처 | 대조 |
| --- | --- | ---: |
| 월말 `grid_candidates.csv` (616행) | `grid.csv` (616행 · 43컬럼) | 누락 0 · 값 불일치 0 |
| 역방향 `1차_판정.csv` (576행) | `통계.csv` (576행 · 같은 7축) | 누락 0 · 값 불일치 0 |

`적중률 = 오른/내린 비율`, `방향 기대값 = ±평균` 으로 그 자리에서 다시 계산된다. **사용자 결정: 그 두 표는 축과 결론을 문서화한 뒤 없앤다.**

**⑥ 월말 `execution.csv` 도 `1차 판정` 컬럼을 갖고 있다** (48행 = 시장 2 × 집행 2 × 월 12). 그중 24행(아래 집행 = 인버스)은 원래부터 전부 「판정 안 함」이다. **컬럼만 빼면 「판정은 성적표에만」이 지켜지고 잃는 판정이 0건이다.**
