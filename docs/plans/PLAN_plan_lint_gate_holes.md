## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

직전 계획서(`/code-review` 게이트)의 코드 리뷰에서 드러났고, **이 환경에서 직접 재현했다.**

**결함 2 — 게이트가 «조용히» 꺼진다.** `is_done()` 이 상태 줄과 **바이트 단위로 완전 일치**할 때만 참이다.
위반이 2건 나와야 하는 본문에 상태 줄만 바꿔 넣은 실측:

| 상태 줄 | `is_done` | 위반 |
| --- | --- | --- |
| `**상태**: ✅ Done` | True | **2건** |
| `**상태**: ✅ Done (2026-09-10 완료)` | False | **0건** |
| `✅` 뒤에 변이선택자 `U+FE0F` | False | **0건** |
| `**상태**: Done` | False | **0건** |
| 콜론 뒤 공백 하나 더 | False | **0건** |

**검사 2·3·4가 전부 `is_done` 안쪽**이라 이것 하나로 게이트 전체가 무음이 된다.
변이선택자는 **화면에서 구분되지 않는다** — 이 결함을 재현하는 스크립트를 쓰면서
작성자가 그 문자를 두 번 연속 무의식적으로 입력했고, 이모지 훅이 잡아줘서야 알았다.

**결함 1 — 품질 검증 검사가 양쪽으로 샌다.** 실측:

| 입력 | 위반 |
| --- | --- |
| Validation 줄이 **아예 없는** Done 계획서 | **0건** (통과) |
| 템플릿 DoD 의 **설명 문구**만 있는 Done 계획서 | **0건** (통과) |
| 자리표시자(`passed=\_\_`)가 그대로인 줄 | 1건 (잡힘) |

구멍이 둘이다. ① `for line in VALIDATION_LINE.findall(text)` 는 줄이 없으면 **0번 돌고 끝난다** —
「없으면 위반」이라는 판정이 코드에 없다. ② 템플릿 DoD 의 `(failed=0, skipped=0; …)` 은
**「이렇게 적어라」는 안내**인데 `FAILED_COUNT` 가 이를 **실측 결과로 읽는다.**

**결함 3 — 파일을 통째로 다시 쓸 수 없다.** `plan_lint.py` 48행·68행에 이모지 리터럴이 있어
`block-emoji-in-code.py` 가 전체 Write 를 `deny` 한다(자기 자신의 내용으로 실측 확인).
`Edit` 로 일부만 고치는 것은 통과하므로 **리팩토링하려는 순간에만 벽이 나타난다.**

### Phase 1 — `plan_lint.py` 를 고친다 (그린)

세 결함이 한 파일 한 문맥이라 함께 처리한다. **순서가 있다** — `is_done` 이 바뀌면 나머지 검사의
발동 조건이 달라지므로 그것부터다.

**설계 결정**

| 결함 | 결정 | 근거 |
| --- | --- | --- |
| **2** | 상태 줄에서 **변이선택자를 제거하고 공백을 정규화**한 뒤 판정한다 | 화면에서 구분되지 않는 문자로 게이트가 꺼지는 것을 막는다 |
| **2** | **선택지 줄 = `/` 를 포함하고 상태 표기를 2개 이상 담은 줄.** 그 외에 `Done` 이 들어 있으면 Done | 「Draft 가 들어 있으면 제외」로 하면 `✅ Done (Draft 에서 승격)` 같은 줄에서 **게이트가 꺼지는 쪽으로** 틀린다. 오판은 **켜지는 쪽**으로 나야 안전하다 |
| **1** | 검사 3에 **「Validation 줄이 하나도 없으면 위반」**을 추가 | 판정이 코드에 아예 없던 것을 채운다 |
| **1** | 템플릿 DoD 줄에서 **명령 이름과 숫자를 함께 뺀다** | 이름만 빼면 숫자가 남아 다른 줄과 섞이고, 숫자만 빼면 이름이 남아 「존재」 검사를 만족시킨다 |
| **3** | `STATUS_DONE` 을 `\N{...}` 이스케이프로, docstring 의 이모지는 **글로 풀어쓴다** | 파일에서 리터럴이 사라지고 런타임 값은 그대로다 |

**작업 내용**:

- [x] `is_done()` 재설계 — 정규화 + 선택지 줄 배제
- [x] 검사 3에 존재 요구 추가
- [x] `STATUS_DONE` 이모지를 이스케이프로 교체 (`\N{WHITE HEAVY CHECK MARK}`)
- [x] `is_done()` docstring 의 이모지를 글로 풀어쓴다

**Validation**:

- [x] Phase 0 스크립트의 **결함 1·2·3 항목이 전부 통과**로 바뀐다 — **20/20 통과**
- [x] `plan_lint.py` 전문을 이모지 훅에 넣어 **`deny` 가 아님**을 확인한다

> **변이선택자는 코드에도 못 쓴다.** 이 상수를 넣으면서 `U+FE0F` 를 리터럴로 세 번 연속 입력했고
> 매번 이모지 훅이 잡았다. 보이지 않아서 넣은 줄도 몰랐다 — 결국 `chr(0xFE0E) + chr(0xFE0F)` 로 적었다.
> **이 결함이 왜 위험한지를 작성 과정이 그대로 보여줬다.**
