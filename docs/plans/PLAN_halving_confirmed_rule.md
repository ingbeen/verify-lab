### 설계 (사용자가 고른 것을 코드로 옮기는 방법)

| 무엇 | 어떻게 |
| --- | --- |
| 이름 붙은 손절 | `execution/constants` 에 **이름을 받아 `손절선(%)` 값으로 돌려주는 함수**를 둔다. 이름은 매매법이 넘기고(반감기는 `STOP_METHOD_LOW_BREAK`) 공통 계층은 형식만 검사한다 — 빈 이름 · `무손절` · `손절불가` · 숫자로 읽히는 글자는 `ValueError`. **기존 `stop_level_value` 의 시그니처는 그대로 둔다** — 중간선거 산출물이 바뀌지 않는다 |
| 거래내역 여덟 칸 | `trade_rows` 의 핵심을 **진입일 · 진입가 · 청산일을 직접 받는 함수**로 떼고 `trade_columns` 는 시세에서 그 셋을 읽어 그것을 부른다. 형식과 청산가 되돌리기의 소유자는 그대로 하나다. 분할 포지션은 평균 매수가 × (1 + 수익률) = 평균 매도가로 돌아온다 |
| 포지션 성적을 체결 조립에 넘기기 | `split_rule` 이 손절 표를 만들기 전의 **포지션 × 손절 방식 결과(`PositionResult` 둘 · 하드포크 몫 · 이탈 여부)**를 `CalendarSplitGrid` 에 함께 돌려준다. `_stop_rows` 와 체결 조립이 같은 결과를 쓴다 — 산식을 다시 쓰지 않는다(절대 원칙 5). `trading.py` 는 `calendar_split_grid` 를 측정과 같은 인자로 부른다 |
| 성적표 · 거래내역 축 | 종목 다음에 **`매매 방식`** — 격자 행 「일시」, 확정 규칙 행은 폭 이름(「월말 분할」). 확정 규칙 행의 `반감기 뒤 진입(개월)` · `반감기 뒤 청산(개월)` 은 **첫 회차**(27 · 9 — `CalendarSplit.first_deadlines`) |
| 확정 규칙 행 | 폭 × 손절 방식 2 × 시기 5. `손절선(%)` 은 `무손절` · `저점 이탈`. 끝난 포지션만 체결이고, 끝나지 않은 포지션(2024)은 거래내역에 없고 요약의 대상 기록에 제외 건수로 남는다(표본 보존). `1차 판정` 은 `시기 = 전체` 행 · `tradable = dataset.is_judged` 그대로 |
| 확정 규칙의 거래내역 한 줄 | 진입일 = 첫 매수일 · 진입가 = 평균 매수가 · 청산일 = 마지막 매도일(이탈했으면 손절 매도일) · 보유일 = 포지션 보유 날 수 · 청산가 = 평균 매도가 · 수익률 = 포지션 수익률 · **보유 중 최악 = 평균 단가 대비 최악**(결정 ㊻) · 청산 사유 = `기한청산` 또는 `저점 이탈` · 하드포크 몫 = 손절 표의 그것. 회차 원자료는 `달력분할회차.csv` 가 갖는다 |
| % 손절 격자 | `STOP_LEVELS` 를 지우고 격자는 무손절 한 종으로 돈다. 요약의 `stop_levels` 는 성적표에 실제로 나온 값(`무손절` · `저점 이탈`) 그대로다 |
