## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

- **국내 데이터가 없다.** 검증 #1은 QQQ와 KODEX 200 **둘 다 본검증 대상**인데(스펙 §2)

- **두 소스가 서로 다른 것을 하나씩 못 준다.** 스펙 §8의 실측 결론이다
  - `get_etf_ohlcv_by_date`: 상장일부터 전 기간(5,881행)을 한 번에 주지만 **분배락이 조정돼 있지 않다.**
    매년 4월 27~29일에 기초지수 대비 -1.4 ~ -2.6%p 의 인위적 하락이 남아 있다
  - `get_market_ohlcv(adjusted=True)`: 분배락을 조정하지만 **한 번에 3,000행까지만** 오며,
    상장일이 아니라 2014-05-21부터 시작한다
- **스펙 §2가 "수익률 계산은 수정주가 기준"을 확정**했으므로 후자가 필요한데, 전 기간을 덮으려면

- 미조정 원본가를 쓰면 **1년 forward return 이 연 약 1.5%p 과소 계상**된다(스펙 §8 결론 1·2).

## 7) 리스크(Risks)

- **이어붙이기가 성립하지 않을 위험** — 세그먼트마다 수정계수가 다르면 이음매에서 가격 축이 끊긴다.
  완화책은 **먼저 재는 것**이다(Phase 0). 실패하면 B/C 로 되돌아오며, 그것도 유효한 결론이다
- **재수집 때마다 과거 가격이 전부 바뀔 위험** — 수정계수가 조회 시점 기준이라 A안에서는 재수집이
  파일 전체를 바꾼다. 이미 낸 측정 결과와 대조가 안 될 수 있으므로 **데이터 기준일을 결과 문서에 반드시 남긴다**
- **uint32 언더플로우** — 부호 없는 정수의 차분에서 하락일이 40억 근처 양수가 된다.
  `float64` 변환 누락은 **예외가 아니라 그럴듯한 숫자**로 나타나므로 눈으로 발견되지 않는다. 테스트로 고정한다
- **3,000행 상한이 조회 시점·서버 사정에 따라 달라질 위험** — 수집기가 상한값을 상수로 가정하지 않고
  **실제 반환된 행과 날짜로 판단**하게 만든다
- **2026년 신호의 forward return 미완결** — 스펙 §8 §9-5 가 이미 지적한 사항이다. 수집 문제는 아니지만
  국내 결과 해석에서 반드시 함께 보고해야 한다
- **로그에 KRX 로그인 ID 가 찍힘** — pykrx 가 표준 출력에 찍는다(비밀번호는 아니다).
  실행 로그를 문서에 붙일 때 그 줄을 뺀다
