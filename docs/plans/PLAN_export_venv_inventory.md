## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

**2026-09-09 mac → WSL 마이그레이션에서 도구 두 개가 죽은 채로 넘어왔다.**
`tools/xlsx` 는 폴더째 오지 않았고, `tools/pptx` 는 스크립트만 오고 인터프리터가 없었다.
사람이 두 PC 를 오가며 손으로 조사해야 겨우 복구됐다.

원인은 `venv` 가 `DENY_SEGMENTS` 에 있어서가 아니다 — **그 제외를 받는 쪽이 알아챌 방법이 없어서**다.

`export.py:131-132` 의 안내문은 이미 「venv 만 든 폴더는 폴더째 사라진다」를 적고 있고,
이어서 **「무엇을 재생성해야 하는지는 `settings.json` 의 `Bash(/...)` 권한 규칙이 가리키는
절대경로가 말해준다」** 고 안내한다. **이 문장이 이번에 틀렸다.**

| 폴더 상태 | 권한 규칙으로 잡히나 | 온 스크립트의 import 로 잡히나 | 실물 |
| --- | --- | --- | --- |
| venv + 스크립트, 규칙 있음 | 예 | 예 | — |
| venv + 스크립트, **규칙 없음** | **아니오** | 예 | `tools/pptx` |
| **venv 뿐**, 규칙 있음 | 예 | **아니오** (담긴 파일이 0개) | `tools/xlsx` |
| **venv 뿐, 규칙 없음** | **아니오** | **아니오** | 다음에 만들 도구 |

**네 번째 칸이 다음 사고다.** 두 탐지 기제가 모두 「간접 증거」라서, 증거가 없는 조합이 남는다.
받는 쪽에 남는 것은 일반론 한 줄뿐이고, 그래서 **매번 사람이 보내는 쪽 PC 를 조사해야 한다.**

**고치는 방향은 「탐지」가 아니라 「기록」이다.** 보내는 쪽은 venv 를 **직접 보고 있으므로**
추론할 필요가 없다. 그 사실을 번들에 적으면 받는 쪽은 조사 없이 재생성한다.

실측으로 확인한 것 (2026-09-09, WSL):

- `~/.claude` 아래 venv 는 `db/venv` · `tools/pptx/venv` · `tools/xlsx/venv` 세 개다
- `venv/lib/python3.12/site-packages/*.dist-info` **폴더명만으로** 이름과 버전이 전부 나온다
  (`openpyxl-3.1.5.dist-info`) — 서브프로세스 없이 파일시스템만 보면 된다
- `rglob("venv")` 는 **0.02초**다. 기존 `collect_relative_paths()` 의 전체 순회(0.04초 / 2,546개)에
  비하면 추가 비용이 없다

## 7) 리스크(Risks)

| 리스크 | 완화 |
| --- | --- |
| **패키지 목록이 PUBLIC 저장소에 커밋된다** | 패키지 이름·버전은 자격증명이 아니다. 같은 값이 이미 전역 `CLAUDE.md` 의 xlsx·pptx 절에 적혀 번들로 오가고 있다. `db/venv` 도 `pymysql` 하나이며 접속 정보는 `.env`(자격증명 판정으로 이미 제외) 쪽에 있다 |
| dist-info 폴더명 파싱이 특이 케이스에서 깨진다 | 이름에 `-` 가 들어가도 `rsplit("-", 1)` 로 버전만 떼면 안전하다. 깨진 venv 는 경로만 남기고 빈 목록으로 둔다 — 예외를 던져 export 를 죽이지 않는다 |
| 매니페스트 스키마 변경이 받는 쪽을 깨뜨린다 | **실측(2026-09-09)**: `plan_apply.py` 는 매니페스트에서 `source` 하나만 읽고(`plan_apply.py:178-179`) 스키마를 검사하지 않는다. 최상위 키가 늘어도 무시된다 |
| 매니페스트 스키마 변경이 기존 결정 파일을 무효화한다 | 결정 누적은 **항목별 해시**로 판별한다. 최상위 키가 늘어도 항목 해시는 그대로다 |
| 순회 비용 증가 | 실측 0.02초. 기존 전체 순회(0.04초)보다 싸다 |
| 「경고하지 않기로 했다」는 기존 결정과 충돌해 보인다 | 충돌이 아니다. 경고(보내는 쪽에 뜨는 알림)는 여전히 안 만들고, **기록**(받는 쪽이 읽는 사실)을 만든다. 문서에 그 구분을 적는다 |
