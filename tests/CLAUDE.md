## 1. 이 프로젝트에서 반드시 있어야 하는 테스트

측정 도구는 **틀려도 결과가 그럴듯해 보인다**는 것이 가장 큰 위험입니다.
아래 세 종류는 기능 테스트보다 우선합니다.

### look-ahead 감시 테스트 (필수)

미래 데이터를 참조하면 성과가 실제보다 좋게 나오고, 눈으로는 발견되지 않습니다.

- **뒤를 잘라낸 입력과 전체 입력의 판정 결과가 같아야 한다**를 확인합니다
  (D일까지의 신호 판정은 D+1 이후 데이터가 있든 없든 동일해야 함)
- **새 이벤트 정의를 추가할 때마다 이 테스트를 함께 추가합니다.** 예외 없습니다
- 실제 작성 예시: `reference/test_examples/event_study_test_example.py`

### 산식 고정 테스트 (필수)

정의가 곧 결론을 만듭니다. **손으로 계산한 예시로 값을 박아둡니다.**

- forward return (종가 기준·익일 시가 기준 각각)
- 초과수익, 베이스라인 3종
- 확장창 순위 판정 (판정 시점까지의 데이터만 쓰는가)
- 구간 끝이 데이터를 넘어갈 때의 처리와 **제외 건수 반환**

### 표본 보존 테스트 (필수)

표본이 조용히 사라지면 생존편향이 생깁니다.

- 입력 신호 수 = 집계된 표본 수 + 제외된 표본 수 가 항상 성립하는지
- 제외 사유별 건수가 반환되는지

## 2. Given-When-Then 패턴

모든 테스트는 명확한 3단계 구조를 따릅니다.

```python
def test_example(self):
    """
    목적: 무엇을 검증하는가(불변조건/계약)

    Given: 어떤 입력/상태를 준비했는가
    When: 어떤 함수를 실행했는가
    Then: 어떤 결과/부작용을 검증했는가
    """
    # Given
    df = ...

    # When
    result = function_under_test(df)

    # Then
    assert ...
```

- "Then"은 되도록 **한 가지 계약**을 명확히 고정합니다
- 복잡한 로직은 한 테스트에 여러 assert를 넣기보다 테스트를 쪼개서 계약 단위로 고정합니다

## 3. 경계 조건 테스트

정상 케이스뿐 아니라 엣지 케이스도 포함합니다. **최소 1개 이상 필수.**

- 빈 데이터 / 최소 길이 데이터
- 등락률이 정확히 0%인 날
- 연속 구간이 데이터 시작·끝에 걸친 경우
- 표본이 0건인 칸 (통계 계산이 예외 없이 "계산 불가"를 반환하는가)
- 창 크기 부족 (이동평균, 순위 축적)
- 극단값 (0, 음수, 매우 큰 값), NaN/결측치

> "엣지 케이스를 어떻게 처리해야 하는가"는 도메인 정책입니다.
> 정책이 정해져 있다면 테스트는 그 정책을 고정해야 합니다.

## 4. 결정적 테스트 (Deterministic)

환경/시간/순서에 상관없이 항상 같은 결과를 보장해야 합니다.

- **시간 고정**: `@freeze_time` (freezegun)
- **파일 격리**: `tmp_path` 기반 픽스처
- **랜덤성**: 무작위 베이스라인은 **시드를 인자로 받아 고정**합니다. 시드 없는 난수 사용 금지
- **순서 안정화**: 결과가 정렬에 민감하면 정렬 규칙을 테스트에서 명시

### 부동소수점 / DataFrame 비교 규칙 (필수)

```python
# 금지 패턴
assert abs(a - b) < tolerance

# 필수 패턴
assert actual == pytest.approx(expected, abs=tolerance)
```

- **모든 부동소수점 연산 결과는 `pytest.approx()` 사용이 필수**입니다
- "정확히 일치"가 정책인 값(라벨, 컬럼명, 날짜, 표본 수)은 `==`로 고정합니다
- DataFrame 비교: `pd.testing.assert_frame_equal(..., rtol=..., atol=...)`.
  컬럼 순서/인덱스 정책도 함께 고정합니다 (필요 시 `check_like=True`)
- 배열 비교: `np.allclose(actual, expected, rtol=...)` 허용
- 단순 부등식 상한/하한 검증(`assert value < threshold`)은 예외입니다

허용오차 기준:

| 검증 대상 | 허용오차 |
| --- | --- |
| 수학적 정확 계산 (수익률, 승률, 순위) | `1e-12` |
| 통계량 (평균, 표준편차, t값) | `1e-9` |
| 가격·금액 비교 | `0.01` |
| 백분율 지표 | `0.1` |

## 5. 파일 격리

테스트는 실제 파일/실제 storage에 영향을 주지 않아야 합니다.

- 테스트에서 `storage/` 실경로(프로덕션 경로) 접근 **금지**
- 파일 기반 기능은 `tmp_path` 또는 경로 상수 패치 픽스처로 격리합니다
- **모듈이 import 시점에 경로 상수를 캡처할 수 있으므로**(예: `meta_manager`가 들고 있는 경로),
  필요한 경우 관련 모듈도 함께 `monkeypatch` 합니다. 이걸 놓치면 테스트가 실경로를 건드립니다
- 픽스처 작성 예시: `reference/test_examples/conftest_qbt_example.py` (`mock_storage_paths`)

## 6. 외부 의존성 금지

- 테스트에서 **네트워크/외부 API 호출 금지** (yfinance·pykrx 포함)
- 환경 의존(로컬 파일, 사용자 홈, OS별 경로) 금지
- 외부 호출은 `monkeypatch`로 스텁 대체하고, 테스트 데이터는 `tmp_path` + 합성 DataFrame으로 구성합니다
- **합성 데이터를 씁니다.** 실제 시세 파일에 의존하면 데이터를 갱신할 때마다 테스트가 깨집니다

> 실제 API 실측이 목적인 코드(pykrx 동작 확인 등)는 pytest 대상이 아니라 **스크립트로 분리**합니다.

## 7. 예외 테스트

- 예외 타입을 먼저 고정하고, 메시지는 정책인 경우에만 엄격하게 고정합니다
- 일반적으로는 핵심 키워드만 `match=`로 부분 매칭합니다

```python
with pytest.raises(ValueError, match="순위"):
    ...
```

- 입력 검증 실패는 `ValueError`, 내부 불변조건 위반은 `RuntimeError`로 구분해 고정합니다

## 9. 자주 발생하는 문제

| 문제 | 잘못된 예 | 올바른 예 |
| --- | --- | --- |
| 컬럼명 대소문자 | `df["Close"]` | 프로덕션 코드의 실제 컬럼명 확인 후 사용 |
| 파라미터 단위 | `buffer_pct=3.0` (퍼센트) | `buffer_pct=0.03` (비율) |
| 부동소수점 가독성 | `0.04650000000000001` | `0.0465` |
| 함수 시그니처 | 임의 dict 전달 | 프로덕션이 dataclass를 쓰면 테스트도 동일 구조 사용 |
| 타임스탬프 | 현재 시각 사용 | `freezegun`으로 고정 |
