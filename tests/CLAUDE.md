# tests 폴더 가이드

테스트 코드에도 본체와 동일한 품질 기준을 적용합니다 (타입 힌트, 한글 docstring, 네이밍).

## 파일 구성

- 파일명: `test_<모듈명>.py` — `src/verify_lab/`의 모듈과 1:1로 맞춥니다
- 공용 픽스처는 `conftest.py`에 둡니다
- 실행 설정은 루트 `pytest.ini`

## 이 프로젝트에서 반드시 있어야 하는 테스트

측정 도구는 **틀려도 결과가 그럴듯해 보인다**는 것이 가장 큰 위험입니다.
아래 세 종류는 기능 테스트보다 우선합니다.

### 1. look-ahead 감시 테스트 (필수)

미래 데이터를 참조하면 성과가 실제보다 좋게 나오고, 눈으로는 발견되지 않습니다.

- **뒤를 잘라낸 입력과 전체 입력의 판정 결과가 같아야 한다**를 확인합니다
  (D일까지의 신호 판정은 D+1 이후 데이터가 있든 없든 동일해야 함)
- 새 이벤트 정의를 추가할 때마다 이 테스트를 함께 추가합니다

### 2. 산식 고정 테스트 (필수)

정의가 곧 결론을 만듭니다. 손으로 계산한 예시로 값을 박아둡니다.

- forward return (종가 기준·익일 시가 기준 각각)
- 초과수익, 베이스라인
- 구간 끝이 데이터를 넘어갈 때의 처리

### 3. 경계 조건 테스트

- 등락률이 정확히 0%인 날
- 연속 구간이 데이터 시작·끝에 걸친 경우
- 표본이 0건인 칸

## 테스트 작성 원칙

- **합성 데이터를 씁니다.** 실제 시세 파일에 의존하면 데이터를 갱신할 때마다 테스트가 깨집니다
- 하나의 테스트는 하나만 검증합니다
- 실패 메시지에 기대값과 실제값이 함께 보이도록 씁니다
- 날짜가 관여하는 테스트는 `freezegun`으로 시점을 고정합니다

## 스킵 금지

`skipped > 0`이면 계획서를 Done으로 처리할 수 없습니다.
"구현이 없어서 테스트를 못 쓴다"면 스킵이 아니라 **Phase 분해**로 해결합니다.
상세는 `/plan` 스킬을 따릅니다.
